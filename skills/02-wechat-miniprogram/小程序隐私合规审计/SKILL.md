# 小程序隐私与授权线索检查

## 范围与依据

自带脚本中的接口映射是历史启发式清单，可能过时或不完整。执行任务时根据当前基础库、官方接口文档和开发者后台提示复核，不能直接把清单当成必须勾选项，也不能由源码推断后台已配置完成。

## 工作流程

1. 确认 project.config.json 指向的小程序根目录，读取 app.json 与真实功能入口。依赖封装、TS、动态调用和原生组件可能不被脚本完整覆盖。
2. 在独立报告目录执行本技能脚本，参数使用被测项目绝对路径：
   `python <本技能目录>/scripts/privacy_audit.py <项目根目录>`。
   它在当前工作目录写 privacy_audit.json；先选好报告位置，避免覆盖既有结果。
3. 逐条回到代码检查命中项是否真的执行、收集什么数据及对应用户场景。额外检查 WXML 组件和属性，包括 show-menu-by-longpress；不要只扫 wx.* 字符串。
4. 对需要声明或权限的接口查当前官方依据，核对 requiredPrivateInfos、授权流程和后台实际状态。记录已核对、待核对与无法访问的部分。
5. 在开发者工具及真机验证授权同意、拒绝、取消和再次进入场景，检查异步回调与失败提示。

## 失败处理与完成标准

空 fail 回调是排查线索，用户主动取消不一定需要错误弹窗；网络、权限或处理失败则应提供可理解的反馈。用语法结构定位回调所属调用，不以缩进或附近关键词作最终判断。

交付表包含接口/组件、文件行号、实际用途、当前依据、声明与授权状态、建议及真机验证结果。扫描零命中不表示没有隐私接口；扫描完成不表示通过提审。后台变更只能通过当前已授权且可用的官方入口进行。
