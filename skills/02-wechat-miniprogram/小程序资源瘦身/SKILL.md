# 微信小程序静态资源瘦身 / 代码质量体积修复

## 什么时候用
- 开发者工具 → **代码质量 → 代码包 → 「图片和音频资源大小应不超过 200 K」** 显示**未通过**。
- 小程序包体积偏大、图标/图片冗余、怀疑有没被引用的组件。

## 关键事实（先记住，能省一半时间）
1. **判定口径是「图片 + 音频资源的总和」，不是单个文件。**
   官方原文：「小程序代码包里可以存放一些必要的静态资源（如 tabbar 的 icon 等）；但其他非必要的静态资源体积过大会影响代码包加载速度。」
   所以哪怕最大单文件只有 4 KB，总数超 200 KB 一样不通过。
2. **`.svg` 也算图片资源**，会计入总和。设计稿导出的图标集常见坑：同一个图标按 N 种配色
   （white / faint / muted / brand / …）各存一份，**几何路径完全相同，只有 stroke 颜色不同** —— 
   这是纯冗余，且绝大多数组合从没被任何 `src` 引用过。
3. tabBar 图标必须是本地 PNG（微信 tabBar 不支持 SVG），这部分通常是必要开销，别动。

## 工作流

### 1. 先量化
```bash
# 工程根目录 = 含 project.config.json 的那一层
python scripts/audit_assets.py <工程根目录>
```
它会打印：图片音频总量、按目录/扩展名分布、可删文件数。先确认总量确实超 200 KB。

### 2. 审计「真正被引用到」的图标组合
同一脚本会输出 `asset_audit.json`，含 `keep` / `unused` 两个列表。它把下面这些都展开：
- 静态路径 `src="/assets/icons/x--tone.svg"`
- 三目表达式 `{{cond ? 'a' : 'b'}}`、`{{'前缀' + (cond ? 'x' : 'y') + '.svg'}}`
- 数组拼接 `{{tabIcons[i]}}--brand.svg`（自动去 `.js` 里找同名数组）
- 通用组件 `empty-state` / `icon-button` 的 `icon × iconColor` 调用点交叉乘积
- 半动态 `mood-{{mood}}--white` → 按前缀 `mood-` 保守全留

**扫描口径很重要**（踩过的坑）：
- WXML 只扫**双引号属性值**；
- **JS 必须额外扫单引号字面量** —— `iconSrc: '/assets/icons/pin--muted.svg'` 这种只扫双引号会漏掉，进而**误删正在用的图标**；
- 但单引号正则**不能用在 WXML 上**（会跨段误匹配出垃圾），要按扩展名区分。

脚本内置两道闸：① 每个含模板变量的表达式必须至少匹配到一个保留文件；
② 独立交叉校验所有静态路径都在保留集内。**两道都为「通过」才动手删。**

### 3. 顺带找死组件（对应面板「无使用或无依赖文件」）
```bash
for d in components/*/*/; do n=$(basename "$d"); \
  cnt=$(grep -rl "$(echo $d | sed 's|^\./||')index" --include=*.json . | wc -l); \
  [ "$cnt" = 0 ] && echo "未声明: $n"; done
grep -rn "<组件名" --include=*.wxml .
```
**两个条件同时成立**（不在任何 `.json` 的 `usingComponents`、不出现在任何 WXML）才算死组件，可移走。

### 4. 迁移（不要直接删）
移出小程序包、放到同级 `_trash/<name>-<date>/`，并写一份 `_manifest.txt` 便于恢复。
必须确保备份目录在**工程根目录之外**，否则照样被打包。

### 5. 验证（缺一不可）
- 重跑审计：`可删` 应为 0，且所有引用仍能命中保留文件。
- 残留引用检查：已移走的组件在全部 `.json` / `.wxml` 中 0 引用。
- 语法体检（每个工程自带的 `_syncheck.js` 之类）。
- 回开发者工具点「重新扫描」确认该项变「已通过」。

## 环境坑位
- **`_syncheck.js` 报 `require is not defined in ES module scope`**：说明上级 `package.json` 是
  `"type": "module"`。解法：复制成 `.cjs` 再跑，跑完删掉；不要去改工程配置。
- **Windows + Git Bash 的 `rm` 可能是坏的 shim**（`safe-delete-common.sh` 缺失，exit 127）。
  删除/迁移一律用 Python `os.remove()` / `shutil.move()`。
- 只做「删冗余」，**不要顺手压缩/改写 SVG 内容**——保留文件的渲染必须和修复前完全一致。

## 收尾
在工程内告知用户：
1. 修复前后的总量对比；
2. 备份的**完整路径**；
3. 「后续新增图标用法时，若用到已移出的『图标名+配色』组合，需从备份取回」——否则真机图标会空白。
