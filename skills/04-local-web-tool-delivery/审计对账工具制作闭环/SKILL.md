# 审计／金额类本地工具的制作闭环

把「金额不能错、用户不懂技术、数据不出本机」的本地工具做到可以连续迭代十几轮，并且每一轮都能被外部证据复核。方法提炼自 `<project-root>\audit-reconciliation-desk`（双边对账工具）：18 轮对比迭代，交付 v2026.11.06-r2；单页 + 一个约 1.08 万行的 `app.js` + 4,400 行 CSS；19 个测试套件 / 849 条断言 / 27 项黄金快照 / 25 个夹具。**文中的数字是 2026-10-29 该项目的快照，换项目重新测。**

## 先判断该不该用

- **用**：结果要进审计底稿、准备函证、对外交付，金额与结论必须可复现；用户是财务/审计人员而不是工程师；要长期维护并交接。
- **用**：已有同类工具要加功能、要对标收敛、要把口径写死。
- **不用**：一次性脚本、纯内部工具、允许连网取数的服务型产品（那套方法的价值在「可复核」，不联网就不成立时收益有限）。

## 五条不可让步的前提

1. **金额整数分**：所有计算以「分」整数进行，展示才除 100；禁止浮点累加。
2. **提示不改金额**：凡是「辅助、提示、留痕、显示范围」的功能，一律不许改 `cents`、不许进净额、不许删记录（详见 [口径红线](references/caliber-red-lines.md)）。
3. **数据不出本机**：纯静态、无外链、无统计、无在线字体；第三方库本地化并登记许可证；启动器只绑 `127.0.0.1`。
4. **面向非技术用户**：不出现「解析／映射／字段／序列化／算法」这类词；每个错误先说「怎么办」。
5. **真实数据只在用户授权范围内读**：真实底稿、企业名、金额绝不进仓库与测试夹具；夹具一律合成；语料体检跳过工资、汇报、个人信息类文件。

## 一、先立口径，再写功能

每个新功能先回答三问，并写进交接稿的编号条目：

1. 它会不会改变任何金额？会 → 主链路，重跑全部金额回归，导出说明写清口径变化。
2. 用户看不见它时谁负责说？缩小范围、跳过数据、认错列、算出 0 笔，都必须主动说明。
3. 能撤销/恢复吗？只改显示与标记的要有后悔药；改金额的默认不做。

维护一张**红线矩阵**：`功能 | 允许碰什么 | 绝不许碰 | 留痕位置`。每一行都必须有「绝不许碰」；没有这一列，边界就靠记忆，而记忆在第 10 轮之后会失效。

提示型功能的实现契约（缺一条就会被误接进主链路）：

- 新建独立字段，不复用金额字段；
- 在主链路之后计算，只吃剩下的数据（「差一点就能配上」只吃配对余料，保证一条记录只被一个结论消费）；
- 明确进不进结果指纹（呈现类不进，结论类进），写进交接稿；
- 测试里放只读断言：操作前后逐笔 `cents`、逐企业 `recv/pay/netCents`、结果指纹逐项相同；
- 界面文案自己声明边界：「只是提示，不改变净额」。

## 二、一轮的五段节奏

1. **选**：从差距表挑一条，写价值×成本；一轮只做一条主差距。
2. **借**：读对标的公开行为与文档，借语义不借源码；GPL/AGPL 只读行为，不读源码、不贴代码。先查许可证再决定能不能读。
3. **落**：核心计算（纯函数、可被测试直接调）→ 数据/导出结构 → 界面（含「怎么办」文案）→ 测试（夹具 + 断言 + 只读性）。
4. **证**：全量回归；动交互/打印跑真窗口；动认列跑真实语料；重打包。
5. **报**四段：改动点 / 借鉴来源（谁、借语义还是代码）/ 验证结果（命令 → 实测数字）/ 残留问题。缺一段算没交付。

差距表状态只有 `✅ 已收敛`、`🚫 已知取舍`、`⏳ 推迟` 三种；判「不做」要写理由与替代方案。**自查发现的「会误导用户」的缺陷，优先级高于差距表里的新功能**，修完补一条能复现它的断言。

## 三、六层证据栈

| 层 | 证明什么 | 什么时候必跑 |
|---|---|---|
| 语法检查 | 文件能被解析 | 每次改 JS |
| golden 快照 | 每个夹具认列/范围/记录/净额/配对/导出逐字段没变 | 改口径、升版本前后 |
| vm 沙箱断言 | 单条口径的边界与只读性 | 每次改对应模块 |
| 一命令全量回归 | 全部套件同绿且断言条数没缩水 | 每轮收尾 |
| 真窗口 QA | 指针拖框、打印媒体、剪贴板、布局 | 改交互/打印/布局 |
| 真实语料 + 包体往返 | 真实识别质量、交付 zip 与源目录一致 | 换版本、换认列规则 |

三个必须固化的机制：

- **断言条数闸门**：runner 里每个套件写死期望条数，实跑少了判 `SHRUNK`，防止「删了断言还全绿」。
- **期望值先跑再抄**：不手算、不沿用上一轮；哈希值不写死（导出带时间戳，每次不同），只断言格式与自洽。
- **逻辑验证与真实交互验证分开报告**：劫持下载函数只能证明字节和文件名，不能证明浏览器真的弹了保存框。

详细命令、沙箱/真窗口/语料的坑见 [证据栈](references/evidence-stack.md)。

## 四、面向非技术用户的六条诚实原则

这些不是文案偏好，全部来自真实缺陷：

1. **不替用户做决定**：导入后一张表都不勾（哪怕文件只有一张表），只标出「这张表认出了企业名和金额」供参考；参与对账永远由人勾选。
2. **不确定就写在行上**：按内容猜的列标「可能要人工核对」，并写出认的是哪一列、什么表头——一本底稿几十张表，只有点开的那张能看到列状态是不够的。
3. **勾了却没算到必须说出来**：表勾上了但 0 笔，列表徽章 + 数据检查 + 预警 toast + 导出说明四处点名；控制总数「平」不代表没漏（全是正常跳过时恒等式照样平）。
4. **空值不硬塞**：账龄没写的单列一档、币种没写的单列一组；`?? 0` 会把「没写」变成「1 年以内」。
5. **打印必须自证**：筛选条在纸上被隐藏，纸面会静默少企业；打印戳强制写「本页只列筛出来的 N 家（一共 M 家，原因…）；要全部打出来就……」。
6. **错误说怎么办**：先给动作（「在 Excel 里只留下要核对的那几张表另存再导入」），再说现象；预警 toast 不要被「完成」toast 覆盖（顺序：完成 → 预警）。

## 五、交接稿纪律（AGENTS.md）

- 结构：定位与硬约束 → 文件清单 → 运行与打包 → 架构与数据流（`state` 字段表 + 主链路）→ 按编号的口径规则 → UI 约定 → 导出结构 → 测试与验收 → 已知坑 → 未做/已判定不做 → 许可证台账。
- **引用代码写函数名 + 行号**，并注明「行号会漂，按名检索」；编辑时锚定代码文本，不锚定行号。
- **改完立刻 grep 复核**：并行改同一文件时 `Edit` 可能返回成功但没落盘；落一条验一条。
- **失败实验也要留档**：写清「为什么这个方案被推翻」，比只写正确做法更能防止复发。
- 文档里的数字标版本与日期，下一轮先跑再改。
- 交接稿、测试、差距清单**不进交付包**。

模板与发布清单见 [交接与发布](references/handoff-and-release.md)。

## 六、发布与停

发布顺序：升版本（`version.txt` + `app.js` 常量 + `更新说明.txt` 三处同步，服务会缓存版本需重启）→ 语法 → 全量回归 → 真窗口 → 真实语料 → 白名单打包 → `zipfile` 回读 CRC/条目/逐文件 MD5 → 用户亲测。

**发版闸门的最后一条在用户手里**：用户本人拿一份真实底稿从头走到尾（导入 → 勾表 → 认列 → 对账 → 看复核提示 → 导出/打印），期间不需要人猜。在此之前只报「改完待发」，不报「可以发布」。

**停的条件**：差距表只剩「已知取舍」与「推迟」。停后冻结，新需求另开决策记录并写明「为什么解冻」，不在已冻结的轮次里插队。

## 七、最容易翻车的十二条

1. 在红的基线上重构，事后分不清是谁弄坏的。
2. 用被测代码算出的数当期望值，把 bug 固化成基线。
3. 只断言「没抛异常」，不断言结构（列数、行号偏移、金额格式）。
4. 改了默认值（自动勾选、单位、档位），用户可见行为悄悄变而文档没改。
5. 导出加了列/加了封面行，忘记同步 `!autofilter` 范围与下游按索引取行的断言。
6. 提示型功能直接写进 `pairings` 或 `rows`，破坏「一条记录只被一个结论消费」。
7. 筛选/分批只改渲染，却让导出、打印、计数各自算一遍，出现两套「可见集合」。
8. 文档里的行号与数字停在上一轮，审计时被当场抓出。
9. 拿「自动勾选数」当识别质量指标；把格式占比塞进认列闸门（本项目实测 19→64，分析列全被勾进来）。
10. 中文路径 + GBK 控制台把输出报错，误判为功能坏了；PowerShell 5.1 用 `Compress-Archive` 打包中文目录并不可靠。
11. `ELECTRON_RUN_AS_NODE` 没设/没 unset：该当 Node 用的按 GUI 启动，该起窗口的按纯 Node 跑。
12. 把「测试全绿」说成「可以发版」，跳过用户亲测。
