# 离线单文件工具的对标迭代

把一款纯前端、离线、双击即开的工具做到能替代商业软件，并且**每一轮都能被外部证据复核**。本方法在 `<project-root>\pdf-page-tools`（PDF 拆分/整理/合并工具）从零跑到 49 轮收敛；文中数字均为 2026-10-29 该项目实测值，换项目时重新测。

## 先判断该不该用

- **用**：功能多、生命周期长、用户是「不懂命令行、只想要一个文件」的人，且你要能回答「凭什么说它好了」。
- **用**：已有离线工具要加功能、要冻结、要交接。
- **不用**：需要后端常驻 → 用 `windows-local-web-tool-delivery`；只要一次性转换 → 直接写脚本；只做回归/打包 → 用 `offline-web-tool-fixture-regression`、`win-offline-web-tool-regression-package`。

## 五条不可让步的前提

1. **产物只有一个文件**：CSS/JS/字体/worker 全部内联，断网、`file://` 双击可用，任何 CDN 引用都是缺陷。
2. **第三方 AGPL 只当裁判**：MuPDF/PyMuPDF 这类只能当独立校验器与设计参照，一行源码都不进项目；随产物分发的库要逐个核对许可证（本项目是 pdf-lib、pdf.js、JSZip）。
3. **数字必须来自实测文件**：毫秒、字节、断言数只从 `tests/*-report.json` 与磁盘取，不许沿用上一轮、不许手写估计。
4. **做不到就报做不到**：拒绝、跳过、压不动都要如实登记；「没测」不许写成「通过」。
5. **夹具一律合成**：用户真实文件与个人信息不进测试目录，也不为了调试去读它们。

## 一、先把产品形态定死

单文件不是打包技巧，是架构约束。四条一起定：

| 形态 | 作用 | 约束 |
|---|---|---|
| `web/`（源码目录） | 唯一真源 | 每个 `.js` 一个文件，靠 `index.html` 的 `<script src>` 顺序加载 |
| 单文件 HTML | 交付给用户的那一个文件 | 由构建脚本内联，不许手改产物 |
| 桌面壳（Electron） | 补浏览器做不到的能力（本机 OCR、Word COM） | 直接加载 `web/`，不走单文件 |
| 命令行 | 批量与脚本化 | 在 Node 模式里 eval 同一批 `web/js`，共用一套引擎 |

**关键契约**：引擎文件（`core.js` / 引擎 / 编解码）的**顶层**不能碰 `document`/`window`，否则命令行跑不起来；需要全局时用 `typeof window !== 'undefined' ? window : globalThis`。函数体内可以有 DOM 调用，只要该入口不被命令行调用。

细节见 [单文件架构](references/single-file-architecture.md)。

## 二、立项：对标选型

选 5 个左右工具，每个承担一种角色，**先查许可证再决定能不能读代码**：

| 角色 | 本项目选的 | 拿来干什么 |
|---|---|---|
| 结构正确性标准 | qpdf（Apache-2.0） | 「坏到哪种程度、能不能修」的三态语义 |
| CLI 体验标杆 | pdfcpu（Apache-2.0） | 批量、可机读报告、命令覆盖面 |
| 独立裁判 | MuPDF/PyMuPDF（AGPL） | 黑盒验证产物；**不读进源码** |
| 已被内嵌的参照 | pdf.js | 浏览器端渲染与取字的上限 |
| 功能清单 | Stirling-PDF | 只对标功能表，不看代码 |

产出一张**差距表**：`# | 差距 | 严重度 | 影响范围 | 价值×成本 | 状态`。状态只有三种词：`✅ 已收敛`、`🚫 已知取舍`、`⏳ 推迟`。本项目最终 32 行 = 23 ✅ / 7 🚫 / 2 ⏳。收敛后若确有新需求，另开决策记录并写明「为什么解冻」，不要在已冻结的轮次里偷偷插一轮。

模板与写法见 [对标循环](references/benchmark-loop.md)。

## 三、单轮怎么跑

一轮只做一条差距，按固定四段交付，**顺序不要颠倒**：

1. **选**：从差距表挑一条，写清价值×成本；高价值低成本先做。
2. **借**：读对标工具的**公开行为与文档**，借语义不借源码。借不到的（AGPL）只描述「它怎么做」，代码自己写。
3. **落**：四层依次落地 —— 引擎（纯函数、可被 CLI 调用）→ 命令行（同一引擎、固定字段名）→ 界面（面板 + 如实报数）→ 测试（夹具 + 探针 + 裁判反查）。
4. **收**：全量回归 → 重建单文件 → 三份文档同步 → 汇报四段。

**汇报四段（用户明确要求，缺一段算没交付）**：

```text
改动点：改了哪些文件、哪个行为。
借鉴来源：对标了谁、借的是语义还是代码（没借就写「无」）。
验证结果：命令 → 实测数字（34/34、298 条断言、字节数）。
残留问题：没做到的、明确拒绝的、下次要接的。
```

## 四、证据体系：让「通过」可被推翻

四层证据缺一不可，全部由脚本产生，不靠人看：

- **引擎用例**：直接调 `PT.pdf.*`，断言结构（页数、`/Rotate`、`/V`）而不只是「没报错」。
- **命令行断言**：同一个引擎走 CLI，断言字段名与退出码（本项目 298 条）。
- **界面宿主**：隐藏窗口加载真实页面，等 `window.__DONE__`，把结果写 JSON。
- **独立裁判**：用 PyMuPDF 打开产物反查，**不能拿被测代码证明被测代码**。

两个协议值得照抄：

- **`TAG {json}` 单行协议**：每个界面模式只打印一行 `SPLIT {"ok":true,...}`，脚本取**最后一条**同标签 JSON 判定，人看的日志随便打。
- **CASES 单一入口**：回归脚本里一张表就是全部用例清单（本项目 34 项 = `build` + 33 项）。新增测试**必须**进表，否则永远不会跑。

细节、环境坑与报告字段见 [证据流水线](references/evidence-pipeline.md)；汇总报告数字用 `scripts/summarize-reports.py`。

## 五、诚实闸门：拒绝也是一种结果

做到一半发现语义做不干净时，**加闸门，不要加谎言**。本项目三个可复用的范式：

- **能力边界闸门**：整页是一张扫描图的页，抹字删不掉像素 → 单独点名 `imageOnly`，产物逐像素不变，界面如实报「这页抹不到」。
- **语义冲突闸门**：填表只写 `/V`+`/AS` 并置 `NeedAppearances`；压平**拒绝**这类文件，而不是偷偷重画外观。取舍写进文档，不当作 bug 修。
- **前置条件闸门**：输入不合法（正则语法错、量词套量词、只读字段）当场拦下，**不出半套文件**。

配套的登记纪律：跳过的项要出现在差距表与「未完成事项」里；报告里区分「逻辑验证」与「真实交互验证」（例如劫持下载函数只能证明字节和文件名，不能证明浏览器真的弹了保存框）。

## 六、构建与发布

```bash
python build_single.py          # 内联 CSS + 按 index.html 顺序内联全部 <script src>
python tests/regress.py --build # 先重建再跑全量，34 项
```

构建脚本必须自带四道自检：翻转 `meta[name=pt-inline]` 0→1、转义 `</script>`、内联后**再扫一遍残留外链**（有就退出）、体积超阈值告警。新增 JS 文件要同时改 `index.html`（否则单文件里没有它）和 CLI 的 eval 列表。

发布清单：`file://` 双击能开、断网可用、`pt-inline=1`、桌面版双击能开、`--help` 正常、`--dry-run` 不建目录、源文件哈希未变。

## 七、什么时候停

停的条件是**差距表里只剩取舍与推迟项**，不是「做累了」或「功能看起来够了」。停之后：

- 差距表 §3 顶部写「本轮后冻结，之后只允许更正事实」；
- 不再接受「顺手加个功能」的诱惑，新需求走新决策记录；
- 转入收尾（下一节），不要开始第 N+1 轮。

## 八、收尾与重构

收尾不是重写。按顺序做，每步都能回退：

1. **安全网**：没有版本控制就先 `git init` 或整目录备份；记录关键文件 SHA-256 与全量回归数字作为基线。
2. **先跑绿的基线**：在本来就红的基线上重构等于同时改两件事。
3. **低风险收口**：消除重复实现与口径分歧（本项目是 `PT.sanitize` 与 CLI 自带 `sanitize` 规则不同），删之前先证明差异只落在未覆盖的输入上。
4. **大文件拆分**：只抽纯函数到新文件，方法名与签名一个不改；每抽一块就跑对应探针 + 全量。
5. **行为契约表**：把「不许变的事」写成编号清单（命名空间与加载顺序、退出码、报告字段名、源文件不变、语义取舍……），重构后逐条对照。
6. **交接文档**：§0 给新对话一段可粘贴指令，附带基线数字、命令、验收矩阵、不做的清单。

完整步骤、行为契约的分类与交接模板见 [收尾与交接](references/finalization.md)。

## 九、最容易翻车的十件事

1. 在红的基线上重构，事后分不清是谁弄坏的。
2. 新增 JS 文件忘了加进 `index.html`，单文件里静默缺失。
3. 引擎顶层碰了 DOM，命令行直接起不来。
4. 用被测代码算出来的数当期望值，把 bug 固化成基线。
5. 断言只看「没抛异常」，没断言结构（页数、`/Rotate`、`/V`）。
6. 改了默认值（缩放开、页码开），用户可见行为悄悄变。
7. 批量处理时以为「一个失败就零产物」，实际是逐个文件写盘。
8. 文档里的数字停在上一轮，审计时被当场抓出。
9. 中文路径 + GBK 控制台让输出报错，误判为功能坏了。
10. 把 AGPL 代码「参考着抄」进项目。

领域级坑（PDF 的 `/Rotate` 坐标、pdf.js 的 detach、PPTX 剪枝顺序、Word COM 收尾）见 [领域坑](references/domain-pitfalls.md)。

| 场景 | 交给谁 |

| 换对话继续同一项目 | `project-handoff`（项目计划交接） |

本技能管**整个生命周期的方法与顺序**；上游技能管其中某一段的执行细节，不重复它们的脚本。
