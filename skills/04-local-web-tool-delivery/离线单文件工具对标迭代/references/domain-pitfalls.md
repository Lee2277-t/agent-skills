# 领域坑

来源：`<project-root>\pdf-page-tools` 在 49 轮里实际踩到、并写进开发手册（§7 共 93 条）的部分条目。换项目时按领域取用；不是通用真理，逐条在自己的环境里复核。

## PDF 引擎

**读入**

- `pdf.js` 的 `open()` 会 **detach ArrayBuffer**。同一份字节要用两次时一律 `bytes.slice(0)`，否则第二次读拿到空数据。
- `renderToCanvas` 必须传 `intent: 'print'`。默认 `display` 在窗口被遮挡时 promise 可能永不 resolve，测试直接挂死。
- 低层遍历三个静默陷阱：页面节点的 `.dict` 不是 `PDFDict`；Type0 字体的字库在 `DescendantFonts[0]`；`context.lookup()` 出来的对象常没有 `.ref`，去重要用对象实例本身。

**写出**

- pdf-lib 低层字典要带上下文：`PDFDict.withContext(ctx)` + `context.register()`；页面引用用 `page.ref`。
- 写 `/Outlines` 必须包 try/catch：个别畸形 PDF 会让整个拆分失败，书签坏了不该毁掉正文。
- 拆分产物若共用大资源（字体、图片），体积会成倍膨胀。要么子集化，要么在界面上提前警告，不要等用户拿到 30 MB 的 3 页文件才发现。

**`/Rotate` 是画东西的最大坑**

- 画坐标的原点是**未旋转 MediaBox 的左下角**，但 `getWidth()/getHeight()` 已经换过轴。
- 图片要预旋负角；四种 `Rotate` 值各有一套坐标换算分支。
- 水印、页码、拼图、印章都必须分别验证 0/90/180/270 四种情况，只在 0 度通过等于没测。
- 只要改方向，就**只改 `/Rotate`**：正文、批注、书签一个字节都不动，然后用裁判逐页比对。

**表单**

- 填值只写 `/V` 与 `/AS`，并置 `NeedAppearances`，**不重画外观**。
- 压平**拒绝** `NeedAppearances` 为真的文件（外观是查看器画的，烘不出真实样子）。这是取舍，不是 bug；写进用户文档。
- 压平的判据不是「没报错」，而是：原件内容流逐字节仍在 + 纸面与开批注渲染逐像素相同 + 勾选框只烘一档。

**抹字（脱敏）**

- 整页是一张扫描图时，删不掉像素。走 `imageOnly` 闸门：单独点名、产物逐像素不变、界面如实报「这页抹不到」。
- 只抹正文是不够的：批注正文、表单值、书签标题、`/AP` 出现流都要一起处理，否则残留是 5 而不是 0。
- OCR 会在中文字之间塞空格，关键词匹配前两边都要去空白；正则与关键词共用同一套去空白口径。
- 「按关键词拆」和「抹字」是两回事：前者命中页各成一份，别在改抹字时顺手改拆分语义。

**水印 / 拼图**

- 水印**只加不改**：产物逐页取文必须与原件一致，这是可自动断言的。
- `fore/back` 靠 `/Contents` 里 `Do` 流的次序，不是靠绘制顺序的参数。
- 拼图每页嵌成 Form XObject，只写摆位矩阵；小册子配页、统一缩放、批注/链接跟随、书签、每格页码、控件外观压平各有开关与默认值，**不要顺手改默认**。

## Office

- **PPTX 剪枝顺序不能换**：先删部件 → 再剪 `.rels` → 再清所有主命名空间的 `*IdLst` 悬空项 → 再重排 `sldIdLst` → 修 `[Content_Types].xml` 与 `docProps/app.xml`。少一步 PowerPoint 就提示修复。
- 节的 `p14:sldIdLst` 引用的是 `p:sldId@id`，不是关系列表；用「按 r:id 查关系」的通用清理会把整节清空。
- **Word 没有「页」对象**：只能靠 `w:lastRenderedPageBreak` 与手写分页符估算。不要把「按页拆」宣传成精确。
- Word COM 收尾：`Close(0)` → `Quit()`（**不能带参数**）→ `ReleaseComObject` → 两轮 GC。对「正在打开的文件」另存为会永久挂起，所以精确分页脚本从不保存，而是替换 `word/document.xml`。

## 命令行

- 退出码只用三个：`0` 成功 / `1` 拒绝或运行失败 / `2` 参数错。
- **单份原子、批量不原子**：单个文件失败不落它的半份产物（填表、压平、合并都是「要么全对、要么不写」）；但批量是**逐个文件写盘**的，前一个成功、后一个失败时前一个已经落盘。脚本判断成败要看退出码 + `files[].ok`，不要假设「有一个失败就零产物」。
- `--dry-run` 只算不写，连输出目录都不建——这条要单独断言，很容易漏。
- 所有命令跑完，**源文件 sha256 必须不变**。
- 报告字段名属于契约（`needAfter`、`verify.left`、`asked/matched/changed`、`planned[]`、`skipped` 等），改名会直接打断下游脚本与断言。
- 随拆分导出的附属文件（文字稿、图片、清单）必须带 `extra:true`，否则会被当成 PDF 去校验页数。

## 界面层

- 界面回归用**真实面板名**（`split` / `arrange` / `merge`），传错不报错、只是静默失败。
- 整理器里一页可以被复制多次：选中/撤销一律基于数组对象与索引，不要假设「页码唯一」。
- 长任务的每个逐页/逐份循环顶部都要有取消检查（`PT.checkCancel()`），重构时不要把它「优化」掉。
