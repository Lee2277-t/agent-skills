# 对标循环

## 1. 选对标：按角色选，不按名气选

一个工具不可能对所有方面都是天花板。给每个对标分配**一个角色**，角色齐了就开始，不要等「集齐所有工具」。

| 角色 | 判断标准 | 许可证雷区 |
|---|---|---|
| 结构/格式正确性标准 | 有没有公开的三态语义（坏在哪、多严重、能不能修） | BSD/Apache 可读代码；AGPL 只读文档与行为 |
| 批量与脚本化标杆 | CLI 是否可机读、是否支持干跑 | Apache/MIT 通常安全 |
| **独立裁判** | 能否在项目外独立打开并检查产物 | AGPL 只能用二进制/绑定，**源码不进项目** |
| 上游参照 | 项目已内嵌的库（如 pdf.js） | 跟随其许可证与 NOTICE |
| 功能清单 | 覆盖面最广的网页工具 | 只看功能表，不读代码 |

三条硬规则：

1. **先查许可证再决定读什么**。本项目对 MuPDF/PyMuPDF 只做黑盒调用与「它怎么做」的设计参照。
2. **裁判必须与被测系统无共享代码**。用自己写的解析器验证自己写的生成器，等于没验。
3. **对标工具不必安装**。本项目 5 个对标里 3 个只读公开文档与 CLI 行为说明，也足够列差距。

## 2. 差距表：一行一条，状态只有三种

```markdown
| # | 差距 | 严重度 | 影响范围 | 价值×成本 | 状态 |
|---|---|---|---|---|---|
| A1 | 损坏 PDF 打不开（对标能救的件我们直接报错） | 高 | 存量坏文件；后果是「这工具用不了」 | 高价值 / 中成本 | ✅ 本轮已收敛，见 §3 |
| A3 | 没有线性化（Fast Web View） | 低 | 少数需要边下边看的场景 | 低价值 / 高成本 | 🚫 已知取舍（离线双击工具不做服务器分发） |
| C1 | 插件注册化 | 低 | 扩展性 | 低价值 / 高成本 | ⏳ 推迟 |
```

写法要求：

- **「影响范围」写用户后果**，不写技术名词。「用户会以为工具坏了」比「缺少 backtrace 机制」有用。
- **「价值×成本」给结论不给分**：`高价值 / 中成本`。数值化会诱发假精度。
- **✅ 必须带轮次**（`✅ 轮 11：…`），否则无法核对。
- **🚫 必须写理由**（为什么不值得做），**⏳ 必须写阻塞条件**（等什么）。
- 状态词只用这三个。不要引入「部分完成」「待观察」，它们会让收敛永远不成立。

数量不必凑整。本项目 32 行是自然长出来的；收敛时 23 ✅ / 7 🚫 / 2 ⏳。

反例：把「跑出来是多少就记多少」当作已完成 —— 那只是给当前行为拍了张照，Bug 也被固化成「已实现」。

## 3. 单轮四段

```markdown
### 轮 NN：<一句话目标>（差距编号）

**改动点**
- 引擎：新增/修改 `PT.xxx.yyy`，语义边界是……
- 命令行：`xxx` 命令，字段名 `files[].aaa`，退出码规则……
- 界面：`<面板名>` 加 `<控件>`，结果行如实报 N。
- 测试：夹具 `make_xxx.py`，探针 `check_xxx.py`，断言 N 条。

**借鉴来源**
- 对标 <工具>/<文档节>：借了 <语义>；未复制代码。

**验证结果**
- `python tests/regress.py --build` → 34/34，`ok:true`，各项相加 438,339 ms。
- `python tests/test_cli.py` → `cases:298, failed:[]`。
- 裁判反查：PyMuPDF 打开产物，页数/`/Rotate`/`/V` 与预期一致。

**残留问题**
- 明确拒绝：<场景> 不做，理由是……
- 未验证：<仅逻辑验证，未在真实浏览器点过>。
```

四条纪律：

- 一轮一条差距。混两条会让「验证结果」无法归因。
- 引擎先于界面。界面只是调用方，先让引擎在 CLI/测试里跑通。
- 测试与实现同轮落地，不排「下一轮补测试」。
- **口径被证伪时，先改文档再改代码**。本项目轮 49 就是把「填完能压」这句错话更正掉，而不是去实现一个语义不成立的功能。

## 4. 收敛判据

同时满足才算收敛：

1. 差距表里没有状态为「未开始」的行；
2. 剩余行的状态只有 🚫 / ⏳，且每条都有理由或阻塞条件；
3. 全量回归与命令行断言全绿，报告时间戳晚于最后一次代码改动；
4. 文档中的数字与报告一致（`grep -n "末次实测"` 逐个核对）；
5. 你能用一句话说明「现在不做的是什么、为什么」。

收敛后冻结：在轮次记录顶部写明「之后只允许更正事实，不再追加功能轮」。新需求另开决策记录，不要偷偷插一轮。

## 5. 取舍登记格式

每条 🚫 至少写四行：

```markdown
**A3 线性化（Fast Web View）**
- 想要什么：网页端边下边看。
- 为什么不做：本工具是离线双击交付，不从服务器分发，线性化对本地打开没有任何收益。
- 代价：文件首屏仍要等全量解析。
- 重新打开的条件：一旦要提供 Web 版托管。
```

缺「代价」和「重新打开条件」的取舍，半年后会被当成待办重新捡起来。
