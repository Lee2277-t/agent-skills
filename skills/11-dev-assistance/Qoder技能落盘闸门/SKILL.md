# Qoder 技能编辑阻塞排查

旧笔记来自特定版本的本机日志，不能当作所有版本的内部机制说明。以当前工具返回、目标路径和宿主文档为准。

## 根据实际错误处置

| 错误 | 检查与下一步 |
|---|---|
| SKILL_CONFIRMATION_REQUIRED | 说明该次操作被宿主要求确认；保留已完成的可评审内容，按当前宿主流程等待所需授权。 |
| SKILL_TARGET_MISMATCH | 核对本次绑定技能目录、解析后的绝对路径及写入范围；修正误路径，不尝试写其他目录来规避检查。 |
| SKILL_PATH_CHANGED | 只读比较当前文件与预期版本，查明并发改动或登记状态差异；同一请求被拒后不连续重试。按宿主提供的刷新、重新选择目标或恢复流程处理。 |

## 保留与恢复

- 原有技能、已验证脚本和用户改动都要保留，不为消除错误覆盖当前版本。
- 若允许导出草稿，可在已授权位置保存内容与差异；若连草稿写入也被拒，则在回复中给出必要内容和未完成原因。
- 不故意提交会被拒绝的写调用来把正文塞入日志，不切换会话或工具绕过当前限制。
- 需要从既有历史恢复时，只读用户指定的有关记录，核对版本、时间、内容与资源依赖。字节数更大不代表版本更正确。
- 收到可执行的恢复方式后再写入，回读文件并检查 YAML、资源引用及实际发现状态。

## 验收

分别报告草稿已准备、文件已写入、技能已被宿主发现、行为已验证四种状态。错误消失或技能出现在列表中，都不能单独证明脚本与依赖齐全。
