# GitHub 发布前审计

先明确要公开的内容与目的地，再检查清单、修复真实问题、按授权发布并回读结果。本技能加载本身不授权发布、建仓或读取凭据；已有用户发布授权有效，不重复索要固定口令。

## 检查与执行

1. 确认项目、目标仓库/分支和上传范围。读取项目规则与相关差异，区分源码、构建产物、Release 附件和本地用户数据。
2. 先运行只读检查，以下路径均相对技能目录：

   ```text
   python scripts/audit.py <项目目录> --dry --json
   ```

   退出码 0=规则内 PASS、1=WARN、2=BLOCK、3=环境/参数错误。输出不是完整安全证明。
3. 对实际上传清单检查密钥、隐私、许可证、依赖与大文件；说明告警证据、是否误报及处理。工具默认只检查已跟踪文件，未跟踪文件另列排除；若准备新增文件，必须在纳入上传清单后重新检查，不能只用当前 PASS 放行。检查暂存内容及相对工作区的差异，避免工作区已清理而暂存区仍含旧密钥。
4. 需要 README 骨架时先预览：`python scripts/make_readme.py <项目目录> --name <名称> --dry`。它不带 `--dry` 就会写文件，不能把生成骨架当成可直接发布的成品；核对示例命令、链接和许可证后再保存。
5. 需要持久报告时，`audit.py --write-report` 会写项目内 `report.md` 和 `report.json`；避开已有同名文件，不把报告意外纳入上传。模板在 [templates/](templates/)，按部署目标选择，不能自动安装 Git hook 或 CI。
6. 明确授权且清单已核对后执行对应发布，回读远端文件/Release 与实际版本。发生认证或网络问题先定位，不轮换凭据、改目标或扩大发布范围；可在原授权内做有依据的安全重试。

## 工具边界

- 原脚本使用 Python 标准库及 Git。历史只扫最近 40 个提交；内容默认最多 400 个文本文件，跳过大于 2MB 文件且长行有截断；非 Git 的忽略语义不完整。报告这些覆盖缺口，重要发布可复用项目已有密钥扫描工具。
- 50MB 是本脚本的保守阈值，不是所有平台或所有发布方式的统一限制。核对实际目的地规则，不能为了通过脚本隐瞒大文件。
- 规则匹配会漏检，也会误报；不要把 PASS 称为“无任何密钥”，不要输出完整凭据。使用当前可用认证机制，不沿用原作者机器上的凭据文件路径。
