# 前端视觉打磨

保留用户品牌、现有设计系统与功能，用页面真实问题决定改动。上游的颜色、字号、圆角数量是参考，不是所有页面必须满足的配额。

## 快速路径

第一次用，只读本页和 `ai-tells.md` 就能开始；其余按需查，不要一次读完。

| 你的情况 | 只读这些 | 做到哪一步 |
| --- | --- | --- |
| 页面能用但不好看 | 本页「工作方式」+ `ai-tells.md` | 拍 before → 审计 → 改 → 复拍 |
| 不知道往哪个方向改 | `aesthetic-direction.md` | 写 5 行简报，选一套骨架 |
| 配色或字体乱 | `color-and-type.md` | 9 档色板 + 4 档字阶 |
| 布局散、组件糙 | `layout-and-components.md` | 内在布局 + 空/载入/错误三态 |
| 动效别扭 | `layout-and-motion.md` | 时长、缓动、origin |
| 想系统提升审美 | `aesthetic-direction.md` + `sources.md` | 四周训练路径 |

## 工作方式

1. 读取相关页面与样式，能运行时看截图或当前 UI，确认内容、主操作与响应式问题。无法截图时先做可证实的局部改动，并明确视觉待验，不因工具不可用无限停工。
2. 可先运行静态辅助检查：`python scripts/audit_ui.py <页面或目录> --json`。脚本路径相对本技能目录；只读，Python 标准库。先读它的检查范围，再把结果与页面事实比对。
3. 按问题选择设计约束，复用已有 tokens 和组件。一般优先调整层级、可读性、间距和对比度；不要为固定“去 AI 味”清单删除有用的渐变、卡片或圆角，不为单一评分强行重做结构。
4. 改动集中在本次范围，保留功能入口、交互状态和无障碍表现。依赖按项目约定处理，不为一次样式调整建立新体系。
5. 对受影响页面复查桌面及相关窄屏宽度、长中文、溢出、遮挡、键盘焦点与必要动效降级。比较修改前后截图；静态审计用于提醒，分数不等于审美或无障碍验收。

## 截图辅助

优先使用当前宿主已有浏览器/截图能力。需要独立截图时：

```text
python scripts/shot.py <本地HTML或URL> --out <新的输出路径.png> --width 1280 --height 800
```

脚本寻找 Chrome/Edge，用临时 userData，不使用个人浏览器资料。`--full-page` 实际使用固定 6000px 高度，并非真实内容全长；它不能代替交互与真实可见窗口检查。检查截图新鲜度和尺寸；原脚本报错提示中的 `--browser` 尚未实现，不照该提示传参。
