# 上游调研与取舍

## 调研了什么

| 来源 | 内容 | 采纳 | 不采纳及原因 |
| --- | --- | --- | --- |
| `anthropics/skills` 的 `brand-guidelines` | 品牌一致性检查表 | 「一次只动一类」的分步思路 | 它面向品牌手册，不面向代码 |
| `anthropics/skills` 的 `artifacts-builder` | 生成可视产物的规范 | 「先拍截图再交付」的纪律 | 它是生成新页面，不是改旧的 |
| `github/awesome-copilot` 的 UI prompt 集 | 大量「make it beautiful」提示词 | 反面教材：这些提示词正是 AI 味的来源（要求「modern, clean, gradient, glassmorphism」） | 完全不采纳 |
| Tailwind / shadcn 默认主题 | 事实上的「AI 默认长相」 | 明确了要避开的色值和圆角（`#667eea→#764ba2`、`rounded-2xl`、`shadow-lg`） | 不引入依赖 |
| Refactoring UI（Adam Wathan & Steve Schoger） | 间距/层级/对比度的原则 | 核心方法论：**约束档位、靠对比建立层级、留白优先** | 它的具体色板不照抄 |
| 《写给大家看的设计书》（Robin Williams） | 对比/重复/对齐/亲密性四原则 | 「亲密性」用于间距分组 | — |
| 中文排版需求（W3C clreq） | 中英混排空格、标点、行高 | `typography-cn.md` 全部依据 | — |
| Vercel / Linear / GitHub 的实际界面 | 现成的好设计 | 四套骨架的气质参考 | 不抄具体像素 |

## 核心结论

**「AI 味」的技术定义**：每个视觉属性都取了训练数据里的**众数**——最常见、最安全、最不会出错的值。众数堆在一起，就成了「见过一万次但说不出是谁做的」。

对策不是「换一套更花的设计」，而是**做选择**：把档位收窄到少数几个值，并让每个值都有理由。一个有 3 种颜色、4 级字阶、1 种圆角的页面，几乎不可能是 AI 默认生成的。

## 为什么不推荐某些流行做法

| 做法 | 为什么不推荐 |
| --- | --- |
| 玻璃拟态（glassmorphism） | 2021 年的趋势，现在等于「模板」；且 `backdrop-filter` 在滚动时掉帧 |
| 新拟物（neumorphism） | 对比度天然不达标，无障碍过不了 |
| 大圆角 + 彩色阴影 | shadcn 默认长相，一眼可辨 |
| 渐变文字标题 | 2023 后的 AI 生成标志 |
| 每个区块都滚动进场 | 用户滚到第三屏就开始烦 |
| 3D 插画 / 手绘风 | 除非有设计师，AI 生成的插画质量不稳定，反而减分 |
| 暗色优先 | 工具类产品暗色好看，文档类产品暗色反而难读；先做亮色 |

## 没做的

- **不做设计系统生成器**：用户要的是「这个页面变好看」，不是一套 Figma token。
- **不做自动截图对比评分**：像素级 diff 对「变好看了吗」这个问题没有帮助，人工看截图更准。
- **不引入任何 npm 依赖**：脚本纯 Python 标准库 + Chrome，零安装。
