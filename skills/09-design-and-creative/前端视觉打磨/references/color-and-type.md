# 色彩与字体：把「少」变成系统

## 一、色板不是五个色号

Refactoring UI 的结论：五个 hex 建不出界面。真实项目需要三类颜色：

- **灰阶 8–10 档**：文本、背景、面板、控件，界面里九成面积都是灰。
- **主色 5–10 档**：按钮、导航、强调，决定产品的整体印象。
- **语义色**：成功、警告、危险，每种 2–3 档（文字、背景、边框各一档）。

档位不是越多越好，而是「需要更深一档时不用妥协」。9 档最合适：好分、够用。

### 9 档法：先定三个点，再填中间

1. 选 **base（500）**：能直接当按钮背景的那个色。
2. 选 **最深（900）**：能当该色系正文的颜色。
3. 选 **最浅（100）**：能当提示条背景的 tint。
4. 填 **700 / 300**：各自是两侧的折中。
5. 再填 **800 / 600 / 400 / 200**。

灰阶同理：最深 = 最深正文，最浅 = 近白背景，中间按真实使用场景填。

**不要**在代码里用 `lighten()` / `darken()` 现场生成深浅。最后一定会出现几十个看起来一样的蓝。档位在 token 文件里定死，用完为止。

### 灰阶要带一点色相

纯灰（R=G=B）放在彩色界面里会显脏或显冷。做法：灰阶往主色 hue 偏 **2–6 度**，饱和度 **2–8%**。

```css
:root {
  --gray-0:  #ffffff;
  --gray-50: #f8f9fb;
  --gray-100:#f1f3f6;
  --gray-200:#e3e7ed;
  --gray-300:#cdd3dc;
  --gray-400:#9aa3b0;
  --gray-500:#6b7482;
  --gray-600:#505967;
  --gray-700:#3a424e;
  --gray-800:#242a33;
  --gray-900:#15181d;
}
```

判断标准：把灰阶和主色放在一起，灰不应该像「另一个品牌」。暖色品牌就往暖偏，冷色品牌往冷偏。

### 不要纯黑纯白

- 正文用 `#1f2328` 或 `#15181d`，不用 `#000`。
- 页面底色用 `#fafafa` 或 `#f8f9fb`，不用大面积 `#fff`。
- 纯白留给卡片、输入框、弹层，让它们形成「一层表面」。

纯黑在屏幕上刺眼，纯白大面积会放大眩光；两者都会让页面显得廉价。

### 对比度

- 正文 ≥ **4.5:1**。
- 大字（≥ 24px，或 ≥ 18.66px 粗体）和 UI 边界 ≥ **3:1**。
- **不要在彩色底上放灰字**：灰在彩色上同时丢失色相和明度对比，看起来像没调完。用同色系更深的一档，或白色 + 加深底色。
- 状态不能只靠颜色：错误同时给图标、文案、边框。

`audit_ui.py` 只做粗略估算，最终以 DevTools 的对比度检查或 axe 为准。

### OKLCH：让「同一亮度」真的同亮

HSL 的 L 不是感知亮度：同一 L 的蓝和黄，看起来差很多。OKLCH 的 L 接近感知均匀，适合成组地造色。

```css
:root {
  --accent:       oklch(0.58 0.16 255);
  --accent-hover: oklch(0.52 0.17 255);
  --accent-soft:  oklch(0.96 0.03 255);
  --ok:           oklch(0.62 0.14 150);
  --danger:       oklch(0.58 0.18 25);
}
```

- 做分类色时固定 L 和 C，只转 H，得到一组「重量相同」的颜色。
- 深色模式不要直接把 L 调低：深色底上要**降 C（饱和度）、略提 L**，否则会荧光。
- 兼容旧浏览器时保留 hex fallback；现代浏览器已支持。

### 语义色与用量

- 主色只负责「可操作」和「当前选中」；成功/警告/危险只负责状态。不要拿主色表示成功。
- 一个页面一个强调色；全屏强调色出现 **≤ 3 处**。
- 大面积色块用 50–100 档，文字用 700–900 档，按钮用 500–600 档。

### 深色模式

不是反色：

- 背景 `#0d1117` 级，表面 `#161b22`，悬浮 `#1c2128`；层级靠表面亮度差，不靠阴影。
- 文字 `#e6edf3`，不用 `#fff`。
- 品牌色降饱和，避免发光。
- 边框比亮色模式更明显，因为阴影几乎不可见。
- 图片降亮度：`filter: brightness(.85)`。

## 二、字体系统

### 字阶：4–5 档，比例固定

```css
:root {
  --text-xs:   12px;
  --text-sm:   14px;
  --text-base: 16px;
  --text-lg:   20px;
  --text-xl:   28px;
  --text-2xl:  40px;  /* 只有展示型页面才用 */
}
```

- 产品界面用 **1.25** 左右的比例，展示页可以用 **1.333**。
- 不要出现 16/18/22/24 这种「每档只差 2px」的伪层级；层级要靠跨度。
- 大多数页面 4 档就够：12 / 14 / 16 / 20（或 24）。
- 中文正文不要小于 14px，16px 最稳。

### 行高与字号反比

| 用途 | 行高 |
| --- | --- |
| 正文（西文） | 1.5–1.65 |
| 正文（中文） | 1.7–1.75 |
| 小字 | 1.5 |
| 标题 | 1.15–1.3 |
| 超大标题 | 1.0–1.15 |

字号越大，行高越紧；字号越小，行高越松。用同一个行高贯穿全站，是模板感的来源之一。

### 行宽

- 西文正文 **45–75 字符**，`max-width: 65ch` 是好起点。
- 中文正文 **30–40 字**，约 `max-width: 36em`（随字号换算）。
- 衬线正文可以比无衬线略宽，行高也略大。

### 字重只留两档

- 正文 400，强调/小标题 600。
- 中文很多系统只有 400 和 700；700 用在中文大标题上容易糊成黑块。宁可降到 600，或靠字号和留白。
- 层级顺序：**字重 + 颜色 > 字号 > 装饰**。Refactoring UI 的做法是先用 weight 和 color，不够再放大字号。

### 字距

- 大标题（≥ 32px）：`letter-spacing: -0.01em ~ -0.03em`，收紧才不散。
- 小字或全大写：`+0.02em ~ +0.05em`；但全大写标签本身是 AI 默认，慎用。
- 中文正文：`0 ~ 0.01em`，不要明显加宽。

### 断行

```css
h1, h2, h3 { text-wrap: balance; }  /* 短标题，行数有限 */
p { text-wrap: pretty; }             /* 避免孤字成行 */
```

`balance` 只适合标题；长段落交给 `pretty`。

### 不下载字体也能有质感

Modern Font Stacks 按字族分类提供系统字体栈：零下载、零布局跳动、零闪烁。下面是四组最常用的：

```css
/* 系统 UI：最稳 */
font-family: system-ui, sans-serif;

/* 过渡衬线：正文、编辑感 */
font-family: Charter, "Bitstream Charter", "Sitka Text", Cambria, serif;

/* 旧式衬线：更古典、书卷气 */
font-family: "Iowan Old Style", "Palatino Linotype", "URW Palladio L", P052, serif;

/* 几何人文无衬线：比 Inter 更有性格 */
font-family: Avenir, Montserrat, Corbel, "URW Gothic", source-sans-pro, sans-serif;

/* 工业窄体：标题、数据感 */
font-family: Bahnschrift, "DIN Alternate", "Franklin Gothic Medium",
             "Nimbus Sans Narrow", sans-serif-condensed, sans-serif;
```

中文字体仍按 `typography-cn.md` 用系统栈。不要为了标题引一个 10MB 的中文字体；思源黑体全量约 16MB，网页加载等于自杀。

### 搭配：两个必须明显不同

- 衬线标题 + 无衬线正文：编辑感，最稳。
- 窄体/工业标题 + 常规正文：技术感、工具感。
- 同一字族的 weight/width 对比：最安全，但需要 variable font。

**不要** Inter + Roboto、PingFang + 思源黑这种「看起来一样」的组合——两个字体如果分不出来，不如只用一个。

### 字体就是身份

Anthropic 的反面清单：只给标题里的一个词换斜体/加粗/换色；全大写标签；每个标题上加小标签。这些不是排版，是装饰。

正面做法：整行标题用同一种处理——超大字重、极窄宽度、整句衬线斜体、超大字号 + 紧字距——让它本身成为视觉元素，而不是内容的包装盒。

### 数字

```css
.table, .price, .timer { font-variant-numeric: tabular-nums; }
```

表格、金额、计时用等宽数字，并右对齐。正文里的普通数字可以用默认比例数字，不必全站开等宽。
