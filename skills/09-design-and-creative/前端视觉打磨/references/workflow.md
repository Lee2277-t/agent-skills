# 动手顺序与翻车点

## 顺序（不要打乱）

### 第 0 步：拍现状

在技能目录内运行（或把 `scripts/` 换成本技能的绝对路径）：

```bash
python scripts/shot.py <url|html路径> --out before.png --width 1280
```

同时拍一张窄屏：

```bash
python scripts/shot.py <url> --out before-mobile.png --width 390
```

**优先拍 before。** 没有截图就无法对比；截图工具不可用时，先记录现状（关键 DOM、字号、色值、窄屏表现），做可证实的局部改动，并明确「视觉待验」，不因工具不可用无限停工。

### 第 1 步：审计

```bash
python scripts/audit_ui.py <目录>
```

输出分数和问题清单。记下分数和具体问题，改完主要对比问题是否消失，分数只作回归提示。

### 第 2 步：定约束（5 分钟，别省）

在纸上或注释里写下四个数：

```
颜色：主色 ____  强调 ____  危险 ____  + 灰阶 4 档
字阶：____ / ____ / ____ / ____
圆角：____（最多 2 档）
阴影：____（1 层，透明度 ____）
```

从 `design-language.md` 选一套骨架直接抄值。**这一步不做，后面一定乱。**

### 第 3 步：改（一次一类）

严格按这个顺序，每类改完截图看一次：

1. **结构**：`<h1>` 唯一、主操作唯一、信息层级
2. **排版**：字号档位、行高、字重、中英混排空格
3. **间距**：档位收敛、对齐、留白
4. **颜色**：色板收敛、对比度、暗色模式
5. **圆角阴影**：收到 1–2 档
6. **动效**：最后做，只做必要的

**为什么这个顺序**：结构错了，调颜色是白费；颜色错了，动效再好也救不回。而且每类独立改，出问题能立刻定位是哪一步引入的。

### 第 4 步：再拍 + 对比

```bash
python scripts/shot.py <url> --out after.png --width 1280
```

把 before/after 并排看。**只看截图，不要看代码**——用户看到的就是截图。

### 第 5 步：复审计

```bash
python scripts/audit_ui.py <目录>
```

分数降了先查原因，不要直接回退：可能是删掉了没用的装饰，也可能是丢了对齐或对比度。分数不等于审美验收，清单和截图优先。

### 第 6 步：过 AI 味清单

打开 `ai-tells.md`，六节逐条打勾。**这一遍不能省**，它是这个技能的核心价值。

## 翻车点

### 1. 改了全局样式，别处塌了

**症状**：改 `.card` 的 padding，结果导航栏也变了（因为导航也用了 `.card`）。

**预防**：改之前先 `grep` 类名用在哪些地方：

```bash
python -c "
import pathlib,re
name='card'
for p in pathlib.Path('.').rglob('*'):
    if p.suffix in ('.html','.jsx','.tsx','.vue','.svelte','.css'):
        for i,l in enumerate(p.read_text(encoding='utf-8',errors='ignore').splitlines(),1):
            if name in l: print(f'{p}:{i}: {l.strip()[:80]}')
"
```

用在 3 个以上地方 → 不要直接改，加新类或加修饰类。

### 2. 移动端塌了

**症状**：桌面好看，手机上文字溢出、按钮点不到、横向滚动条。

**预防**：每次改完必拍 390px 宽截图。三个高频原因：

- 固定宽度 `width: 600px` → 改 `max-width`
- flex 子项缺 `min-width: 0` → 加
- 长单词/URL 没断 → `overflow-wrap: break-word`

### 3. 暗色模式下白底白字

**症状**：用户在系统暗色模式打开，一片白或者一片黑。

**预防**：颜色**全部**走 CSS 变量，不要在任何地方硬编码 `#fff` / `#000`。改完用 Chrome DevTools 的 Rendering → `prefers-color-scheme: dark` 模拟一遍。

### 4. 引入字体导致白屏 3 秒

**症状**：`@import url(https://fonts.googleapis.com/...)` 在慢网下阻塞渲染。

**预防**：中文字体不引；英文字体用 `<link rel="preconnect">` + `font-display: swap`；或者干脆用系统字体栈。

### 5. 「越改越花」

**症状**：每轮都想加一点东西（再加个渐变、再加个动效），最后比原来还乱。

**预防**：**每轮只能删不能加**，除非有明确理由。改完问自己「我删掉了什么」，答不上来就是加多了。

### 6. 把用户的品牌色改掉了

**症状**：用户说「优化一下」，你把主色从红换成蓝。

**预防**：除非用户明确说「配色随便改」，主色不动。只调它的**用法**（用在哪、用多少、配什么灰）。

### 7. 无障碍倒退

**症状**：为了「简洁」把 `alt` 删了、把 label 改成 placeholder、把按钮做成 `<div onclick>`。

**预防**：`audit_ui.py` 会查 `alt`、`<h1>`、可点区域。对比度低于 4.5:1 必须改。

## 报告模板

改完给用户这样的回复（不要只说「优化好了」）：

```
## 改了什么

**排版**
- 字阶 6 档 → 4 档（32/20/16/14），删掉 18px 和 22px 两个「中间值」
- 正文行高 1.5 → 1.7（中文需要更松）
- 中英混排补了 12 处空格

**颜色**
- 主色 #6C5CE7 → #0969DA：原色在浅底对比度 3.1:1 不达标，新色 5.2:1
- 灰阶从 5 种收到 4 种
- 删掉 3 处渐变文字标题

**结构**
- 主操作从 3 个并列按钮改成 1 主 2 次
- feature 卡片从 3 个改成 4 个（3 是最模板的数字）

**动效**
- `transition: all` → 指定属性，时长 300ms → 150ms
- 删掉滚动视差
```

## 什么时候该停

改到「四问都能答好、AI 味清单全过、窄屏不塌」就停。80 分只是回归下限，不是目标；继续抠细节的收益很低，而且容易过度设计。

真正的提升来自**内容**（真实截图、具体文案、能用），不是再调 2px。
