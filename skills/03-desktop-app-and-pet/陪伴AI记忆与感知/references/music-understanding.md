# 音乐情绪与乐器识别增强

核对日期：2026-10-29。依据文末官方文档/源码整理，以下窗口、流程与验收安排是本库工程建议。当前收录的是方法，尚未安装模型或完成真实歌曲推理。

## 先选路径，再运行

复用 soundcheck 的基础特征，盘点当前可用 Python、推理后端、模型权重、显存/内存及目标平台。先核对已有源码是否已启用声音标签模型，避免重复部署。只装能回答本次问题的一个基线，先分析代表片段；有歧义再扩大时间范围、分轨或加第二模型。

| 问题 | 可选基线 | 必须核对 |
|---|---|---|
| 常见声音/乐器候选 | PANNs AudioSet 标签；需要时间定位时评估其事件检测模型 | 实际 checkpoint 的类别表、采样率、片段/帧级输出和时间换算 |
| 偏音乐领域的乐器候选 | Essentia 的 MTG-Jamendo instrument 模型 | 标签范围、配套 embedding、输入及输出节点；没有的类别不能识别为确定标签 |
| 情绪走势 | Essentia 的 valence/arousal 回归或 mood 分类模型 | 匹配的特征提取器、维度顺序、数值范围及时间聚合方式 |
| 歧义音色/情绪描述比较 | LAION-CLAP 的音乐相关 checkpoint | 音频预处理与文本语言、checkpoint、候选描述集合；相似度未经概率校准 |

核对包版本、模型来源/哈希及代码与权重各自许可证。Essentia 官方模型页注明 MTG 模型使用 CC BY-NC-SA 4.0 并提供其他授权渠道；产品采用前核对具体模型授权。Windows 安装和导出格式以目标版本实测为准，不因为有 Python 示例就承诺原生 Windows 可直接运行。

不要照抄旧教程的 Python/CUDA 版本或默认自动下载命令。记录需要下载的权重和依赖，在当前授权范围执行；方法学习无需顺带安装大型模型。失败时保留可用特征与缺口，不静默换云服务。

## 分段与证据对齐

1. 记录原始音频路径、内容哈希、时长和有效区间。只有歌词、封面或曲名时，不能声称分析了声音。
2. 复用已存在段落；没有时可从 10–20 秒重叠窗口试起，再按模型实际感受野调整。这不是通用最优窗口。短尾段、静音和补零分别标注；补零不算真实音频。
3. 同一源片段按各模型要求分别重采样/归一化。CLAP 文档数据接口示例使用 48 kHz，PANNs 有不同采样率模型；不要用一个采样率套全部模型。响度测量保留原电平，模型预处理后的电平不能冒充母带响度。
4. 保存窗口起止、模型输出、聚合方式与源时间偏移；剪下片段后的局部时间要加回原始起点。标签覆盖窗口不代表精确音符级起止，整段分类也不能冒充帧级检测。

## 乐器：逐级判断，保留未知

先判断打击/弓弦/拨弦/管乐/键盘/电子等音色家族，再在实际类别范围内判断具体乐器。一个片段可含多种乐器，不能强制 Top 1；父标签“弦乐”和子标签“小提琴”不算两个独立声源。标签缺失不证明该乐器不存在，分数低也可能来自混音掩蔽。

对歧义段落，用相同上下文的 CLAP 描述比较，例如分别比较小提琴、二胡、合成弦乐的声音描述，另加其他音色对照；尽量只改变待比较的乐器词。先测试 checkpoint 支持的文本语言，不假设中文乐器名会自动获得稳定语义。候选集合会影响排序，只问“小提琴还是钢琴”不能排除真正是二胡。零样本候选没有自动成为模型新增类别。

两种证据相符可增强判断，但使用同源数据/相似模型不能视作独立确认。冲突时回听或扩大对照，仍不清楚则退回音色家族/未知。没有实际听取能力时注明“模型候选”，不写“我听到”。

混音过密且问题需要时再分轨；分轨可能生成伪影，必须对照原混音。鼓/贝斯/人声/其他四轨不是四种具体乐器，`other` 更不是一个确定乐器。古筝、琵琶、唢呐、二胡以及合成器仿真音色须用有出处的独奏与混音样本单独评估；没有支持证据时不把标签翻译成某个中国乐器。

## 情绪：曲线与解释分开

把 valence 理解为愉悦倾向，arousal 理解为激活程度；维度值是模型估计。按模型元数据解码轴顺序、量纲和标签，不随意把不同模型输出映射为同一百分比。“非开心”不等于“悲伤”，多个二分类 mood 分数也不构成互斥情绪分布。

分别描述伴奏氛围、人声表达与歌词含义。歌词须有实际文本及必要对齐；歌词消极不意味着声音悲伤。音量大/速度快只能支撑能量或节奏观察，不能单独推出开心；小调也不是悲伤的充分条件。音乐表达不能用来推断作者、演唱者或听众的真实心理状态。

先看各段变化，再给全曲概括；避免均值抹掉“平静主歌→紧张过渡→释放副歌”。平滑用于减少抖动时保留原值和突变；时序平滑不能使错误标签变真。诗意联想可作为明确的主观解读，不写入客观测量字段。

## 交给文本模型的最小证据

按需保存以下信息，不强制给用户展示大段 JSON：

| 信息 | 内容 |
|---|---|
| 来源 | 音频哈希、原时间区间、原混音或分轨、模型与权重版本 |
| 基础测量 | 与问题相关的拍速候选、响度/能量变化及单位 |
| 乐器 | 候选名称/家族、分数类型、窗口或事件级范围、替代解释 |
| 情绪 | 各维度名称/原始量纲、段落趋势、声音与歌词各自依据 |
| 结论边界 | 模型冲突、缺失能力、覆盖范围、未知项及是否实际试听 |

保留模型原始分数；未校准时不生成“识别准确率 92%”或自造置信度。不把跨模型分数直接平均。若产品要显示高/中/低可信度，先定义独立验证支持的判定规则，否则直接写候选、相符或冲突。

回答先突出最明显且有证据的变化，再给支持它的少量时间点。只输出与问题有关的证据，不把每个标签平均写成鉴赏段落。

## 成本与返修

缓存键覆盖音频内容、片段、预处理、模型/权重、标签与 CLAP 候选集。换候选文字可复用兼容音频 embedding，但需重算文字相似度；换 checkpoint 不复用旧 embedding。只对有争议段补分析；不要为一处音色误判重跑所有模型或整首 ASR。

## 实际接入后的验收

- 乐器：用有可靠标注且未参与阈值调优的独奏、真实混音、中国乐器、相似音色和未覆盖声源；统计每类 precision/recall、误报、漏报与拒答。训练集/验证集按曲目或来源隔离，不能把同曲邻接片段分两边造成泄漏。
- 情绪：由多人独立标注段落和转折，保留分歧；回归可看误差/相关性，分类看各类结果。与仅用基础声学特征的基线比较，不能靠一次生成的文字“听起来合理”验收。
- 时间：核对片段偏移、重叠合并、尾段补零及模型输出步长。检查只出现两秒的乐器不会被误写成整曲存在。
- 退化：静音、噪声、无目标乐器、短音频、缺模型及分轨伪影；纯正弦波可测技术边界，不能证明真实乐器识别准确。
- 运行：记录设备、冷启动/缓存延迟、峰值内存及失败行为；模型不可用时只能返回已测部分。对未装模型的本次技能更新，只报告文档/引用校验，不报音乐识别通过。
