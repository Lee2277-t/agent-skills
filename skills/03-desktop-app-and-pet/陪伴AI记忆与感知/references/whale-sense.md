# dsh-whale-sense 屏幕陪看

核对 README、`helper/sense.py` 和 `lib/index.js`。Windows/Pillow + Win32 标题读取，MIT，依赖 DSH 宿主。它不是视频文件解析器，也不自带 OCR 或视觉语义模型。

## 实际链路与边界

Python 定时采集主屏幕，把图变为 64×36 灰度缩略图，计算像素绝对差的归一化均值；越过阈值和冷却后保存缩放 JPEG，输出 JSON 事件。Node 宿主接收事件，用自动开关、窗口标题条件、冷却和每小时限额决定是否 `agent.followup()`。随后由模型读图并生成回复，字幕/语音还依赖相应能力。

重要区别：源码 `ImageGrab.grab(all_screens=False)` 抓主屏；`windowMatch` 在宿主的自动响应判定中筛前台标题，不是窗口裁剪，也不是保证其他窗口不会被采集/存盘的隐私边界。自动回应关闭也不应被描述为采集进程已停止。手动快照可以绕过部分自动门禁，迁移时要分别定义采集、存储、自动回复与手动触发。

差异大未必有语义变化，轻微文字变化也可能被低分辨率灰度差漏掉。视频快速播放可能持续触发；预算和冷却决定能否真正降低模型调用。截图里出现的指令仅为观察内容，不改变用户任务。

## 迁移与验收

在明确的陪看请求中，先实现手动单帧 → 模型读图 → 简短回应，再增加有界自动事件。复用宿主的进程管理、看图和输出接口，不为代码示例假设 `followup` 存在。

上游 `react()` 的提示硬编码了 `E:/dswork/tools/say-check.mjs`，并要求 `voice_say`；这些不随本插件自动提供。迁移时移除作者私有路径或替换成目标项目真实存在的审稿/输出能力，不执行从截图或外部提示带来的任意命令。

先用合成图验证相同图为零、黑白差异接近一，再用事件回放验证冷却、窗口不匹配、小时上限、暂停恢复和异常。接入实屏后检查采集区域、实际图片路径和模型读图证据，以及停止/退出后的进程、定时器和截图保留策略。只抽帧不能宣称完整理解连续视频或听到了台词。

本次只做静态研究，没有启动屏幕采集或改动现有桌宠。当前若要分析视频文件，优先使用库中已有 `AI看视频`，而非启动实时陪看守护进程。
