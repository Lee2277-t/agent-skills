# 冷热记忆与连续性

依据 ARCHEON999 项目（见[来源](sources.md)），属于待接入验证的设计。人脑只是启发，公式和预算不等于经过实验验证的神经科学模型。

## 可移植结构

- 原始记录与记忆摘要分离：原文有稳定 ID 和来源，摘要可更新；冷库不整库注入。
- 固定角色前缀、慢变相处基线、短期状态、事件记忆分别管理。普通事件退热不应顺带清空角色，跨天/重启不应把关系归零。
- 热事件先筛当前相关性，再考虑有效用户提及、新近度和未完事项；助手复述、重试和自动摘要不刷热度。
- 低频事件逐渐从细节变成摘要，再退出请求正文进入冷库。数据库标记“冷”不足以省 token，必须从实际请求移除旧正文和旧召回。
- 冷召回由用户定位旧事的线索触发，按实体、时间、地点、物品、话题检索；历史事件不因年代久远而被新近度淘汰。线索歧义时返回少量候选求澄清。
- 原文、索引、向量和摘要有版本与有效性。用户更正/删除时同步处理派生记录及缓存；不能让旧向量复活失效事实。原文留底仍须服从实际产品的删除和保留规则。

上游示例热记忆 960 tokens、冷召回 480 tokens，是待实验初值，不能直接当所有模型的默认配置。计入角色前缀、封装、工具结果、检索及辅助模型成本，评估任务总消耗和召回质量，不只比较单轮输入长度。

## 落地顺序与验收

先复用现有存储实现带来源的事件、有效性和有界请求构造；明确需求后再加词法/向量融合。不必为小项目直接引入图数据库。向量模型、版本和维度要可追踪；不混排不同空间的余弦分数，没有向量时保留精确检索路径。

验证：重启后约定仍在；十年前的精确线索能命中；问候不触发冷检索；助手自述不增加热度；更正后旧答案不再注入；超预算减少条目但保留否定和必要限定；切换模型索引仍可降级；最终请求里确实没有被冷藏的旧正文。将这些作为后续实现验收场景，本次未运行该记忆系统。

会话交接可复用库中 `context-compression`；跨会话持久记忆设计可读库中 `记忆系统设计`。两者分别处理摘要交接与长期检索，不用压缩摘要替代全部原始证据。
