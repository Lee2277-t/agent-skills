# 按改动影响范围验证

目标：用能守住本次行为的最小检查集合交付证据。不是只测修改过的文件，也不默认把所有功能跑一遍。

## 1. 确定本次变化和基线

- 先读项目 AGENTS.md、当前入口及任务相关测试说明，再按需读源码。确认当前保留、退役和未实现的功能；历史交接不能覆盖当前事实。
- 有 Git：结合工作区、暂存区、未跟踪文件和本任务提交确认差异。比较分支时使用确认过的基准与 merge-base，不假定分支叫 main。不能遗漏未提交内容，也不能把别人的已有改动都算成本次任务。
- 无 Git：修改前在项目允许的测试产物目录保存本次相关源文件的原内容、相对路径与哈希，以及判断新增/删除所需的文件清单。新文件记为原先不存在；修改范围扩大时先补基线。清单限定运行源码、配置和相关资产，排除依赖、缓存、历史归档、用户数据和密钥，不复制整个项目。
- 已经改完且没有可信基线：用任务记录、用户指定文件和当前调用关系判断，标明无法完整确认的差异；当前文件不能冒充修改前版本，不能仅据当前状态证明没有误删。
- 项目是缄桌宠或结构相似的 Electron 应用时，按需读 [桌宠参考](references/desktop-pet.md)。其中路径和脚本都是候选，使用前核对当前项目。

## 2. 从差异确定受影响行为

从改变的行为出发，沿入口、调用方、消费者和状态传播找影响范围。检查必要的间接调用，不固定为只追一层；到未改变的契约或能说明不受影响的边界再停止。

除 import/require，还要考虑 IPC/事件、动态加载、页面 script、CSS 选择器与命中区、资源路径、共享配置、缓存及异步回调。文件同名或历史上一起提交只能作线索，不能单独证明相关或无关。

| 变化 | 至少确认什么 |
|---|---|
| 新增 | 能从实际入口触发、预期行为成立、必要的失败/取消路径以及与现有流程的交接；新增测试自身必须纳入 |
| 删除 | 原入口与调用同步移除、后台任务和注册被清理、共享的保留行为仍可用；用户数据是否保留按需求验证 |
| 修改 | 改变后的行为及相关边界、调用方契约、共享状态的其他消费者 |
| 纯文案/样式/素材 | 实际显示、布局、加载与必要交互；文案若参与程序分支、布局若改变命中区，就沿相应行为继续追踪 |

公共初始化、状态格式、依赖和共享播放逻辑改变时，扩大到实际消费者。只有影响确实遍及全应用、项目强制或用户要求时才全量验证，并说明具体原因；不因改了 main.js 或 package.json 就机械全量。

## 3. 选择和执行最小有效检查

执行前简述：本次变化 → 受影响行为 → 选择的检查及原因。范围明确时直接执行，不把普通测试选择变成额外审批。

- 优先复用项目现有的定向命令、用例过滤或行为脚本。先看实际断言、运行环境和副作用，确认测到本次行为；不只信测试文件名、旧报告或说明文档。
- 新增/修改的测试、仍未解决的相关失败都纳入。共享状态按消费者选代表性行为和必要边界，不把受影响功能再裁掉来节省成本。
- 测试不支持过滤时，运行最小的相关整份脚本；不要为一次小改动开发通用选择器、改造全部旧测试，或只删断言得到“定向通过”。脚本很宽且没有必要全跑时，可做最小独立行为检查。
- 现有测试测不到时才补最小检查。修 bug 先用原问题输入/操作确认失败条件，再验证修正；断言来自预期行为，不照抄当前输出。低影响文案改动通常只需目标界面检查，不另建测试框架。
- JS 语法检查按文件逐个执行；类型/构建采用项目真实支持的最小范围。语法、构建和行为证据不能相互替代。项目强制检查始终保留。
- UI 改动在实际目标宿主检查本次流程，必要时截图；Electron 行为不能只用普通浏览器页替代。只有纯计算变化且没有显示影响时，不要求无关截图。
- 模拟服务可验证协议、状态和播放门禁，不能证明真实接口、真实音色或系统级交互成功。检查隔离数据、网络、端口和进程副作用，沿用项目约束。

没有选到测试时，检查是文档类变化、缺测试、映射缺失还是基线不足。不要把空结果当成功；用直接行为检查补证据，无法验证则报告缺口。Chisel 等分析器若已有可辅助选择，但不作唯一依据，也不因本技能自动安装它们。

## 4. 失败处理与停止

- 区分业务缺陷、过期测试和环境问题；不要为了消除失败恢复已退役功能、修改无关业务或放宽预期。
- 过期测试先对照当前需求和源码证明哪里过期，再修正必要夹具/预期。绑定旧交付哈希或旧结果的脚本只能证明对应快照，不用于否决正常新改动或复用旧“通过”。
- 修复后重跑失败项和受修复影响项。新证据发现影响扩大才增加检查，不能因一次失败重跑全部功能。
- 所选检查通过且影响边界有依据后立即停止；没有新改动、新失败或未解疑点，不重复测试、浏览全项目、生成额外报告或截图。
- 同一失败原因没有新证据时，不盲目重试；记录阻塞和最小下一步。不得把未完成项写成通过，也不以固定时间到期代替验收。

## 5. 交付证据

简短报告以下内容，不输出大段原始日志：

```text
范围：改了什么；关联到哪些行为。
验证：本次命令/操作 → 退出码、成功标记或断言结果；必要的证据路径。
跳过：无关功能及不受影响的依据，按类别概括。
未验证：具体缺口及原因；没有则写无。
```

结果必须来自当前版本本次执行。报告区分模拟与真实、自动与人工；不把语法通过说成全部功能正常，不承诺固定节省比例。该技能选择验证范围；与证明式验收技能同时使用时，证据对应所选范围，不自动扩大成整套回归；明确的项目强制检查与用户要求仍有效。
