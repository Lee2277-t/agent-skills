# 图标集重置 + 透明底切图

## 什么时候用

用户给一张（或几张）游戏素材表 / 图标集参考图，要求：

- 「结合目前风格重置」成统一的某种画风（水彩、手绘…）；
- 排成固定网格（4×4、5×3…）、**去掉文字标签与重复项**；
- **要透明底**，方便直接放进游戏。

不要用本技能处理单张插画或海报。

## 关键取舍：要透明底，就必须牺牲背景纸纹

生成模型（`hy-image-3.5-edit-wb` 实测）**只出 RGB、不出 alpha**。所谓「透明底」是自己后期抠的。

因此 prompt 里必须把两件事**分开写**：

| 部位 | 怎么要求 | 原因 |
|---|---|---|
| **物体本身** | 纸纹、颜料晕染、水渍边、沉淀颗粒、可见笔触 → 全部写在这里 | 画风质感必须留在对象上 |
| **背景** | **干净纯白平面，不要纸纹、不要斑点、不要水痕、不要阴影、不要网格线** | 背景越平，flood-fill 抠得越干净 |

> 若用户同时要「水彩纸本色底」和「透明底」，这是**互相冲突**的：纸纹底抠不干净（噪点会被当成内容）。
> 正确做法是**两版都给**：白底生成图 + 抠好的透明底图。若用户坚持要纸纹，就另出一张「透明图标贴到纸纹上」的合成图，而不是在抠图阶段硬保留纸纹。

## 一、生成：4×4 网格提示词骨架

```
严格保持与参考图完全相同的水彩手绘风格：颜料自然晕染、水渍边缘、颜料沉淀、
可见笔触、低对比度、柔和光线、暖色调为主。这种纸纹与笔触质感要体现在**每一个物体本身**上，
而不是体现在背景上。

画面结构：4×4 网格整齐排列 **十六个**互相独立的图标。每一格只放一个图标，
水平垂直居中，格子间距均匀，每个图标四周至少留 15% 空白，
绝不允许超出格子、绝不允许互相遮挡、绝不允许拥挤。

第一行四个：<逐格点名物件 + 特征 + 位置>
第二行四个：……
第三行四个：……
第四行四个：……

背景：干净平整的纯白色背景，背景上不要纸纹、不要斑点、不要水痕、不要阴影、
不要网格线、不要边框，只有图标本身。

绝对不要出现：<用户给的负面词，逐条写进正向 prompt>。
整张图为 1024×1024 的正方形。
```

要点：

- **画幅要方形**。16:9 里切 4×4，每格只有 320×180，图标会明显偏小、上下两行挤在一起。用户若没说，直接建议 1024×1024。
- **逐格点名**，不要只给一份名单。「第一行四个：A、B、C、D」这种带位置的写法，模型对「每格一个」的执行率高得多。
- **参考图里重复的元素要单独点掉**。例：源表里「木板」出现两次，模型会照样画两摞。写法：
  > 「图1 里木板重复出现了两次，重绘后**只保留一摞**；全图只有这一摞木板，不要出现第二摞。」
- **浅色物件也要点名**（牛奶瓶、棉布、白瓷碟）：不然模型容易画成一片白，抠图时会被当成背景吃掉。
- 工具的「负面提示词」没有独立入口，全部写进正向 prompt；但否定式描述对模型效力有限，**能正向描述的就正向描述**（「每格只放一个图标」优于「不要多画」）。

## 二、抠透明底：flood-fill，不是阈值

**不要**直接用「亮度阈值」判背景——`min(rgb) >= 某个值` 会把牛奶、棉布、白瓷碟这些浅色物件一起吃掉。

正确做法：**从画面四边向内 flood fill 纯白**，只有连通到边界、且够白的像素才是背景。

```python
from PIL import Image, ImageFilter
from collections import deque

im = Image.open(SRC).convert('RGB'); W, H = im.size; px = im.load()
WHITE_T = 250                     # 实测背景是 253–255，250 足够严
bg = bytearray(W * H); dq = deque()
def push(x, y):
    i = y * W + x
    if bg[i] or min(px[x, y]) < WHITE_T: return
    bg[i] = 1; dq.append((x, y))
for x in range(W): push(x, 0); push(x, H - 1)
for y in range(H): push(0, y); push(W - 1, y)
while dq:
    x, y = dq.popleft()
    if x > 0: push(x - 1, y)
    if x < W - 1: push(x + 1, y)
    if y > 0: push(x, y - 1)
    if y < H - 1: push(x, y + 1)
content = bytearray(1 if not bg[i] else 0 for i in range(W * H))
```

这样**物件内部被轮廓包住的白**（奶瓶里的牛奶、碟子、毛线）会保留为不透明，正确。

- **先检查有没有「被包住的白」**：逐格统计「非 content 且非 bg」且 ≥150px 的区域。数量为 0 才说明没有残留白块。实测这套图是 0（齿轮缝、椅背缝都通到格子外）。
- 若确实有大的被包白区（例如图标本身是两个零件靠在一起、中间夹出封闭空隙），再按「纯白 + 面积 + 是否落在更大色块 bbox 内」逐块判断剔除。2026-10-01 角落物品集实测：框架类物件（展示架/书架）框内透空是"背景看穿"要挖透明，阈值 `HOLE_T=1200px`（大于挖透明、小于当高光保留）一次过；水瓶/水缸水体是带色非纯白，不受影响。
- ⚠️ **挖孔洞不能一刀切**（2026-10-01 节庆UI横幅实测）：横幅/面板类物件的"中间留白布面/留白数字区"也是被包住的白，但它是**内容而非透空**，必须保留不透明（游戏里要在上面叠字）。同一项目里：展示架框内→挖，横幅中间→留。先看清这块白的语义再定阈值，别套用上一张表的 HOLE_T。

### 柔和边缘 + 去白边

```python
al = Image.new('L', (W, H)); ap = al.load()
for y in range(H):
    r = y * W
    for x in range(W): ap[x, y] = 255 if content[r + x] else 0
al = al.filter(ImageFilter.GaussianBlur(0.7))     # 0.7 够柔，再大就发虚
ap = al.load()
# 反预乘去白边：半透明像素的 RGB 被白底冲淡过，要还原
if a < 255:
    f = a / 255.0
    r = clamp((r - 255 * (1 - f)) / f)
```

不做反预乘的话，放到深色游戏界面里，每个图标边缘会有一圈**白色描边**。

## 三、剔除多余物件 + 格内居中

模型常「多加一个东西」（例：用户只要「葡萄酒瓶」，模型配了一只酒杯），违反「每格只放一个图标」。

**⚠️ 最大的坑：连通域分析必须做在「未模糊」的遮罩上。**
高斯模糊会把相邻但分离的两个物件（瓶子和酒杯，实测相距仅 10px）**粘成一个连通块**，
于是「只留最大块」删掉的其实是别的东西，整格切出来是破的。

```python
# ✅ content 是未模糊的 bytearray；❌ 不要用 blur 之后的 alpha
# 在目标格子范围内 8-邻域分连通块，只保留最大的那一块
comps.sort(key=len, reverse=True)
for pts in comps[1:]:
    for i, j in pts: content[(cy0 + j) * W + cx0 + i] = 0
```

**⚠️ 第二个坑：居中时「遮罩」和「颜色」必须一起平移。**
只改遮罩不动 RGB，位移后取到的是目的地原本的像素（酒杯那片白），瓶身中段会**变成白色**。

```python
# ✅ 先把整格造成 RGBA，再整块平移（颜色+透明一起走）
cell = out.crop((cx0, cy0, cx0 + CW, cy0 + CH))
nc = Image.new('RGBA', (CW, CH), (0, 0, 0, 0))
nc.paste(cell, (dx, dy))
out.paste(nc, (cx0, cy0))
```

`dx, dy = 格心 - 保留块 bbox 中心`。

## 四、批量拆单图标

按网格切格 → 在该格内取 `alpha > 0` 的 bbox → 加 12% padding 成正方形 → 存为独立 PNG。

```python
w, h = bx1 - bx0 + 1, by1 - by0 + 1
s = max(w, h); pad = round(s * 0.12); side = s + 2 * pad
icon = Image.new('RGBA', (side, side), (0, 0, 0, 0))
icon.paste(out.crop((x0 + bx0, y0 + by0, x0 + bx1 + 1, y0 + by1 + 1)),
           ((side - w) // 2, (side - h) // 2))
```

每个图标尺寸会不一样（这是对的，随物体大小走）。若要**统一像素尺寸**，改成把 bbox 贴进固定 `side` 的画布。

⚠️ **但"同物体多尺寸系列"（大/中/小帐篷等）绝不能逐个撑满画布**（2026-10-01 实测踩坑，用户一眼发现）：
拆单用统一缩放系数（如 `gs = 目标px / 最大bbox宽`），全部按同一系数缩放，保住 1.00/0.84/0.70 这类相对比例；
代价是透明边距随尺寸变化（如 18/25/32px）——"统一边距"与"保留大小差"在固定画布上不可兼得，优先保大小差。
若游戏里用引擎缩放控制大小，才可改回逐个撑满 + 统一边距。

## 五、验收（必须做）

1. **把透明图合成到中灰底（如 `(120,130,140)`）再看**。白底上看不出抠图问题，灰底上「没抠干净的白色残块」和「丢掉的浅色物件」一眼可见。
2. **单图标拼一张检查图**一次 Read 看完 16 个，比逐个读省得多。
3. 检查有没有白色描边（反预乘有没有生效）、有没有多余物件、有没有格子空掉。
4. 输出清单里 `print` 每个文件的尺寸和 mode，透明底必须是 `RGBA`。

### `.miora` 画布文件怎么读（踩过）

- `.miora` **不是 JSON，是二进制自定格式**，`utf-8` / `utf-16-le` 直接 `decode` 都会报错或读空。
- 正确读法：`open(p,'rb').read().decode('utf-8', errors='ignore')`，再正则抓条目引用：
  `r'(village-spring-rain_assets/[0-9a-zA-Z_\-\./]+\.(?:png|jpg|jpeg))'`，id 用 `r'wb-item:([0-9a-zA-Z_\-]+)'`。
- **删图前先校验引用**：把抓到的文件名逐个在 `village-spring-rain_assets\` 下查存在性，缺了画布会显示空白格。
- **`miora_write_canvas` 更新后落盘有滞后**，刚写完立刻读文件可能看不到新条目；要核实就隔一次再读。
- 带 **8 位十六进制前缀**的文件（`528cb518-xxx.png`）都是画布自动生成的引用副本，**永远别删**；自己产出的备份图（ `_v1` / `_v2` / `_xxx分析图.png` ）才可以删。

## 七、单图标补丁流程（2026-10-01 补充，比整表重出便宜得多）

整表 4×4 出图后通常只有 1~3 个格子有问题（文字、画错、空格、近似重复）。**不要整表重出**（构图会漂、好格子全丢、多花积分），
改成：单独生成出问题的那一个图标（1024×1024 白底、参考图用该表白底定稿）→ 抠图 → 贴回表格的指定格（白底表贴白色 RGB 格、透明底表贴 RGBA 格，先清格再贴）→ 覆盖对应单图标文件 → 重拼联络表。

## 八、新踩的坑（2026-10-01 实测，ImageGen 通道）

1. **PIL 的 `getbbox()` 对 RGBA 按"所有通道非零"计算**。画布初始化成 `(255,255,255,0)` 时 RGB 全图非零，bbox 永远是整图。
   取内容范围必须用 `rgba.getchannel('A').getbbox()`。
2. **孤立噪点会把 bbox 撑成整图**。flood-fill 之后背景里可能剩几个 <40px 的杂色小点（不连着任何物体），
   单图标流程也要先做连通域过滤（剔除 <40px 的块）再取 bbox，否则裁出来是一整张 255×255 的"空图"。
3. **图标会溢出 256px 格子边界**（上一行的图标脚下超出格线 ~20px）。按几何切格会把邻格的"脚"带进下一行图标。
   正确做法：全局连通域标记后**按质心归属格子**，切格时把不属于本格组件的像素清透明。整表重建时每个图标按自身 bbox 居中。
4. **并行多次 ImageGen 会文件名冲突**：输出文件名取自 prompt 前缀+秒级时间戳，同一秒内多个调用返回**同一个路径**，后写的覆盖先写的（实测丢了 2 张图）。
   要么串行出图，要么每出一张立刻改名。
5. **ImageGen 出图没有右下角水印**（对比拉伸 12 倍验证过白底干净），可跳过去水印步骤；但新通道第一次用还是要扫一遍确认。
6. 模型对"每格只放一个"仍会跑偏：会空一格、会把没要的物件补进空格、会把两种同类物件画成近似双胞胎。
   验收联络表时重点看：空格、未点名的多余物件、同类物件是否长得一样。
6. **发光物件（灯笼/星光）的光晕会被抠成不透明光雾**：flood-fill 会把光晕中 min(rgb)<250 的区域全保留，灰底上看是物体外一圈白黄光雾。两选一：接受它当游戏里的"发光"效果（灯笼实测效果不错）；或 prompt 里要求"光晕很淡、快速融入白色背景"让 flood fill 吃掉大部分光晕。
7. **碎小物件类图标（星屑=散落小星星）MIN_SZ 要降到 ~12px**：默认 <40px 剔噪会把散落的碎星当噪点删光。同时注意这类物件连通域很多（散落），每格要"保留全部达标块"而不是"只留最大块"。
8. **空格要逐格点名**（2026-10-01 实测有效）：部分留白的网格（如 3×3 只放 5 个图标），
   必须按行写明哪些格"完全留白空白，不画任何东西"（如"第三行三格：全部完全留白空白"）。
   这样写模型会把空格留成纯白，不会自作主张补物件；只写"共 X 个图标"不点名空格则容易跑偏。
9. **超时或中途失败的单帧，必须先 check 目录再复用**（2026-10-01 实测）：
    `ImageGen` 调用若返回 429/error，**可能已经偷偷落盘了一部分**（flood fill 到一半就断）。
    收尾前用 `ls -t <output_dir> | head -5` 看最新文件的**时间戳 + 尺寸**，确认不是半张烂图再 copy；宁可重跑一次，别把未完成的图当成品。
    同理，帧文件别用「同一名字覆盖」的方式管理，容易把上一版好图盖掉还找不回来。
10. **一套精灵/动作帧必须有统一命名表**（2026-10-01 实测）：
    别让同一套帧散落成 `XXX_动作_白底.png` 和 `XXX_动作_透明底.png` 两套散装文件，
    统一用 `角色_帧名_{白底,透明底,对齐底}.png`（如 `miner_待机_透明底.png`）便于引擎按前缀批量加载。
    另外同角色的 variant（v1/v2、同一个动作的两个版本）务必先 `shutil.copy` 到 `_旧版<角色>/` **再覆盖**，
    事后无法判断"用户到底看过哪一版"。

### 角色帧 vs 图标级要求的差别（同一套 1024 白底同样适用）

| 项目 | 图标素材 | 角色/动作帧 |
|---|---|---|
| 是否统一撑满画布 | 需要（同级图标统一 92px 内容） | **不能**逐个撑满 |
| 垂直基准 | 格内居中 | **必须脚底对齐同一条基准线**（见下） |
| 常见脏东西 | 多余物件 | 脚下一圈灰色椭圆投影，抠图后会变成独立灰块 |
| 特殊处理 | – | 坐姿帧的"底"是臀部不是脚，用整体 bbox 底对齐即可 |

## 九、角色动作帧：脚底基准线对齐（2026-10-01 矿工五帧实测）

**"保持角色脚底在同一水平线上"这种要求，靠 prompt 只能做到 80%，最后一步必须脚本对齐**——
模型每次副主体/道具高度不同（举镐 > 扛镐 > 站着），直接拼一起会看到角色"上下跳动"。

```python
BASELINE_Y = 1000                     # 1024 画布上的统一脚底 y
def bottom_align(im, canvas=1024, baseline=BASELINE_Y):
    crop = im.crop(im.getchannel('A').getbbox())   # ⚠️ 对 RGBA 必须用 A 通道取 bbox
    out = Image.new('RGBA', (canvas, canvas), (0, 0, 0, 0))
    out.paste(crop, ((canvas - crop.width) // 2, baseline - crop.height))
    return out
```

- **不要按每个动作各自的 bbox 高度去归一化**。例如"举镐"帧因为道具高，撑满画布后人物躯体会比其他帧小一圈，看着像换了个人。
- 缩放必须是**同一套帧共用一把尺**：先按待机帧定好缩放系数 `gs`，其余帧套同一个 `gs`，再做脚底对齐。
- 灰底检查图里要**把基准线画出来**（`draw.line` 一条深灰横线横穿全部帧），"脚底齐线"才能一眼看出来，而不是靠感觉。
- 坐姿帧（喝水、擦汗）的"底"其实是臀部不是脚，按整体 bbox 底对齐即可，视觉上会自然贴住地面基准线。

### 整套帧要以「同一个新的待机帧」当 image1（实测重要）

同一角色的整套动作帧**必须全部用同一个新的待机帧当 `image1`**，不要各自拿自己的老图当参考——
否则每帧都只在自己基础上小改，几帧叠加下来会整体漂移（脸越来越大、衣服越来越花）。

实测流程：先重出待机帧（承载"新表情 + 新配色 + 新质感"）→ 其余帧**全部以这个新待机帧为参考**按姿态重绘 → 得到风格完全统一的一套。


## 十、flood-fill 的补充：水彩图标边缘那圈「淡雾」必须用严阈值（2026-10-04 实测）

### 现象
技能第二节推荐 flood-fill（WHITE_T=250）判背景。但在**灰蓝色调工业图标**这类图上，
模型会在图标周围画出一圈极淡的水彩雾/纸痕（亮度 235–250），
flood-fill 认为它「不是纯白」→ 当成物体保留 → 灰底检查图上每个图标外糊一圈白雾。

实测外环亮度分位（膨胀 8px 后取环）：

| 图标集 | 外环 5% | 25% | 50% |
|---|---|---|---|
| 传送带 | 242 | 247 | 250 |
| 管道 | 243 | 247 | 249 |
| UI 按钮 | 246 | 249 | 251 |

50% 分位都到 249–251，靠 `min(rgb) < 250` 根本切不掉。

### 解法：自动背景亮度 − margin，再配形态学

```python
bg_lv = np.percentile(mn_channel, 92)     # 背景亮度，实测都是 253
th    = bg_lv - margin                    # 图标 margin=15~20，角色 margin=20
m     = mn_channel < th
lab,n = ndimage.label(m, ...)
# 只留面积 >= min_area 的前若干大连通域（顺带干掉散点噪）
keep  = ndimage.binary_closing(keep, iterations=2)   # 补内部孔
if erode_r: keep = ndimage.binary_erosion(keep, iterations=erode_r)  # 图标：削掉残雾
```

- **图标**：`margin=15, erode_r=2`（腐蚀 2px 把残雾削干净，图标形状粗壮不怕削）。
- **角色 / 带细长道具（锄柄、伞骨）**：`margin=20, erode_r=0`，**绝不能腐蚀**，
  否则锄柄直接被吃断。靠严阈值去雾，靠 `binary_closing(3)` 补内部孔。

### 验收指标（看不到图时也能判）
统计 `alpha>200 且 min(rgb)>240` 的像素占比 =「近白不透明」残留。
抠干净的图标该值 **< 0.5%**（实测 0.01%–0.40%）。
v1（flood-fill, WHITE_T=250）在灰底上是明显脏的，改用严阈值后达标。

## 十一、别硬编码取格坐标：先扫九宫格占用率（2026-10-04 实测）

模型会把物件放错格（管道集里「阀门」跑到了第三行正中）。
**不要**在脚本里写死 keep 列表，先扫一遍确认每格到底有没有东西：

```python
m = (mn < np.percentile(mn, 92) - 15)
for r in range(3):
    for c in range(3):
        sub = m[r*H//3:(r+1)*H//3, c*W//3:(c+1)*W//3]
        print(r+1, c+1, '%.2f%%' % (100*sub.mean()))
```

空格占比 <0.2%，有物件的格子通常 15%–48%。扫完再填 keep 列表，一次就对。

修格位本身：**用这张表自己的白底定稿当 image1 重出**，并在 prompt 里逐格点名
「最左上格 / 上边中间格 / 最右上格 / 左边中间格 / 正中间格 / 右边中间格」，
比「第一行三个：A、B、C」约束力强（模型认「上边中间格」这种带方位的说法）。

## 十二、看不到图时怎么验收（2026-10-04）

部分会话里图片读取会被过滤（`Content filtered`），**不要假装自己看过图**。
改用可量化指标，并在回复里明确告诉用户「我没法肉眼确认，请你过一眼」：

| 要验的东西 | 可量化替代 |
|---|---|
| 有没有水印 | `whiteness = 0.5*luminance + 0.5*blue`，右下角 vs 正上方，差 **<-1 或 >+3** 才可疑 |
| 抠图干不干净 | 「近白不透明」占比 < 0.5% |
| 构图有没有裁切 | 逐行/逐列密度看四边留白；**单列密度 <25 的是噪点不是主体** |
| 头身比 | alpha 逐行连续段：帽/头/肩/腰的宽度剖面，头高 = 帽顶到肩线 |
| 网格排布 | 九宫格占用率扫描（见第十一节） |

注意：主体验收别用「cols>8」这种松阈值，会把边缘 12px 的杂色点当成主体，
误判成「左边被裁切了」。用 **`>25`** 或直接看连续段。

## 十三、角色合成进背景的默认做法（2026-10-04 农夫实测）

- 角色透明底**裁到内容 bbox**再存（不要留 1024 白边），引擎好摆放。
- 合成时给一坨极淡接地阴影，否则人物会「浮」在地面上：
  椭圆 `(70,66,58,46)` → `GaussianBlur(6)` → 贴到脚底略上方，透明度 46/255。
- **一次出三个尺度**（如 160 / 220 / 300px 高）让用户挑，比猜一个尺寸来回改省事。
- 脚底 y 放画面 78%–85% 高度处（592 高的背景取 y≈470–500），符合中景站立。
- 用户说「写实 4-5头身」其实自相矛盾（真人 7-8头身）。实测这类 prompt 出来约
  **帽顶到肩线为一个头单位时 ≈5.8 头身，按颅骨算 ≈9 头身**。
  要更矮更敦实，就在 prompt 里加「躯干加长、腿缩短、肩更宽」这类正向描述。


## 十四、模型改不动的几何要求，直接后期做（2026-10-04 农夫优化实测）

用户提了六项优化，模型做到四项（降细节、提暗部、降对比、统一暖调），
**做不到两项纯几何/后期能算的**：

| 要求 | 模型表现 | 正确做法 |
|---|---|---|
| 「人物占画面 1/3~1/2」 | 完全没缩，仍 94.5% | **后期缩放居中**，出 40%/45% 两版，零积分 |
| 「脚下加 20%–30% 深棕椭圆阴影」 | 没画出局部暗块，只罩了层整幅暖雾 | **程序画椭圆 + 高斯模糊** |

> 判断口诀：**能用「缩放 / 平移 / 画个图形 / 调曲线」实现的，都别写进 prompt 让模型猜。**
> 模型只对「质感、色调、细节密度、笔触」这类它擅长的东西可靠。

### 整幅色偏（背景不白了）怎么救
模型加"统一暖黄"时常把整幅一起罩上，背景从 255 掉到 249，与「白色背景」冲突。

```python
mn = a.min(axis=2)
bgmask = mn > 245                                   # 背景像素
bg = np.array([np.median(a[:,:,c][bgmask]) for c in range(3)])
a2 = np.clip(a * (255.0 / bg)[None, None, :], 0, 255)   # 逐通道缩放还原纯白
```

⚠️ **先确认这层雾是中性还是暖色**：打印 `bg` 的 R−B。
实测农夫优化版 `bg=(251,250,251)`，R−B=0 是**中性灰雾**，去掉它不会削掉人物的暖调；
若 bg 本身偏暖（R−B>5），说明暖调是靠背景撑的，这时候要和用户确认要不要保留。

### 落地阴影的参数（手把手）
```python
sh_w = int(cw * 0.82); sh_h = max(6, int(ch * 0.05))
sh = Image.new("RGBA", (sh_w, sh_h), (0,0,0,0))
ImageDraw.Draw(sh).ellipse([0,0,sh_w-1,sh_h-1], fill=(92,72,52, 84))  # 深棕
sh = sh.filter(ImageFilter.GaussianBlur(max(2.0, sh_h*0.34)))
cv.alpha_composite(sh, (pad_x + (cw-sh_w)//2, ch - sh_h//2))   # ① 先铺阴影
cv.paste(body, (pad_x, 0), body)                                # ② 再贴人物
```
- **填充 alpha 必须填目标值的 ~1.3 倍**：填 64（25%）经高斯模糊后实测只剩 16%–19%；
  填 84（33%）模糊后中位 23%、75 分位 27%、峰值 33%，正好落在 20%–30%。
- **顺序不能反**：先铺阴影再贴人物，否则半透明阴影会盖在靴子上把靴子弄脏。
- 阴影专属像素怎么量（排除人物本体，否则量到靴子）：
  ```python
  body_only = np.zeros((cv.height, cv.width), bool)
  body_only[0:ch, pad_x:pad_x+cw] = (np.asarray(body)[:,:,3] > 8)
  sh_only = (cva[:,:,3] > 0) & (~body_only)
  np.percentile(cva[:,:,3][sh_only], [50,75,90]) / 255.0
  ```

## 十五、UI 底板 / 九宫格素材（2026-10-04 木质按钮底板 512×192 实测）

### 让模型出"很扁很宽"的比例：只给具象换算，别给抽象比例

| 写法 | 出图实测 |
|---|---|
| ❌ 「宽高比约为 8 比 3」 | 内容宽高比 **1.51**（目标 2.67，差得离谱） |
| ✅ 「宽度约为高度的 **2.7 倍**（举例：宽 900 → 高约 340）」+「只占画面高度约三分之一，上下各留约三分之一纯白」 | 1024 画布内内容 949×343，宽高比 **2.77** ✓ |

> **模型算不出比例，但能换算具体数字。** 永远补一句「举例：宽 X → 高约 Y」，
> 再加一句「占画面高度/宽度几成」，让它知道要在画布里留白。

### 裁剪必须留余量，否则边缘会被 LANCZOS 切平（新坑）

按 `alpha>16` 的 bbox **紧裁**再缩放，会让输出端第一行/最后一行出现
**最宽 87–139px、alpha 最高 123 的硬边**——原本应有的柔和晕边没了，变成一条被刀切过的直线。
根因：紧裁后 bbox 外全是透明，重采样 kernel 在画布边界振铃，把内部高 alpha 溢到最外圈。

```python
ys, xs = np.where(alpha > 16)
c0, r0 = max(0, xs.min()-PAD), max(0, ys.min()-PAD)     # PAD=12（源图像素）
c1, r1 = min(W, xs.max()+1+PAD), min(H, ys.max()+1+PAD)
plate = sp.crop((c0, r0, c1, r1)).resize((OUTW, OUTH), Image.LANCZOS)

# 缩放后再对外沿做 2px 线性羽化，彻底杜绝硬边
arr = np.asarray(plate.split()[3], dtype=np.float64)
for i in range(2):
    f_ = (i+1)/3.0
    arr[i,:]*=f_; arr[-1-i,:]*=f_; arr[:,i]*=f_; arr[:,-1-i]*=f_
plate.putalpha(Image.fromarray(arr.astype(np.uint8), "L"))
```

**验收硬指标**：`alpha[0].max()`、`alpha[-1].max()`、`alpha[:,0].max()`、`alpha[:,-1].max()`
必须全部为 **0**。出现过 123 → 必返工。

> ⚠️ 别用 `Image.getbbox()` 取裁剪框：它会把 alpha=1 的极淡晕边算进范围，
> 缩放后板身铺不满画布（实测左右各差 4–5px）。要用 **`alpha>16` 的实心掩码**求 bbox。

### 九宫格（Godot NinePatchRect）验收

用户给了 patch 边距后，必须验证**圆角真的被包在这四条边距里**：

```python
rows = (alpha>16).sum(axis=1); cols = (alpha>16).sum(axis=0)
# 竖向圆角：从上往下数，行宽首次达到 90% 最大宽所需的行数
i90 = next(i for i in range(len(rows)) if rows[ys[0]+i] >= 0.9*rows.max())
assert i90 < PATCH_T          # 同理横向 j90 < PATCH_L
# 四角 patch 内必须有 alpha 渐变（说明圆角落在这块区域里）
alp[0:PATCH_T, 0:PATCH_L].std()      # >5 才算包住，实测 ~120
```

实测（512×192，边距 80/40）：竖向圆角 4px < 40 ✓、横向 14px < 80 ✓、
中部可拉伸区 **352×112**。

### 底板类素材的专属指标

| 检查 | 算法 | 目标 |
|---|---|---|
| 中间比边缘浅（方便放文字） | 中部矩形 vs 四条边带 的平均亮度 | 中 > 边（实测 194.6 vs 153.6） |
| 暖棕木色 | 板身 RGB 均值 | R>G>B ✓ |
| 低饱和 | `mean((max-min)/max)` | <80（实测 29.0） |
| 抠图干净 | `alpha>200 且 min(rgb)>240` 占比 | <0.5%（实测 0.015%） |
