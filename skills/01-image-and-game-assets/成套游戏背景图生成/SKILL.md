# 成套游戏背景图变体生成

适用场景：一次要做一整套**构图完全相同、只有季节/天气/时段不同**的背景图。这类任务的难点从来不是"画得好看"，而是：
1. 每张的**布局必须一致**（差一点整套就废）；
2. **指定元素不能被漏掉**（奶牛、葡萄园、溪流宽度…）；
3. 模型每张都会在角落**压水印**，必须删。

## 0. 开工前先建立"矩阵"和"对应关系"

先和用户把矩阵定清楚，例如：季节 × 天气(晴/雨) × 时段(昼/夜)。
然后定义**参考图对应表**——做某一张时，用"同季节切面的上一层"里**同天气同时段**那张当基准：

| 要做的图 | 参考图 |
|---|---|
| 秋天晴天白天 | 夏天晴天白天 |
| 秋天雨天白天 | 夏天雨天白天 |
| 秋天晴天黑夜 | 夏天晴天黑夜 |
| 秋天雨天黑夜 | 夏天雨天黑夜 |

**为什么必须这样配**：同天气同时段的两张，光照逻辑能直接迁移，且不会把雨丝/乌云/夜色/灯光串进不该有的画面。混着喂（比如拿雨夜图去生成晴天图）几乎必串味。

**矩阵不一定是方形**：天气维度可能多于 2 种。实测冬天是 **晴 / 雪 / 雨 三种 × 昼夜 = 6 张**（春/夏/秋 各 4 张），整套图因此是 4+4+4+6 = 18 张。开工前先把天气种类数确认清楚，别默认"晴雨两类"。

**用户给的时段描述可能重复或缺漏**（实测：阶段三春天贴了一遍"黄昏收市"，两端一字不差，
把"夜晚"那段覆盖掉了）。这种时候**不要停下来追问**，按系列既定矩阵补齐缺的那一格
（夜晚就沿用同系列既有的夜景逻辑：星月/月色铺地/收摊盖布/暖窗+油灯），
然后在交付说明里明确点出「你的描述里 X 重复了、Y 缺了，我按惯例补了，不需要就删」并给出退路。
追问一轮的代价远大于补一格 + 说明。

**雨天永远从"同季晴天"派生**（见 §2.6），所以一个季节里有雨天时，执行顺序是：
```
第 1 批：晴天 / 雪天 / 晴夜 / 雪夜   ← 直接从上一季对应图派生
第 2 批：雨天 / 雨夜                ← 用第 1 批刚出、已清完水印的晴天图派生
```
两批之间**必须先把第 1 批的水印清掉**，因为第 2 批要拿它们当参考图。

**参考图优先用已经定稿、已清过水印的成品**，不要用最初的上传方图：
- 已是目标画幅 → 省掉一次布局重排，一致性更高；
- 已无水印 → 不会让模型把角落字样一起仿出来（等于省掉一次去水印）。

**正交维度不止季节/天气/时段，还有「场景阶段」。** 例：同一张地图先出「阶段一=空场（集市未搭建）」，再出阶段二（搭建中）、阶段三（开集）。阶段是**第一层维度**，其下再套季节×天气×时段。做阶段 N 时，参考图只能取**阶段 N 已定稿的那张**，绝不能跨阶段拿（拿阶段三开集图去派生阶段一空场，帐篷摊位会一路串回来）。

**同一目录可能并存多条场景完全不同的线**，文件名规律却一样（都叫「季节+天气+时段.png」）。开工前先把目录列一遍，确认这套的**场景内容**是不是接手人以为的那个——本项目就踩过：目录里同时有「农场全景（玉米地/奶牛/猪羊/隧道铁轨）」和「乡村集市空场（土路/葡萄园/酒庄/远山）」两套，混用参考图等于白做。判据是**打开图看内容**，不能只看文件名。

**治本办法是目录分层 + 前缀命名**，别让多套图平铺在同一层：
```
<project-root>\game-assets\背景\            ← 上级目录，只放各条线的子文件夹
  ├ 乡村集市\            ← 本线，文件统一带 `阶段一_` / `阶段二_` 前缀
  ├ 工业区\
  └ 农场全景\（或散着的无前缀旧图）
```
本项目实测：农场线那 16 张是**无前缀**的 `春天晴天白天.png`，集市线是 `阶段一_春天_晴天_白天.png`，
两者只差一个前缀。**取参考图前先确认前缀**，拿错线的图当基准 = 整批返工。
整理完记得把交接文档里的旧路径批量替换掉，并在文档开头加一条「路径已变更」的醒目说明。

## 1. 提示词骨架（按段落写，不要一口气堆）

```
【基准与不变量】参考图（XXX）是唯一基准：严格保持与参考图完全相同的布局、
地形、建筑位置、道路走向、分区、围栏位置、树木分布。参考图是横版 W×H，
本次输出 W×H，保持同一套布局与构图，相对方位完全不变，不要拉伸、不要裁掉
地物、不要偏移构图、不要改变建筑位置。四周保留<材质边>。

【只改变什么】只把<维度>从 A 改成 B，其余不变：

【天空】
【地面/道路】
【指定必须保留的重点对象】← 单独一段，最详细的措辞放这里
【动物】
【色调】
【画风保持不变】…尺寸 W×H。
【禁止项】画面中不要出现：…
```

**尺寸写在提示词正文里**比只靠 size 参数可靠（本系列实测模型对 960×600 固定返回 960×592，但正文写了至少不会被理解成别的比例）。

## 3. 批量执行

- **miora 可用时**：多张可以并行发（一次消息里多个工具调用），不用串行等。
- **只能用 ImageGen 时**：**必须串行**，一次一个（见 §2.9）。
- 去水印 + 量基线 + 出验收图**合并成一个 Python 循环脚本**，一次跑完整批。不要每张一个脚本。
- 循环里**必须把每张的基线 min/max 打印出来**。若某张打印出一排完全相同的值（如全是 591、min==max），那不是"基线很平"，而是**判纸阈值对新季节失效了**（雪景纸边偏暖偏暗，`mn>185` 判据失效）——换色相判据 `(r-b)>=22 and r>175` 重测。详见技能 `ai-image-watermark-removal`。
- 流程细节见技能 `ai-image-watermark-removal`（同结构平移贴片法）。

## 4. 验收清单（必做，逐张过）

1. **全图看一眼**：构图/布局是否和参考图一致，有没有整体跑偏。
2. **放大"重点对象区"**（裁一块放大 1.8–2 倍）：指定的动物/作物/建筑在不在、数量对不对。**这是最容易漏的一步**。
   - 批量验收时**拼图**：把 N 张图的同一区域裁下来拼成一张大图（2 列 × 多行 + ASCII 标签），一次看完，比逐张读省很多。
   - 重点区域一般两个：**动物区**（奶牛/羊/猪在不在、围栏内有没有水）和**葡萄园/高风险地物区**（有没有变色、消失、被冲毁）。
3. **放大右下角**看水印是否清干净。
4. **核对尺寸**是否与整套一致（本系列 960×592）。
5. 逐条对照用户的清单式要求，**没达标的如实说，不要替模型美化**。

## 5. 交付与留档

- 成品复制到用户指定目录，**命名与既有文件同规律**（如 `季节+天气+时段.png`）。
- 重做的版本：旧版改名带 `_v1` / `_v2` 后缀留档，不要直接删。
- 画布/文档**正在引用的图片文件不能删**（带 8 位十六进制前缀的副本尤其不能删）。
- 交付时给**完整路径**，并附一句"尺寸是 W×H，与其余 N 张一致"。

## 环境备忘

- 纯 PIL 足够，不需要 numpy/cv2（几十×几十像素的区域，纯 Python 循环够快）。
- Windows git bash 里跑多行脚本用 `<< 'PY' ... PY` heredoc，不要塞进 `python -c "..."`。
- 这台机器 bash 的 `rm` 是坏的（exit 127），删文件用 Python `os.remove()`。
