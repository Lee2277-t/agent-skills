## 2. 措辞规则（本流程最容易翻车的地方）

### 2.1 否定式描述基本无效
「不要规律雨丝 / 不要斜线纹理」这种写法模型会忽略、有时反而**强化**该特征。

→ 雨丝/云/纹理这类要改**正向描述**：
> 「雨丝长短不一、粗细不同、间距随机不均，有的地方成片密集、有的地方稀疏零散，局部连成朦胧雨雾，像手绘时笔尖点触和拖扫出来的自然痕迹」

### 2.2 「保留 X」≠ 会画出 X
模型对「保留 X」的理解是"照着参考图来"。**如果参考图里根本没有 X，它就直接省略。**

→ 先**核对参考图里到底有没有 X**（放大裁切看）。没有时，措辞必须换成：
> 「必须画**一头**黑白相间的奶牛——白色身体带黑色斑块，四条腿站立，体型清楚可辨，头朝侧面，**这是本张图必须出现的关键动物，绝对不能被省略、不能被画成别的动物**」

实测：同为晴天参考图（本身无奶牛），写「保留奶牛」→ 漏；换成上面这套措辞 → 到位。

### 2.3 季节色会污染指定区域
写「金黄小麦 / 金黄成熟作物」会把葡萄园、草地一起染黄。
→ 需要保持特定颜色的对象要**单独锚定**：
> 「葡萄园结构完整无损，叶片转黄/保持绿色，**紫黑色的葡萄串**饱满悬挂，**木质支柱清晰可见**，不要变成麦田或金黄条垄」

### 2.4 亮度类要求要写两遍
夜景/雨夜图容易出成一片死黑。写：
> 「整体亮度适中、层次清楚，**绝对不要漆黑一团、不要过暗**，<具体地物>的轮廓都清晰可见」

### 2.5 别让水跑进围栏/农田
只写"地面湿润、土路有水洼"，模型会把**围栏内、猪圈里也灌满水**，羊直接站在池塘里。降雨/湿润类需求必须**把水域范围钉死**：
> 「**围栏内是湿润的草地**，草地上只有湿意、草色变深和散落的水珠与落叶，**绝对不要出现水面、池塘、水洼或任何积水，羊和猪都站在湿润的草地上，不要站在水里**。水洼只出现在土路上。」

同理，河流/溪流要写「**保持参考图原有的窄宽度**，不要变宽、不要变成宽阔河流，水流平缓，不淹没农田、不淹没道路」。

### 2.6 改天气时，从"同季的晴天图"派生
要给一个季节加雨，**参考图选该季节的晴天版**，而不是上一版的雨天图。原因：晴天版的围栏内是干草地，派生出来的雨天版才不会继承"池塘"；从上版雨天图派生只会把积水一路传下去。

链条示例（重置春天时）：
```
春天晴天 ← 夏天晴天        （换季，靠晴天图最干净）
春天雨天 ← 新生成的春天晴天  （加雨，顺手甩掉旧积水）
```

### 2.7 雪覆盖类要求要写"覆盖成什么"，不能只写"被雪覆盖"
写「农田和草地被雪覆盖」，模型会**保留田里原有的作物（金黄麦秆、深绿玉米秆、穗子），只给它们撒一层雪**——出来是"覆雪的作物田"，不是雪野。这一条实测在晴天版最明显（冬天晴天白天/黑夜的农田里金黄作物仍在）。

→ 要雪野就明确写"**覆盖成什么**"，并否掉残留物：
> 「农田里**没有作物、没有秸秆、没有穗子**，只有平整的雪面，雪面下**隐约透出田垄的线条**和暗褐色的土壤（只透出线条，不要露出作物）」

### 2.8 换季要清掉参考图残留的季节色
从秋/夏图派生的夜景图，模型有时会把参考图的**季节色残留在枝干上**——实测冬天夜景三张的葡萄架上留了少量红色斑点（秋季红叶的余味），放大才看见。

→ 换季时除了写"枝干光秃"，还要**把残留色的名字点掉**：
> 「枝干是**褐色木质**，**不要有红色、橙色、黄色的叶片或果实**，藤架上**绝对不要出现葡萄串**」

同理，春天"嫩绿新叶"要写「**绝对不要出现紫黑色的成熟葡萄串**」，夏天"深绿"要写「**不要变黄**」——即：**季节色是双向的，既要写出你要的色，也要写出你刚改掉的那个色。**

### 2.10 在雪景上加雨/在晴天加雪，都要写「原来的东西变成了什么」

参考图是雪景、目标却是**雨天**时，只写「下雨、地面湿润」会出来**「雪地上在下雨」**这种自相矛盾的画面。
必须写清楚雪被雨**转化成了什么**：

> 「冬天的薄雪**被雨水打湿、部分融化成湿雪和泥泞**：草地是化开的湿雪与**露出来的湿草**，
> **不再是纯白的雪面**；土路湿滑泥泞，土路的轮廓清晰可见，路面上出现几处水洼……」

反过来（晴/雪天上加雪）也一样：写「雪花」之外还要写**地面是「被雪覆盖成什么」**（同 §2.7）。

雨丝的措辞与雪花的措辞是同一套路：**用「随机、疏密不均、像笔尖点触和拖扫出来的自然痕迹」正向描述**，
不要写「不要规律斜线」——否定式无效（§2.1）。

### 2.11 加昼夜维度：夜景不是"把白天调暗"，是换一套光

夜景只有两种失败态：**一片死黑**，或者**白天图盖了层蓝滤镜**。六个要点：

**① 地面段必须写「只是蒙上夜色，形状走向不变」**
> 「地面笼罩在深蓝的夜色里：<某元素>从<白天的颜色>变成<被夜色压暗的颜色>……
> **地面和物体的整体形状、走向与参考图完全一致，只是全部蒙上一层夜色。**」

不写这句，模型会顺手把场景重画一遍（树挪位置、土路改道）。

**② 夜空要有正向的随机细节**（同 §2.1，否定式无效）
> 「深蓝色的夜空，夜色浓郁但不是纯黑；星星**大小不一、疏密随机不均**，像笔尖点出的白色小点，
> **绝对不是网格状或排队整齐的图案**；一轮纤细的弯月，柔和的淡黄色 + 周围一圈很淡的柔光。」

**③ 给画面留一个「唯一的暖色锚点」，否则夜景会平**
> 「窗户透出暖黄色灯光，**窗格清晰**；暖光**在周围地面上投下一小片柔和的暖色光晕**
> ——**这是本张图必须出现的关键细节，绝对不能被省略**。」

借 §2.2 的「必须出现」措辞，否则窗光经常被直接省掉（参考图白天版本来就没灯）。

**④ 亮度兜底照 §2.4 写两遍，并补夜景特有的失败态**
> 「亮度适中、层次清楚，**绝对不要漆黑一团、不要全黑、不要过暗**，
> 葡萄园/建筑/土路/路标的轮廓和走向都清晰可辨；**同时不要出现大片纯黑**（保住水彩低对比度）。」

**⑤ 雨夜不要星星和月亮**——这是物理矛盾，不写清楚模型会给你"月亮+雨"。
> 「低垂的厚实雨云把星星和月亮**完全遮住**，天空里看不到星星也看不到月亮，
> 只有云层厚薄形成的深浅层次。」

同时雨丝要改成「**淡灰白色的细线**」（深色背景上），并让窗光在「**湿地面和水洼上留暖色倒影**」——雨夜的亮点就在这里。

**⑥ 雪夜**：留几层薄云，**云隙间露出星月**（月亮透云显得柔和朦胧）；
薄雪在夜色月光下呈「**冷调的蓝白色**」，雪面下隐约透出土路走向。

**参考图仍然取同组合的白天版**（春晴夜 ← 春晴昼），不要拿别的夜晚版派生——白天版最干净，
季节/天气属性不会串，也不会把另一段时段的光逻辑带进来。

**天气 × 时段 两层维度同时存在时，先铺完天气、再在天气内部铺时段**（2026-10-01 春天雨天实测）：

```
第 1 步：晴天白天 → 晴天清晨 / 晴天黄昏 / 晴天夜晚      （时段在晴天里铺完）
第 2 步：晴天白天 → 雨天白天                            （加天气，同 §2.6）
第 3 步：雨天白天 → 雨天清晨 / 雨天黄昏 / 雨天夜晚      （时段在雨天里铺）
```

**第 3 步的参考图取「雨天白天」，不要取「晴天清晨/黄昏/夜晚」各加一次雨。**
虽然 §2.6 说"加雨从晴天派生"，但那是**首次加雨**的规则；同一天气内铺时段时，
取本天气的白天版才能让 4 张雨图的**雨丝密度、水洼位置、盖布方式**完全一致——
否则四张各加一次雨，雨的画法会各不相同，成套感直接散掉。
（清晨/黄昏/夜晚三张都从同一张雨天白天派生，也顺带满足「不要从黄昏派生夜晚」。）

### 2.12 交付前清理：草稿移入回收目录，不要硬删

用户说「只保留最终形态，草稿删掉」时，**不要真的 `os.remove()`**，而是移到同级回收目录：

```python
REC = r"<project-root>\game-assets\_旧草稿_YYYYMMDD"          # 与被清理目录同级，不在其内部
shutil.move(src, os.path.join(REC, subdir, os.path.basename(src)))
```

理由：用户看到的是"目录干净了"，但任何一步判断失误都能恢复；同时汇报里说明回收目录的完整路径，
让用户自己决定是否彻底删除。要回收的通常有：**中间层级的派生图**（本例 4 张纯季节版，被 18 张完全覆盖）、
**旧预览拼图**、以及**这些图的 1536 原始留档**。

保留：最终矩阵成品 + 总览索引图 + **系列基准图**（点亮版/空场版这种"源头形态"不要删，以后还要拿它派生）。

### 2.13 进入「阶段二/三」：新增参考图里完全没有的对象

阶段推进（空场 → 搭建中/小摊 → 开集）时，**新阶段的核心对象在参考图里根本不存在**，
所以绝对不能用「保留 X」的写法（同 §2.2，模型会直接省略 = 等于退回上一阶段）。

措辞要点（2026-10-01 阶段二实测）：

- 单开一段写「【必须在参考图基础上新增的内容】参考图里原本没有 X，这次必须新增：……」，
  再补 §2.2 的「**这是本张图必须出现的关键对象，绝对不能被省略、绝对不能被画成别的建筑**」。
- **同时把"不该长的东西"点掉**：写摊位只写"木架 + 一块粗布"会不够，模型会顺手给它加棚顶和招牌
  （一步跨到下一阶段）。必须写「**没有帐篷顶、没有遮阳篷、没有围布墙、没有招牌、没有任何文字、没有旗帜、没有彩旗、没有灯笼**」。
- 参考图选取：**本阶段第一张**可以（也只有它）从上一阶段派生；**之后一律只用本阶段已定稿的图**，
  否则上一阶段的空场/下一阶段的拥挤会一路串回来（同 §0「不能跨阶段拿参考图」）。

### 2.13b ⚠️ 阶段升级时负面词会**整体反向**，必须重写，不能沿用上一阶段

上一阶段拼命压制的"不该长的东西"，到了下一阶段往往**就是用户点名要的东西**。
沿用旧负面词会和同一张图里的"必须新增"直接打架 —— 模型收到互相矛盾的两组指令，
表现是"要的东西时有时无、不要的东西时隐时现"，而且极其难调。

2026-10-01 阶段二 → 阶段三（乡村集市）实测对照：

| 元素 | 阶段二（严禁） | 阶段三（要求） |
|---|---|---|
| 摊位 | 1–2 个 | **3–4 个，排成一排，之间有间距** |
| 帐篷 | 绝对禁止 | **一两顶小型条纹帐篷** |
| 布告栏 | 绝对禁止 | **木柱撑木牌板 + 贴几张空白泛黄纸** |
| 小舞台 | 绝对禁止 | **右侧小型木台，空无一人** |
| 旗帜 | 绝对禁止 | **两三面朴素小旗** |
| 篝火 | 绝对禁止 | **允许，但只限"很小的石圈 + 极微弱火苗"** |

**做法：每进一个阶段，先把上一阶段的负面词清单整条过一遍，逐项决定"禁 / 放 / 反转为要求"**，
只保留真正仍然不该出现的项（阶段三剩下的负面词只有：`大型帐篷、大量帐篷、成片的帐篷群、
过大的篝火、熊熊燃烧的大火、大量村民` —— 即"同类对象只禁**过量/超大**，不禁**存在**"）。

**派生链的选择也跟着变**：当新阶段的元素是**整组从零新增**时，
基准张宁可**从再上一个阶段的空场图跨阶段派生**，也不要从"已经有半套设施"的上一阶段派生 ——
后者要同时完成"2 个变 4 个"+"凭空加 4 类新设施"两件事，位置继承会打架。
实例：阶段三春天基准张 = 阶段一春天晴天白天 + 一整段"必须新增"，
八张全部一版过、零返工（四季以来第一次）。

### 2.14 「让某个对象处于某种状态」要双向否定——只写"是什么状态"压不住

用户的要求常常是「灯**刚刚熄灭**/货物**还没摆完**/牌面**空白**」这类**状态**描述。
只正向写「灯已熄灭」实测会翻车：模型照样画出**两盏点亮的油灯**；路标牌面也被写上**手写字迹**。

规律与 §2.8「季节色是双向的」同源：**写出你要的状态，同时把相反的状态也点掉。**

| 要求 | 正向写 | 必须补的反向否定 |
|---|---|---|
| 灯已熄灭 | 「已经完全熄灭，只是一盏暗色小金属灯盏，可以有一丝极细极淡的青白色细烟」 | 「**画面里看不到任何火焰、看不到灯头的亮光、看不到任何暖黄色光晕**」+ 负面加「火焰、亮着的灯、灯光光晕」 |
| 牌面空白 | 「牌面是**完全空白的光木板**，只有木头本身的淡色木纹」 | 「**没有任何文字、字母、数字、刻痕、签名、符号、图案，也没有任何手写字迹的痕迹、铅笔线、粉笔痕迹**」 |
| 货物未摆完 | 「一部分货物还堆在摊位旁边的地上等待摆上去」 | （配合 §2.2 写"必须出现"，否则模型会把货物全摆上台面） |

顺带：这类状态通常是**整张图里唯一的叙事点**，所以要用「**这是本张图必须出现的关键细节，绝对不能被省略**」
把它钉住（同 §2.11 ③ 的窗光手法）。

### 2.15 「减量 / 变空 / 状态变化」是模型最不听话的一类要求

「货物减少」「台面收空」「盖上粗布」这种要求，实测**直接写基本无效** —— 模型会保留参考图里那桌货，
只在旁边添点东西交差。同一张图为此连跑 4 版才收敛（2026-10-01 黄昏收市图）。

**有效的写法是「三步锚定」：**

1. **先点明参考图原本是什么**：「参考图里两个摊位的台面上**原本摆满了整排的果蔬和面包**」
   —— 模型需要知道要改掉的"原状"是什么，否则它会认为当前样子就是目标。
2. **给出可量化的目标**：「台面**百分之九十的面积都是空荡荡的粗布**」「每个台面**总共只剩下两三个孤零零的小东西**」。
   写"减少"没用，写"只剩两三个"才有用。
3. **列出禁止出现的具体物**：「**绝对不要出现整排的面包、成堆的果蔬、摆满一桌的货物**
   —— 台面上完全看不到任何橘红色的西红柿、绿菜或黄面包」。
   要**用画面里的实物名**（西红柿/绿菜/面包）而不是抽象词（货物/商品）。

**多条要求并存时，用「硬要求一 / 二 / 三」编号分段。** 一版只改一个硬要求、其余整段原样复制，
收敛最快（本项目就是这么从 v1 走到 v4 的）。**不要在同一版里同时动两个要求** —— 会分不清哪个改动起了作用。

**凡是要它出现的对象，都要单独挂一次「必须出现」锚定。** 踩过：写"摊位旁边的地上堆着几口空木箱"，
没加「这是本张图必须出现的关键对象，绝对不能被省略」→ 模型**直接把木箱那摞省略了**（同 §2.2）。
一次改动里往往有 2–3 个"必须出现"的对象（摊位 / 空木箱 / 小油灯 / 路标），**每个都要挂**。

### 2.15b 「收摊/夜晚」会诱导模型**凭空新增盖布空台**——换尺子图 + 圈定"只有谁能盖布"

设施已齐的场景（阶段三）做黄昏/夜晚收摊图时，模型会反复在画面空地（尤其右侧）**凭空长出 2 个盖布的空台子+木凳**，
把"摊位 3 个"偷偷变成"5 个"。负面词写"新增的摊位、盖着布的空台子、额外的桌子、木凳" +
正面写"帐篷旁空地必须空旷"都压不住（实测连返 2 版无效）。

两个有效手段（2026-10-01 秋季实测，各解决一张）：

1. **查尺子图的内容**：`image2` 亮度尺子若选了自带"多个盖布摊位"布局的图（如阶段二的 2 摊图），
   模型会把那套布局照搬进来——哪怕 prompt 写了"不要照搬内容"。换成**布局与 image1 完全相同的同阶段夜晚成品**
   当尺子（如阶段三夏夜），内容干扰源直接消失。
2. **把盖布权限写成排他**：「只有原有的三个木摊呈现收摊状态……**除此之外不要给任何别的物体盖布，不要出现任何新的台面**」，
   比泛泛的"不要新增"有效。

验收时黄昏/夜晚图要**专门数一遍设施总数**（数摊位数、看空地），这是本类任务最容易出现"悄悄+2"的地方。

**2026-10-01 冬季补充**：阶段二冬季尺子图同样会诱导**设施替换**而非仅新增——
雪天清晨"陆续摆开"让右侧木舞台被换成新增摊位+木凳，雨天白天让木舞台变成**成片盖布棚**。
压法升级为两条并用：① prompt 开头列**设施清单**（"全部设施清单如下，一个都不能多、一个都不能少：
三个木摊/布告栏/右侧木舞台原样保留/两顶帐篷/两面小旗/石圈篝火/木路标"）；
② 尺子图换成**布局完全一致的阶段三同天气成品**（v2 一版过）。

### 2.16 「盖上布」会被画成「撑起来的棚顶」——四重限定才压得住

给摊位/桌子「盖上防雨布 / 盖一块粗布」，模型的默认理解是**搭个棚**，一步就把画面推进到下一个阶段
（集市未搭建 → 突然长出帐篷）。只在负面词里写「帐篷」不够。

**必须四重限定：**

1. **说明盖法与走向**：「布是**直接盖在台面上的**，顺着台面垂下四个边角」
2. **否定形状（关键）**：「**没有支架、没有撑杆、没有绳子吊起来、没有立起来的立柱**」
3. **正面锚定原有结构**：「**木摊架的简陋结构仍然完整露在外面、看得清清楚楚**」
4. **负面词表补全**：「帐篷 / 遮阳篷 / **棚顶**」（原来常只写「帐篷」）

改天气/时段做「收摊」状态时都适用。实测四重限定后一次通过（2026-10-01 雨天图）。

### 2.17 色调类要求：局部改对了 ≠ 整体达标，必须用数值验证均值

用户常提一组**互相拉扯**的要求，例：「整体灰蓝冷调、低饱和」+「水洼反射窗户的暖黄灯光」。
模型能把你点名的局部画对（暖黄倒影有了），但**可能在别处加大暖色面积来"补偿"**，
导致整体反而更亮更暖。「低饱和」「冷调」「不要漆黑」这类**全局**要求，
**不能靠看局部放大图判断**，必须算整图均值。

可复用的体检口径（每 3 像素采样，避免太慢）：

```python
p=img.load(); w,h=img.size; r=g=b=0; n=0; warm=0; dark=0
for y in range(0,h,3):
    for x in range(0,w,3):
        R,G,B=p[x,y]; r+=R; g+=G; b+=B; n+=1
        if R>150 and R-B>70: warm+=1          # 艳暖像素（饱和橙黄）
        if (R+G+B)/3 < 60: dark+=1            # 暗部
print(f"R{r/n:.1f} G{g/n:.1f} B{b/n:.1f} | 亮度{(r+g+b)/(3*n):.1f} | 暖{warm/n*100:.2f}% | 暗{dark/n*100:.1f}%")
```

**判读**：把「同季晴天的定稿图」当基准，逐项对比。
本项目实测（春天、阶段二）：

| 版本 | R/G/B 均值 | 亮度 | 判读 |
|---|---|---|---|
| 参考（晴天白天） | 189 / 181 / 134 | 168.1 | 基准 |
| v1（**采纳**） | 133 / 130 / 108 | 123.7 | 亮度降 44、暖度减半 → 冷调达标 |
| v2（弃用） | 152 / 146 / 117 | 138.2 | **反而更亮更暖**，偏离要求 |

踩过的坑：只看「水洼主色改成了灰蓝」就以为 v2 更好，**指标一算才发现整体变暖了**。
**先看数值再看图**，能省掉一轮误判。

判定"是否漆黑"用暗部占比（<60 的像素），实测夜景/雨景在 **4%–5%** 附近是合适的；
超过 15% 基本就是糊成一片了。「不漆黑」这条光看均值亮度不够，要配暗部占比。

**暗部占比比均值亮度更敏感，是夜景的第一判据。** 2026-10-01 雨夜实测：

| 版本 | 亮度 | 暗部占比 | 判读 |
|---|---|---|---|
| 参考（雨天白天） | 123.6 | 4.7% | 基准 |
| 夜 v1（弃用） | 89.6 | **17.2%** | 超 15%，糊成一片 |
| 夜 v2（**采纳**） | 98.3 | **12.2%** | 亮度回到参考的 79%，达标 |

提亮夜景的有效措辞（写进【硬要求】并编号，光靠"不要过暗"压不住）：
> 「整体亮度保持在**参考图的七成到八成**之间……**夜色是靠偏冷的蓝灰色调表现的，不是靠把画面压黑表现的**；
> 画面里最暗的地方也要能分辨出那是什么东西。」
> 负面词补「**大片纯黑、剪影式的黑块**」。

**⚠️ 「暖色占比」这个全局指标会被场景底色污染，不能用来判断"暖黄灯光画出来没有」。**
同批次实测：雨天白天 暖 1.25%、雨夜 只有 0.19%——看着像"夜景忘了画窗光"，
其实白天那 1.25% 大半来自**土路/草地的暖黄底色**，夜景整体转冷后这部分自然消失。
判断某个**局部光源**在不在，要改成**定位暖点簇**：

```python
# 找 R-B 明显的像素，按坐标聚类，打印前 6 个簇的坐标与 RGB
if R-B > 45 and R > 110: pts.append((x,y,R,G,B))
# 再和参考图对照坐标：酒庄窗 ≈(690,390)、摊位油灯 ≈(430,520)、村庄窗 ≈(170,430)
```
本项目靠它确认了 v1 的酒庄窗光其实**早就画出来了**（214,125,33），真正的问题只有"太暗"。
→ **先定位再下结论**，否则会为了一个不存在的毛病重出一版。

### ⚠️⚠️ 提亮/压暗类要求：文字说不动时，喂第二张图当「亮度尺子」（双参考图法）

模型对「亮度保持在参考图的七到八成」「不要过暗」这类**相对数值**描述几乎无感
——2026-10-01 夏天实测：夜景连写「八成左右、绝对不能低于七成」仍只出到 57%。

**改法：`image1` 放内容基准，`image2` 放一张「亮度已经对了」的同系列成品当尺子**，
并在提示词开头就把两者的分工钉死：

```
有两张参考图。第一张是内容基准：布局、地形、建筑、……全部以它为准（照抄 §1 骨架）。
第二张只是明暗程度的尺子：请参照它那种「……」的亮度来处理画面，
只学它的明暗程度，不要照搬它的季节、植被和内容。
```
再配一条【硬要求一：亮度】「成品的明暗程度必须和第二张参考图基本一样……」。

**实测三次全部一次命中**（ImageGen `input_fidelity=high`）：

| 目标 | image1（内容） | image2（尺子） | 结果 |
|---|---|---|---|
| 夏天晴夜 | 夏天晴天白天 | 春天晴天夜晚 | 亮度 94.5（尺子 93.2），暗部 42.9%→21.1% |
| 夏天雨白天 | 夏天晴天白天 | 春天雨天白天 | 亮度 123.6（尺子 123.6），暗部 24.0%→7.6% |
| 夏天雨清晨/黄昏/夜晚 | 夏天雨天白天 | 春天雨天同***时段*** | 122.9 / 117.5 / 104.4，与尺子 121.9 / 113.3 / 98.3 对齐 |

**要点**：
1. 尺子图选**同系列、同时段、亮度已达标**的那张（跨季节没问题，季节色由 image1 决定）。
2. 「只学明暗、不要照搬内容」这句必须写，否则会把尺子图的季节/植被一起搬过来。
3. 有了尺子之后，季节色、构图仍 100% 由 image1 决定，实测没有出现串季。
4. **先算尺子图的数值再选它**——别拿一张本身就偏暗的图当尺子（本项目阶段一的夏天夜景暗部 48.9%，
   拿它当尺子只会一路黑下去）。

**配套：判断"这一版够不够亮"用同季晴天定稿图当基准 + 同组已有成品当尺子，两边对。**
本项目夏天全套最终数值（阶段二）：晴 清晨 134.8 / 白天 132.1 / 黄昏 109.8 / 夜晚 94.5；
雨 清晨 122.9 / 白天 123.6 / 黄昏 117.5 / 夜晚 104.4。暗部占比全部落在 6%–22%。

**补充：同一张图反复微调时，直接重发比局部修补快。** 改一个硬要求就整张重发，
提示词从上一版复制、只改对应那一段；`output_dir` 每版换新名（`dusk_v2`/`dusk_v3`…），
旧版保留到定稿再一起清 —— 方便回退，也方便横向对比（把各版同一区域裁下来拼一条，一眼看出哪版最好）。

### 2.18 「去元素」改造：把已有成品里的某个对象删掉（无动物版）

场景：整套图原先画了动物/人物，现在游戏引擎要**动态放置**这些图标，要求改成「无动物版」。
目标 = **除该元素外一切不变**。

**参考图分工（2026-10-01 农业区实测，14 张一版过）：**

- `image1` = **同场景、同天气、同时段的旧版含元素图**（管构图与内容 —— 唯一可信的构图来源）
- `image2` = **已经做完的同季节去元素成品**（一张图同时干两件事：当氛围/亮度尺子 + 当「这个场景没有元素时该长什么样」的示范）

**⚠️ 不要为了「提亮 / 换色」去换 image1 的底图。** 换底图 = 换构图来源，模型会当成新场景重新发挥。
实测：把夏天雨天白天的 image1 从「旧版雨天图」换成「夏天晴天图」想提亮，
亮度确实上去了（104.5 → 127.5），但**模型顺手在牧场里加了一片水塘，塘里还有白色水禽** ——
直接违反「无动物」，整张作废。**要最小改动，就必须沿用同场景旧版当 image1。**

**措辞要点：**

- 单开一段【修改一·去动物】，列出**用户点名的每一种动物**（牛、羊、猪、鸡），并补两个层次：
  1. **删完怎么补**：「删掉后用与周围一致的草地、泥土、干草和木栅栏纹理把空处填补自然，不留动物轮廓与阴影」；
  2. **别把建筑一起删掉**：「木栅栏、谷仓、鸡舍、木箱等建筑与静物要原样保留，不能一并删掉」
     —— 实测不写这句，模型会把整座畜栏/谷仓一起抹掉。
- 负面词表要**预防性扩容**：除用户点名的之外再加「**无鸭、无鹅**」，负面项补「**不要新增任何池塘、水禽**」
  —— 模型在「填空白」时非常容易自己造出水塘 + 水禽（见上面换底图那个坑）。
- 季节色仍照 §2.8 双向写；换季图另加【修改二·季节/天气】段。

**验收：**

- 动物区按 §4.2 裁块放大拼图，逐张确认无残留（谷仓、围栏、木箱、干草堆应当仍在）。
- **雪天图的 `wm_score` 天然偏高**（实测雪天 9.14、冬天晴天 7.47，其余只有 3–5）——
  因为雪地亮度逼近纸边。分数高**不等于**有水印。**必须目视右下角 3 倍放大图再判断**，
  不要因为数值高就重复去水印。

### 2.19 返工前先打开旧图核对，别凭印象下结论

2026-10-01 农业区实测两例：

1. **以为是模型偏色，其实原图就这样。** 发现新图玉米地是金黄，判断「被画成秋天了」准备返工；
   打开旧图一看，**旧版玉米地本来就是金黄**，新图是忠实还原（亮度 104.5 / 暗 18.8% vs 旧 106.3 / 19.7%）。
   不核对就白返一轮。
2. **以为是指标退化，其实是改掉了错误。** 秋晴昼的「暖色占比」从 55.0% 掉到 27.2%、秋雨昼 37.9% → 10.4%，
   看起来像秋色被洗掉；拼出新旧对比图才发现，**旧版的「暖」是天空被画成了大片橙色**（秋天白天不该是橙天）。
   新版把天改回蓝/灰，秋叶与金黄玉米都在 —— 这是**改进**，不是退化。

→ 数值异常只是**发起核查的信号**，不是返工的理由。**先拼「新旧同框对比图」看一眼再决定。**

### 2.21 「微调轮」：已定稿成品做统一优化 —— 只给 image1，千万别给 image2

验收完的整季图，用户常会提一轮统一微调（雨丝改自然、水洼别过亮、清晨雾气加强、整体更通透 / 低对比）。
这类改动是**画面内容层面**的，PS 式滤镜改不了，只能重绘微调。要点：

1. **只传 `image1` = 该张成品本身，不传 `image2`。**
   秋天夜景踩过 3 次坑：image2 尺子图自带「盖布摊位」布局，被模型整体照搬，凭空长出设施。
   微调轮不需要外来亮度尺子（**原图就是亮度基准**），加 image2 只会引入布局污染源。
2. **prompt 开头钉死身份**：「这张参考图就是成品的唯一基准：本图就是这张参考图的微调优化版本」，
   再逐项列出「只优化 A / B / C，其余一律不动」，并把物体数量写清楚（如「三个盖布木摊，不多不少」）。
3. **成品命名带后缀**（`norm.py` 第三个参数 suffix → `<原名>_优化.png`），**原图不动**，方便用户新旧并排对比。
4. **先改 1 张再批量**：挑「专项改动最多」的那张（如雨天白天，雨丝 + 水洼两项都在）。
   改坏已验收图的成本是真实的，一次性全改等于把整季重做一遍。
5. **⚠️ 微调轮会把夜景提亮 —— 这是微调轮最高频的返工点。**
   晴天夜晚实测：原图亮度 98.5，微调后变成 **120.5**（直接变黄昏感）。
   根因：微调模板里「暗部稍微提亮一点 / 更通透 / 最暗的地方能分辨出东西」这套措辞，
   **在夜景上会被整体执行**，而不是局部执行。
   夜景必须额外写死三条，缺一不可：
   - 「亮度必须和参考图一样暗，绝对不许提亮，绝对不能变成黄昏/傍晚」
   - 「画面里绝大部分面积仍然处在夜色的暗部：夜空深紫、草地暗橄榄、土路深灰褐——这些暗部都不要提亮」
   - 「画面里只有 X 处很小的暖色（油灯 / 窗光 / 月亮），范围都很小」
   加上后回到 100.5（原 98.5），一次通过。**夜景微调不能只写「暗部稍微提亮一点」。**
   改用网格热区脚本（把图分 16×10 格，统计 `R>140 且 R-B>55` 的暖色像素，输出 top 格坐标 + 强暖点重心）
   间接判断「暖光焦点加没加上、加在哪」，并**如实告诉用户我看不到图、请他确认**——不要假装验收通过。

### 2.20 关键文件改动后必须复跑校验

用 `cp A B && mv C D && cp E F` 这类串联命令做「回退 / 改名」时，**中途失败会让前面的步骤留在半路**，
而整体仍可能不报错。实测：一条回退命令执行后终端无输出，**落盘的仍是未回退的 V3**，
直到复跑数值体检（亮度 127.5 = V3，而非 V2 的 104.5）才发现，白等一轮。

→ 回退 / 替换关键成品后，**必须重新读一次该文件的数值或打开确认**，不能只看命令有没有报错。
