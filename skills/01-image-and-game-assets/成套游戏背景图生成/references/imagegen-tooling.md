## 2.9 出图工具：miora 不可用时用 ImageGen 兜底

`miora_edit_image` / `miora_text_to_image` **不是每个会话都可用**——实测 2026-10-01 那次会话里 ToolSearch 完全查不到 `miora_*` 工具。
这时改用内置 **`ImageGen`** 的 image-to-image 模式，提示词骨架与第 1 节完全相同，只是参数不同：

| 参数 | 取值 | 说明 |
|---|---|---|
| `image1` | 已定稿的参考图（本地绝对路径即可） | 不要用最初的上传方图 |
| `size` | `1536x1024` | ImageGen 只接受 1024x1024 / 1024x1536 / **1536x1024**（横版）三种；竖版构图用 1024x1536 |
| `input_fidelity` | `high` | 保真度调高，构图最贴参考图 |
| `output_dir` | 每张一个独立目录 | **但这条不可靠，见下方「必须串行」** |

**必须先做尺寸归一**：ImageGen 返回 **1536×1024（3:2）**，不是目标画幅。以 960×592（1.62）为例：

```python
im2 = im.resize((960, round(H*960/W)), Image.LANCZOS)   # 1536x1024 -> 960x640
cut = im2.size[1] - 592                                  # = 48
im3 = im2.crop((0, cut//2, 960, im2.size[1]-(cut-cut//2)))  # 上下各裁 24 -> 960x592
```

实测这样裁不会切到地物（上下各留 24px，主要吃掉白纸边和一点点天空）。
**不要为了凑尺寸做非等比拉伸**——8% 的横向拉伸会把水桶、圆石压成椭圆。

### ⚠️ ⚠️ ImageGen 文件名撞车：给不同 `output_dir` **不够**，必须串行

ImageGen 的落盘文件名 = **prompt 前缀 + 秒级时间戳**。
同一秒完成的两个任务 → **同一个文件名 → 后完成的直接覆盖前一个**。

**踩过三次，第二、三次都证明了「不同 output_dir」也救不了：**

| 批次 | 并发数 | 结果 |
|---|---|---|
| 4 张季节图 | 4 | 3 张进 `raw/`、1 张进 `raw_winter/`，`raw/` 里**秋/冬撞车，冬天被覆盖** |
| 5 张天气图（每张给了不同 `output_dir`） | 5 | **5 张全部落进同一个目录**（第一个调用的目录），**冬天晴天又被覆盖** |
| 秋天 3 个时段（清晨/黄昏/夜晚，三个不同 `output_dir`） | 3 | **3 张全部落进 `_tmp_aut_dawn`**，且黄昏与夜晚时间戳同秒 → **黄昏被覆盖，直接丢图**，只能单独重发 |

**根因是并发竞态：`output_dir` 在多调用并发下会被忽略/串号。**
单发时 `output_dir` 是准的（所以看起来像「能用」），多发就一定出问题。

**第三次的新发现：并发不仅串目录，还会同秒完成 → 文件名完全相同 → 静默覆盖。**
这时 `ls` 数文件数仍然能发现问题（3 张变 2 张），但**已经有一张永久丢失**，只能重出（多花一次额度）。
所以「串行」不是性能优化建议，是**避免丢图的硬要求**。

**结论：ImageGen 必须串行发 —— 一次消息只发一个生成调用，拿到结果再发下一个。**
串行后时间戳天然错开，零覆盖（实测 4 张雨天串行发全部正常）。

**配套的两个检查动作（别省）：**
1. 一批出完先 `ls` 数文件数。**少于张数 = 有图被覆盖了。**
2. 结果里的 `localPath` 若出现重复，**立刻按画面内容认领**（缩略图拼 2×2/3×3，比看文件名可靠）；
   缺哪张就单独补发那一张（补发时更要串行）。

> 对比：`miora_edit_image` 没有这个问题（返回的 `localPath` 由服务端生成，天然唯一）。
> 如果会话里 miora 工具可用，优先用它。

### 2.22 ⚠️ ImageGen 会话中途「降级为 1:1 方形」——**裁方图救不回来，用「内嵌横版」提示词**

2026-10-01 阶段四夏天实测：同一会话里第 1 张正常返回 **1536×1024**，从第 2 张起
**之后每一次都返回 1024×1024**，`size=1536x1024` 完全失效（换措辞/极简 prompt/单图 vs 双图/换 image1
全部无效）。**先做一次「尺寸探测」**：拿一张必定要做的图跑一次，看返回尺寸，再决定走哪条路。
（旧版本会话同样是"前 2 张正常、之后全方"。所以这不是偶发，是**服务端降级**。）

#### ⚠️ 第 0 步：探测画布形状——它会**在同一个会话里来回跳**

不要假设"上次是方图，这次也是"。2026-10-01 同一个会话实测：**第 1 次出 1536×1024、第 2 次出 1536×1024
（但内容画成超宽幅）、第 3 次出 1536×1024、第 4 次又出 1024×1024**。size 参数时灵时不灵。

**因此提示词里的版式段要写成"双分支"，让模型按实际画布自己选**，一次发出去无论返回哪种都能用：

```
【版式要求（严格按你实际输出的画布形状选一个）】
① 若画布是正方形（1:1）：正中间横放一条宽幅全景，横向铺满，高度占画布 62%（上下居中）；
   上下各留约 19% 的空白水彩纸边（纸边里只有纸纹与极淡水彩晕染，不画景物）。
② 若画布是横版（如 1536×1024）：画面满幅铺满四边，不留任何空白纸边相框，画幅比例接近 3:2。
```

**❌ 横版画布上仍用单一"内嵌横版"版式 = 2.19:1 超宽幅**（2026-10-01 实测）：
"横向铺满整幅宽度 + 高度占 62%" 在 1536×1024 上算出来是 2.42:1，模型画成约 2.19:1，
而目标比例是 1.6216 → 裁切时按宽度定高会**丢掉左右各约 26%**（右侧大树、左侧葡萄园边缘全没了）。
用户一眼就看出来"布局又偏了"。**这种图必须废弃重出，不能将就。**

**❌ 横版满幅的提示词里写"横向铺满"会把单排集市画成上下两排摊位**（v3 实测，整张废弃）。
满幅写法必须显式加一句 **"集市摊位只能是单独一排，绝对不能变成上下两排"**，
负面词再补「两排摊位 / 重复摊位」。

#### ❌ 先说被证伪的做法：把方图裁成横版

上一版技能里写的"裁中间横带 + 复用纸边"**能让图凑出 960×592，但取景是错的**，这也是
"整套图布局看着到处偏移"的真正原因。原因：**模型在方形画布上会重新构图**——它把天空、前景草地的
占比按方形画布重新分配，场景被放大填满，所以**没有任何一个 3:2 裁切窗口能还原原生横版的取景**。

量化判据（务必记住这套口径，能立刻分辨"是取景错还是颜色差"）：

| 对比 | 梯度结构相似度（粗尺度 NCC） |
|---|---|
| 原生横版成品 vs 锚点（同为白天） | **0.95** |
| 方图取任意窗口裁切 vs 锚点 | 最好只有 **0.29** |

→ 方图裁切项的分数只有"已知正确"的 1/3，**说明构图真的不一样，不是颜色差异造成的**。

#### ✅ 正确解法：让方形画布里「内嵌一条真正的横版画面」

在 prompt **最前面**加一段版式硬要求，模型会照做（实测 6/6 全部成功，且画质无损）：

```
【版式·第一硬要求】输出是方形画布（1024×1024），请排成上下带留白的版式：
画面正中间是一条横版宽幅的<场景>全景，横向从最左边一直铺到最右边，
高度占整张画布高度的 62% 左右（上下居中）；这条横版区域的上方和下方，
各留一条约 19% 高度的空白水彩纸边，纸边里只有纸张纹理和极淡的水彩晕染，
不画任何景物、不画天空、不画草地。这条横版区域内部，天空只占上方约四分之一，
主体在中间，前景在下方。
```
负面词补一条：「**把场景拉满整个方画布**」。

**关键点**：版式段必须放在 prompt 最前面；其余内容段（基准/只改什么/画风）照常跟在后面。
派生后续图时，**image1 直接取这张"已带纸边的方图"**，模型会沿用同一套版式（雨/时段四张全继承成功）。

#### 方图**没有**纸边时：先用 NCC 判断是「被纵向拉伸」还是「重新构图」，再决定压回去还是裁

有时模型不理版式段、直接**满幅铺满方画布**（2026-10-01 实测）。这时不要直接按 3:2 裁中间带，
先做一次 `(y0, h)` 扫描判断性质：

```python
# 以「同天气、已对齐的旧成品」为主对照（关键！）
for h in range(480, H+1, 16):
    for y0 in range(0, H-h+1, 16):
        cand = src.crop((0, y0, W, y0+h)).resize((960, 592))
        score = edgeNCC(cand, OLD)      # 梯度结构相似度
```

- **判读**：最佳 `h ≈ W/1.6216 = 631` → 不变形裁切就够；最佳 `h` 明显更大（如 796）→
  **方图是被纵向拉伸的构图，要按比例压回去**（本例如 1024×796 → 960×592，纵向压 21%），
  此时 `(y0=212, h=796)` 拿到 NCC **0.546**，而"裁 631 不变形"只有 0.36。
- ⚠️ **必须用同天气旧成品当对照**。跨天气（如雨天 vs 晴天）的边缘 NCC 上限只有约 **0.17**，
  拿跨天气图当基准会把"正常"判成"全错"（本轮先踩过：一度以为 NCC 0.114 是崩了，其实晴天↔雨天
  本来就低）。**做法：把「旧雨晨 vs 晴天锚点」的基线一起打印出来当标尺**（=0.1715），
  候选与锚点相近（0.1706）即通过双参照验证。
- 顺带把横向也扫一下（`x0`, `w`），别假定一定全宽——但一致性优先，非必要不逐张调。
- **验收四件套**（不用肉眼也能收口）：
  1. **分块 NCC（4×4 网格）全为正、零负相关格** = 无局部重影（本轮 16/16，最低格 0.189）；
  2. **底部 12 行亮度平滑无突变** = 没裁进白纸边（本轮 113→110）；
  3. **右下角亮度显著低于左上角** = 无水印（本轮 105.5 vs 225.0）；
  4. 左右边缘列亮度 ≈ 全图均值 = 无异常裁切（本轮 141.7 / 147.1 vs 142.5）。

#### 自动取回横版：纸边识别 + 统一裁切（脚本 `_work/band_crop.py`）

```python
# 纸色 = 四角 60x60 块的 RGB 中位数；dev = 每像素与纸色的 L1 距离
rows = dev[:, int(W*0.12):int(W*0.88)].mean(axis=1)   # 只用中段列统计行
y0,y1 = longest_run(rows, thresh=40)                   # 阈值 40 是关键
cols = dev[y0:y1, :].mean(axis=0)                      # 再在带内统计列
x0,x1 = longest_run(cols, thresh=40)
```
要点：
- **阈值必须实测**。纸边行的分数（含纸纹）约 **12–17**，画面行 **180–420**，所以 40 安全；
  用默认的 14 会把纸纹判成内容。
- **只用画面中段列统计行**：右下角"AI生成"水印会让底部纸边行的分数飙高，
  把内容带一路延伸到图底（第一版就这么错了）。
- 检出带后再按目标比例定窗口：**一律取带的全宽、竖向居中、按 3:2 定高**，
  并且**硬性限制窗口不越出检出带**（越界就会把纸边裁进成品，夜景/黄昏图最明显）。
  ⚠️ **clamp 的目标必须是检出带 `[by0, by1-h]`，不是画布 `[0, H-h]`** ——
  2026-10-01 晴天夜晚那张，因为只 clamp 到画布边界，加到垂直校正后窗口下沿越出带 15px，
  成品底部出现一条白纸边（行亮度剖面 y=572 由 98 突跳到 234，肉眼一看就是白带）。
  **再加一道保险：检出带四边各内缩 `inset=6`px** —— 纸带与画面交界有几行过渡色
  （既不达标纸也不算画面），不内缩会把这条淡边裁进来（该张修完仍残留底部 4px 亮度 125）。
  内缩只影响"贴边"的图，有余量的图完全不受影响。
  **验收口径：跑一次"底部逐行亮度剖面"，末 3 行与画面中部的差值应在 ±15 以内。**
  ⚠️ 不要让对齐算法自由挑缩放——实测它会挑出忽大忽小的窗口（某张缩到带宽的 88%），
  整套一致性立刻崩。一致性 > 单张最优。
- **固化成工具库脚本**：`<project-root>\game-assets\背景\_工具脚本\letterbox_crop.py`
  （合并 纸边检出 + 3:2 居中 + `--up` 垂直校正 + 带内 clamp，支持单文件/整目录：
  `python letterbox_crop.py "方图目录" "输出目录" --up -14`）。

#### 系统性垂直校正（脚本 `_work/final_crop.py`，`UP_SHIFT_960 = -14`）

内嵌带版本相对原生横版锚点，**内容会整体偏低约 10–15px**（960 空间）。统一校正即可：

- 判据（两种独立指标交叉验证，2026-10-01 实测同一张图）：
  粗尺度 NCC 在 **-12px 处最高（0.390 vs 0 处的 0.305）**；相位残差在 -20px 附近归零。
  取 **-14px** 两指标都好。
- **⚠️ 符号陷阱：取样窗口"上移"会让画面内容**下移**。要把内容抬上去，必须把窗口往**下**取（y += Δ）。**
  我第一次写反了，残差反而从 -13 变成 -15。
- 校正量是**整套共用一个常数**，不要逐张调——逐张调又会破坏一致性。

#### 残差测量：相位相关（脚本 `_work/phase_align.py`）—— **只用于诊断，别用它做精修**

```python
fa, fb = fft2(A), fft2(B); r = fa*conj(fb); r /= abs(r)+1e-9
i = argmax(ifft2(r).real)   # 峰值位置 = 平移残差
```
- **乘汉宁窗**再 FFT，否则边缘环绕会干扰。
- 判读基线：**原生横版成品 vs 锚点峰值 ≈ 0.25，残差 (1,-2)（几乎完美）**；
  内嵌带成品峰值只有 0.02–0.04。**峰值低不代表没对齐**——白天↔夜晚这种跨时段的
  结构相关本来就接近 0。**残差数值比峰值可靠，且要和"同为白天"的图对比才有意义。**
- ⚠️ **2026-10-01 实测教训：相位残差"看着很一致"也不代表能拿它做逐张平移精修。**
  当时 6 张残差都指向"偏低 10–13px"，于是按残差逐张推了一版（`preview4`）——
  结果残差忽大忽小、峰值只有对照组的 1/5，**构图被推歪，肉眼一看就废了**。
  根因：模型这几张的构图本身就有细微差异（缩放/透视各自微变），相位相关把这种
  "结构性差异"误读成"纯平移"，硬推只会越推越歪。
  → **正确姿势：只取一个"整套共用的常数量"（本次 -14px），推完用 50% 叠加图肉眼收口。**

#### 指标陷阱汇总（本类任务极易被误导）

| 指标 | 什么时候会骗你 |
|---|---|
| 梯度 NCC（全分辨率） | **雨丝/雪花**贡献海量高频边缘，把分数整体拉低 |
| 梯度 NCC（粗尺度 80×49 + 高斯模糊） | 对平移**不敏感**（±10px 分数纹丝不动），只能用来比"缩放/取景量级" |
| 结构掩膜 IoU（二值化边缘重叠率） | 同样对平移不敏感（纯平移 10px 仍满分 2.0）；对**缩放**敏感（偏差 2%→1.85、4%→1.46、6%→1.29） |
| 暖色占比 | 会被场景底色污染，判断"暖光画出来没有"要**定位暖点簇**（技能 §2.17） |

**结论：自动指标只能用来做"候选之间的相对排序"，最终一定要用「锚点与该图 50% 半透明叠加」
看有没有重影来收口。** 叠加图重影小 = 对齐可接受。

#### 降雾 / 提通透：常见副作用是「雾没了但整体褪色发白」，用脚本补（`post_dehaze.py`）

用户提「下雨天早晨雾太重 / 要降雾、提通透」时，**先出图，再用数值分清是"雾"还是"灰"**，
不要靠反复改 prompt 硬刷（本会话为此多烧了 2 次额度）。

2026-10-01 雨天清晨实测的典型症状——三个指标一起看：

| 指标 | 优化前 | 直出 | 判定 |
|---|---|---|---|
| 亮度 | 131.9 | 143.0 | ✓ 不发闷了 |
| 对比度 | 45.1 | 47.5 | ✓ 通透了 |
| **饱和度** | 62.6 | **52.7** | ✗ 褪色 |
| **暖色像素占比** | 61.4% | **48.0%** | ✗ 发白 |
| **远景细节能量** | 6.17 | **5.57** | ✗ 远景更糊了 |

→ 雾气确实少了，但**换成了整体发白**。用 `<project-root>\game-assets\背景\_工具脚本\post_dehaze.py` 一次到位：

```
python post_dehaze.py 输入.png 输出.png --sat 1.16
# = 饱和度 x1.16 + 上 45% 区域大半径小强度去雾锐化(radius5/percent45) + 全图极轻锐化(radius1.2/percent22)
```

结果：饱和 52.7→**61.3**（目标 62.6）、远景细节 5.57→**8.75**（旧版 6.17，晴天 13.32）、
亮度 142.5 保持 ✓。脚本会打印前后数值，直接和同系列定稿对比。

**口径提醒**：
- **"远景细节能量" = 远景区（上 12%~38% 高、中段宽带）的相邻像素灰度差均值**——这是"通透度"的
  可量化代理指标，比主观判断靠谱。雾少 → 该值升高；发灰发白 → 该值降低。晴天参考值约 13，
  雨天合理区间 **7–10**。
- 后处理**只对"灰"的部分动手**（饱和、局部对比），**不要动亮度基调**，否则整套明暗梯度会乱。
- 用 `--sat` 一次加太多（>1.3）会出"塑料感"，与"低对比度、柔和光线"的画风要求冲突。

#### ✅ 交付前必跑：「整套构图一致性自检」（`series_align_check.py`）——别等用户用肉眼抓包

2026-10-01 阶段四夏天的教训：晴天夜晚那张**逐张数值体检也过了、分块对齐也 16/16 全正**，
但用户一眼看出"和另外七张相比有些偏移"。原因：**只做了逐张验证，没做整套横向比对**。

```
python series_align_check.py "整套图目录" "参照图名关键字"     # 例：... 夏天" "晴天_白天"
```

**为什么用「边缘强度投影」而不是全图 NCC**：投影只比"结构落在画面的哪个位置"，
白天↔夜晚、晴天↔雨天的亮度差完全不影响它。全图 NCC 在跨时段会直接塌到 0.03 左右（本轮实测：
旧晴夜 vs 锚点仅 **0.0307**，看不出任何东西）。

**判读**：`d` = 把该图内容向【下/右】挪多少才能对齐参照；`r` = 相似度。

| 症状 | 结论 |
|---|---|
| `d` 偏离中位数 > 20px（约画面高 3.4%），但 `r` 正常 | 小偏差，可接受，不必动 |
| **`d` 离群 + `r` 全场最低** | **取景/缩放被改了，平移修不回来 → 必须重出** |
| 同为夜晚的两张互比 `r` 偏低 | 正常，夜晚↔白天天然低；**只在同一时段类别内部比才要求接近 0.9+** |

⚠️ **写法陷阱**：离群判定不要用"位移超出其余图的范围"——整套的最小值和最大值**必然**被标出来，
每套都报警，等于没有判据（本轮第一版就这么错）。
**正确写法：位移相对整套「中位数」偏离 > 20px + 相似度比其余图最低值再低 0.06。**

实测数据（参照＝晴天白天）：晴天清晨 0/0.979 · 晴天白天 0/1.000 · 晴天黄昏 +16/0.879 ·
**晴天夜晚(旧) −46/0.743** · 雨天清晨 −16/0.897 · 雨天白天 −16/0.851 · 雨天黄昏 −12/0.882 · 雨天夜晚 −32/0.807
→ 晴夜纵向偏 46px 且 r 全场最低 ⇒ 重出。**重做后 d=0、r=0.934**，跨时段 NCC vs 锚点 0.0307→0.2627。

**修单张偏移的正确流程**（不要试图用平移/等比缩放去救）：
1. `image1` = 布局锚点（同一套里构图最正的那张），`image2` = 上季**同天气同时段**成品（只学明暗冷暖，并在提示词里写死"不要学它的内容"）；
2. 提示词把"不得改变取景范围和缩放、地平线/远山/村庄/帐篷/摊位位置一比一还原"写在最前；
3. 出图后按 §2.22 的流程裁，用 `series_align_check.py` 复检是否还在离群名单里。

#### 三类「局部微调」怎么都不该重新出图（除非要动内容）

用户常在一个爱消息里下发好几条（降雾 / 调色 / 加层次 / 去水印）。**先分类：**凡是不牵涉
"画东西"的，一律用后处理，省额度且**零构图风险**；只有"内容变了"（出现/消失物体、
两排摊位之类）才值得重发。

| 需求类型 | 归属 | 做法 |
|---|---|---|
| 降饱和度、降某种颜色、加暖/冷调 | **后处理** | HSV 里按色相区间做 `S` 缩放；冷暖调用**通道比例偏移后把亮度归一化**（直接叠暖色会把画面提亮，会乱整套明暗梯度） |
| 降雾 / 提通透 | **后处理** | 距离渐变暗通道去雾（`post_dehaze.py` / 本轮 `_work/finalize_v5.py`） |
| "某块区域要有层次/变化" | **后处理**（重生成没用，见下） | 低频起伏放大：`out = img + (blur(16) - mean)*k`，用渐变蒙版限定区域 |
| 出现/消失物体、错位、网点还在 | 重新出图 | —— |

**⚠️ 布局锚点图绝对不能重新出图。** 整套图的装饰锚点（阶段四夏天 = `晴天_白天`）一旦被替换，
其余 7 张的参照系全废。它的任何优化（哪怕用户写的是"参考图保持原样+优化 xxx"）都必须走后处理。

**⚠️ "给天空加云层层次"这类需求，重生成是白搭。** 2026-10-01 雨夜实测：把"云层要有丰富明暗变化"
写进正面提示词、把"平坦单调的天空"写进负面词，专为这事重出一版 —— 云层低频起伏 **21.24 → 20.12（−5%）**，
完全没用。改成局部低频起伏放大（`k=0.8`，只作用于 y<0.36H 并渐变归零）后，低频起伏直接到 ~32（+50%），
亮度/对比度几乎不变。**结论：模型不会为了"层次"去加东西，这类诉求直接上后处理。**

**渐变去雾的要点**（雾主要压远处，近景本来就没雾）：
```python
dc = MinFilter(15)(min_channel(img))        # 暗通道
A  = 原图在 dc 最亮 0.1% 位置的均值         # 大气光
t  = clip(1 - w*(dc/A.max()), tmin, 1.0)
dh = (img - A)/t + A                        # 全局去雾结果
m  = clip((0.72H - y)/(0.45H), 0, 1)        # 距离渐变：远处全去雾，近景不动
out = out*(1-m) + dh*m
```
取 **w=0.60**，之后 `gamma 0.95` 轻微补亮（去雾必然压暗，不补就会"灰暗"，正好踩用户负向词）。
实测远景细节 8.75 → 10.80、近景细节 6.82 完全不变（水彩柔感保住了）。
