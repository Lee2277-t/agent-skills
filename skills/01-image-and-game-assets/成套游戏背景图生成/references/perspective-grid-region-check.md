## 8. ❌ 别让模型在「俯视透视地面」上画规则网格 —— 用程序画（2026-10-04 实测）

场景：工业区基础地面底图，要求地面上有"隐约可见的 6×6 网格分界线"（供后续搭建对位）。

### 8.1 模型做不到这件事（两版都失败，方向相反）

| 版本 | 结果 |
|---|---|
| v1（提示词写"隐约可见的淡色分界线，非常淡、不抢眼"） | 网格淡到**几乎看不见**，达不到"缩小后仍清晰" |
| v2（改写成"清晰可辨但柔和、细线、不笔直不机械"） | 网格**重到像 CAD 辅助线**，而且**每格大小不等、越远越大**，透视上完全错误 |

**根因（务必记住）**：**俯视透视地面上不存在"等距方格"**。真实地面上均等的 6×6 网格，
在透视画面上必然是**近处格子大、远处格子小**。模型会把它画成"等距"，于是越远越挤、
看着像辅助线。**靠改提示词无法解决，这是透视与"等距"本身的矛盾。**

### 8.2 ✅ 正确做法：程序绘制「透视网格」（脚本 `_工具脚本/grid_overlay.py`）

1. **抹掉模型画的歪线**：对地面区做 `MedianFilter(9)` 取低频，**只把"比低频暗且很细"的
   部分往回提**（`lift = clip(base-sub, 0, 26) * 0.65`）。
   注意必须用中值/低频做底，不能用"周边均值"——否则道路、石块这类大尺度暗部会被一起抹掉。
2. **按透视规律画线**（这是关键）：
   - 横线位置按 `t ** (1 + persp*3)` 分布（`persp=0.16`）→ **越远越密**，符合近大远小；
   - 竖线远端向**消失点**收分（消失点取画面中线偏上，`x_top = vpx + (x_bot-vpx)*0.55`）；
   - 线本身加**手绘抖动**（`jitter=3.0`）+ **断笔**（随机若干小段衰减到 0.05~0.4）+
     随机浓淡，再高斯平滑 → 水彩笔触感；
   - **两端渐隐** + 远端更淡（`fade *= (1 - 0.5*(1-u))`）。
3. **强度**：`alpha≈0.11`（v2 直出的重线约等于 alpha 0.22~0.30）。
   下半部（近处）可做 **0.72→1.27 的补偿**，否则近处线条会被地面纹理吃掉。
   线色用比地面略深的灰 `(62,66,72)`，**不要用黑**。
4. **验收**：`alpha=0.11` 时线条覆盖率约 1~3%；
   目视确认"不抢眼、有浓淡、透视自然、缩小后仍看得出格子"。

> 通用结论：**凡是需要"精确几何"的元素（网格、标尺、等分线、对称结构），
> 都不要交给生成模型，用程序叠加。** 模型擅长质感与构图，不擅长精确几何。

### 8.3 ⚠️ 反过来：要「去掉网格线」时，**别在原图上抹** —— 重新出图更快更干净

2026-10-04 实测：用户看过带网格的底图后说"再生成一版无网格线、无黑色分界线，
地面只有泥土石板枯草石头，没有任何人为线条"。我第一反应是在原图上把线抹掉（省额度），
**结果失败**：

- 用 `MedianFilter(9)` 反复抹 3 次，线的**像素占比确实从 14.3% 降到 0.12%**，
  但目视仍有**明显残留的斜线**，而且反复抹线在中部造成了**横向条带感**（斑块）。
- 根因：模型自己画的那些网格线**又粗又长**，中值滤波的半径压不住；
  加大半径又会把石块、土路边缘一起抹平，得不偿失。

**✅ 正确做法：直接重新出图，在 prompt 里把"无网格"写成第一硬要求。**
实测一次成功，且质量更好：

```
【本次唯一要求：把画面中所有网格线与直线彻底去掉。】
1) 地面上没有任何人为画出的线条：没有网格线、没有分界线、没有辅助线、
   没有坐标线、没有任何笔直的直线或几何分割线。
2) 地表的全部内容只有：灰色的泥土、泥土上的碎石与石板、少量枯黄的草丛、
   零散的石块、以及自然的土路痕迹。全部是自然、随机、不规则的分布。
```

负面词要专门加一组：`网格线，网格，分界线，辅助线，坐标线，直线，笔直的线，
几何线条，矩形框，方格，规则图案，人为线条，田字形，十字线`。

**判断依据（什么时候该重出、什么时候该抹）**：

| 情况 | 做法 |
|---|---|
| 要去掉的元素是**你（程序）自己叠加**的 | **直接删/重新合成**，零成本、100% 精确 |
| 要去掉的元素是**模型画的、且又粗又长** | **重新出图**（第一硬要求 + 负面词专组） |
| 要去掉的元素是**模型画的、小而局部**（如角落水印） | 在图上修补（见 §6/§7） |

## 9. 单张「只改一块」类的改动怎么验收（2026-10-04 农业区农田翻耕实测）

需求形态：一整套图里只改**一个区域**（如"画面中央的农田改成翻耕过的空地"），其余全部不动。
这类任务的验收关键是**证明改动只发生在那一块**。

### 9.1 先算「改动范围定位图」——分块色差一眼看出改没改错地方

```python
d = np.abs(new - ref).mean(axis=2)          # 逐像素色差
grid = np.zeros((6, 8))
for i in range(6):
    for j in range(8):
        grid[i, j] = d[i*gh:(i+1)*gh, j*gw:(j+1)*gw].mean()
```
把 6×8 网格打印成表，**改得最多的块必须落在目标区**。实测农田翻耕：
最大块 (3,5)=48.9 正是农田，天空/远山/左右两侧只有 13–23（水彩笔触的固有噪声）。
再配 **4×4 分块结构相关**：只有中央那块掉到 0.23，其余 0.76–1.00，说明别处结构没动。

### 9.2 「有没有真的改对」要靠颜色判据，不要靠感觉

| 指标 | 参考 | 成品 | 判读 |
|---|---|---|---|
| 棕色像素比 `R>G>B 且 R-B>25` | 52.1% | **82.8%** | 变成棕土 ✓ |
| 绿色像素比 `G>R+5 且 G>B+5` | 28.2% | **2.8%** | 作物没了 ✓ |
| 金黄像素比（成熟作物） | 9.9% | **2.0%** | 无成熟作物 ✓ |

### 9.2b ⚠️ 判「耕地在哪」时，颜色判据一律失效（2026-10-04 实测，三种全废）

想把"翻耕地"从画面里分割出来时，依次试过三种颜色判据，**全部失败**：

| 判据 | 失败原因 |
|---|---|
| `R>G>B 且 R-B>25` 判棕 | 整幅地面本来就偏棕，原版（一块耕地都没有）也算到 **55.8%**，连通域糊成一整块 |
| 「与原版对比：变色 >22 且变暖 >8」 | 模型会**整幅轻微偏暖**，连天空都有 11–12 的色差 → 掩膜一路连到 y=3 的天空 |
| 用 v1 耕地取样色做 RGB 距离分类 | 原版也判出 **38.7%**，因为土路/干草地/裸土颜色就在那个范围里 |

→ **唯一可靠的指纹是「犁沟的周期性」**（下节 FFT），但要注意：
**葡萄园的行、玉米的行本身也非常规整**，所以阈值**不能取绝对值**，
必须取「原版自己最强的周期性」当基线：

```python
thr = np.percentile(stripe_map(原版), 97)     # 原版没有耕地 -> 超过它才算犁沟
```
实测（960×592，64×64 块 / 步长 32）：原版基线 328；原版与 v1 都检不出块，
**v2 检出 2 块独立的高规整条纹区**（x448-672 y256-448 与 x64-320 y416-544，互不相连）
= 第二块耕地确实加上了。

### 9.2c ⚠️ 先读图，再算数 —— 别用数值去猜几何（**已升级，取代旧版结论**）

**（旧版结论：看不到图时几何约束验不了 → 只能出对比图交用户目视。这条只对"纯文本模型"成立。）**

**升级版（2026-10-04 后续实测，重要）**：助手是**多模态**的，**直接 `Read` 图片**就能看见画面。
之前几十轮全部靠色差/FFT 推断几何，"耕地有没有越界、篱笆在不在、栅栏被没被盖"**根本没验到**，
还错判了好几轮。改为**读图定位**后，一次就定准了。

**正确工作流（几何类需求必用）**：
1. **先 `Read` 原图**，看明白场景里到底有些什么（本轮一看就发现：两块玉米地**各有一圈深绿灌木篱笆**，
   旧版把篱笆一起埋进耕地还外扩——这是数值永远看不出来的）。
2. **出「带坐标网格的放大图」**：`crop(区域) → resize(×3~6, LANCZOS) → 每 10/20px 画红蓝网格线 + 标坐标`
   ```python
   c = im.crop((x0,y0,x1,y1)).resize(((x1-x0)*S,(y1-y0)*S), Image.LANCZOS)
   d = ImageDraw.Draw(c)
   for gx in range(x0,x1+1,10):
       X=(gx-x0)*S; d.line([(X,0),(X,(y1-y0)*S)], fill=(255,0,0)); d.text((X+2,2), str(gx), fill=(255,0,0))
   for gy in range(y0,y1+1,10):
       Y=(gy-y0)*S; d.line([(0,Y),((x1-x0)*S,Y)], fill=(0,0,255)); d.text((2,Y+2), str(gy), fill=(0,0,255))
   ```
3. **`Read` 这张网格图，直接读出边界坐标**（篱笆内缘在多边形哪几个点）。
4. **把手写的多边形叠加回原图验证**（半透明填充 + 描边），`Read` 确认贴合，再进合成。

**数值只用来做"辅助校验"**（如色差确认改动收在目标区、FFT 确认犁沟出来了），
**不能用来替代读图定位几何**。

### 9.3 用 FFT 验证「周期性纹理」画出来没有（田垄/犁沟/条纹类需求）

"整齐的田垄和犁沟"这类需求，肉眼才好看，但**看不到图时可以用频域验证**：

```python
sub = gray[田地区域] - GaussianBlur(8)(gray[田地区域])   # 只留高频纹理
sub -= sub.mean(); sub *= np.outer(hanning(h), hanning(w))
F = fftshift(abs(fft2(sub))**2); F[cy-3:cy+4, cx-3:cx+4] = 0   # 挖掉直流
iy, ix = unravel_index(argmax(F), F.shape)
波长 = row_count / hypot(iy-cy, ix-cx);  能量比 = F[iy,ix]/F.mean()
```
实测：翻耕后 **波长 11.6px、方向 −55°、峰值能量比 1175**；参考图（种着作物）只有 141。
→ 能量比高一个数量级 = 条纹**明显且规矩**，正是"整齐的犁沟"。
⚠️ 反过来：**条纹能量比参考还低** = 模型只把作物抹平了、没画垄，要重出。

### 9.4 ⚠️ 去水印的两个新坑（本轮踩到，补 §7）

1. **「异常亮行」检测会被画布底部的亮带污染。** 本轮原始 1536×1024 的底部
   （640 空间 y618 之后）本来就是一条逐渐变白的亮带，逐行亮度扫描会把 606–639
   **整段**判成水印，据此定的修补矩形是错的。
   → **定位要用「同图左右段对比」或「与已清干净的同场景参考图同区对比」**：
   水印只在右侧（x≥755），左侧同高度的亮度才是基线。实测水印真身只有 **y602–616**。
2. **❌ 填充的低频不能取自目标区自身**（§7.3 那套 `low(tgt,12)+(src-low(src,12))`
   在水印很大很亮时会失效）——目标区的低频**已经被水印抬亮**，补完仍残留 +9.4。
   → **v3 改法：低频/色块取自「参考图对齐后的同一区域」，高频笔触取自「新图正左侧干净带」**：
   ```python
   R[24:616] = ref                      # 参考图对齐到 640 空间
   fill = low_freq(R[Y0:Y1, X0:X1], 6) + (A[Y0:Y1, sx0:sx0+sw] - low_freq(A[...], 6))
   ```
   实测残留从 **+9.4 降到 −0.8**（参考 vs 成品右下角 whiteness 差）。

### 9.5 一套图两种画幅口径（592 / 600）时，底部对齐而不是各自居中

模型返回 1536×1024 → 960×640。要同时出 960×592（与整套一致）和 960×600（用户口径）时，
**别各自居中裁**（600 版会把底部亮带/水印多裁进来 4 行）：
```
592 版 = rows 24..615      （与既有 18 张同一套裁法，构图位移实测 0/0）
600 版 = rows 15..614      （底部与 592 版齐平，多出的 8 行取上方的天空）
```
验收：成品**末 3 行亮度 vs 画面中部**的差要落在 ±15 内（本轮 −29.5 是因为该场景底部
本来就是暗前景，与参考图同区一致即可，不是裁进亮带）。

**验证残留的量化判据**：对地面区取 `MedianFilter(11)` 做低频，`d = 低频 - 原图`，
统计 `d>8` 的像素占比。**注意这个指标会把石块边缘、土路边缘也算进去**，
所以不能只看数值——**必须同时目视**。真正的人为线条特征是
"**窄（1–6px）+ 深 + 长且连贯**"；天然纹理则是"宽、浅、断续"。本轮验收时
逐行暗带检测出的都是 1–6px、深度仅 2–4 的条带，判为天然水彩纹理，通过。
