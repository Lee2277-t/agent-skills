# 生成图水印去除（同结构平移贴片法）

## 先判断：能不能用这个方法

贴片法成立的唯一前提是**水印压在有规律或平坦的区域上**（松林、草地、纸张、天空、水面、重复纹理的墙面）。

- 成立 → 用本文方法，秒级完成，原图画风一律保留。
- 不成立（水印盖在房子、动物、路牌、人物脸等**独占性内容**上）→ 不要硬修，贴片会明显穿帮，直接重新生成或换裁切。
- 也不要用「生成模型重画一遍」来去水印：那是重新出图，构图会漂，而且要再付一次费用。

（为什么不能靠提示词避免 —— 见文末「关键前提」。）

## 再选路线：单张手工 还是 批量工具化

| 场景 | 走哪条 |
|---|---|
| 一两张，需要人眼判断结构走哪条缝、纸边在哪 | 本文下面的手工贴片流程 |
| 一批同模型出图、要嵌进生成流水线、多页文档扫描页、视频 | `references/batch-tool.md`（自动检测选框 + 逐像素反解修补 + 前后计数器闸门 + 视频回退） |

手工流程**不要硬写成脚本逐张调坐标**：那些坐标不可迁移（换题材、换画幅、换季节都要重新量基线），批量必崩。要走批量就把算法固化成「检测 → 修补 → 计数 → 交人判不合格」，判定链、阈值、修补链顺序和验收计数器都写在 `references/batch-tool.md`，可直接照抄。

工具化第一条铁律与手工相同：**选框只罩住水印本身**，宁可漏一处也不要框大——框大会把邻域实体或正文搬进补丁区。

## 步骤

### 1. 定位水印，注意它常有两层

水印常是「主标 + 副标」两层，且横跨明暗不同的区域：

- 压在深色地物上的那层最明显；
- 落在浅色纸面/浅背景上的那层**对比度可能只有 5–10 个色阶**，正常看不出，放大 4–6 倍或做对比拉伸才会显形。

**两层都要处理**，只修肉眼可见的那层，用户一放大就露馅。定位方法：

```python
# 深色区域上的水印：找偏白且低饱和的像素
if lum(c) > 120 and not (min(c) > 195 and max(c)-min(c) < 45): -> 命中
# 浅色纸面上的水印：pixel 比纸底色更白，用对比拉伸看
v = clamp((min(c) - 235) * 20)   # 放大差异后再看
```

先裁一块放大存文件、用 Read 看一眼确认边界，再动手。

### 2. 量「结构基线」——这一步决定成败

在水印两侧找出**最强的横向结构线**（例：松林与纸面的交界边缘、草坡线、墙脚线），逐列测出它每一列的高度 y。

- 基线在水印这一段**平稳（波动 ≤ 3–5 px）** → 可以整块平移取像素，接缝几乎不可见。
- 基线明显倾斜或起伏很大 → 平移后会出现「双边缘」，改用更小的块逐段取，或放弃贴片。

```python
for x in range(x0, x1, 10):
    for y in range(H-1, top, -1):
        if not is_paper(px[x, y]): print(x, y); break   # 该列结构线高度
```

### 3. 分区取像素

按区域性质拆成 1–2 个块，每块整体平移取干净同结构像素：

| 区域 | 平移方式 |
|---|---|
| 主体块（林地/草地/纸面，水印所在） | **横向平移 −Δ**，Δ 要大于水印宽度，取同一批行号 |
| 边界条（如右侧纸边、画面外的窄带） | **纵向平移 −k**，因为横向平移会把别处的地物结构搬进来 |

纵向平移那一块要确认源行本身干净（水印上下都要留出至少一个水印高度）。

**默认就试水平/垂直平移，不要一上来就内容填充。** 平坦纸面上一块水平平移足够（见下面 1280×720、960×592 两例）。只有当某个方向**没有足够干净空间**——源区越界，或会带入长凳、摊位、房子边缘等实体——才回退内容填充；此时四个方向（左/右/上/下）各测一次，取「目标边界列 vs 源边界列的平均绝对差」最小的那个，全都不合格才用填充，并且要在结果里明说「周边空间不足，已改用内容填充」，不要静默换方法。

### 4. 合成：羽化权重

```python
w = clamp((x-X0)/F, 0, 1) * clamp((y-Y0)/F, 0, 1)   # F ≈ 8–10 px
out = orig*(1-w) + patch*w
```

- **只对内部边界羽化**。贴着图像外框的边（右、下）不需要羽化。
- 两个替换块相邻时，在重叠带取两者平均，避免硬边。
- 羽化带必须落在**没有水印**的区域，否则会把水印淡着留下来。块起点要留够 F 的余量。

### 5. 验收（必须做，别跳过）

1. 把修补区裁出来放大 4–6 倍看接缝；
2. 全图 100% 看一眼是否自然、有没有把笔触抹平；
3. 再跑一遍第 1 步的偏白像素检测，确认水印区没有异常亮点。

不合格**不要自动重做**，把问题说清楚让用户定。

## 明确不推荐的做法

- **IDW / 谐波迭代填充**：会把水彩笔触、纸张颗粒抹成一片平滑色块，在纹理区一眼假。适合的是平坦色块（纯色背景、纯纸面），不是纹理区。
- **直接涂色块**：破坏纸感与颜料沉淀。
- **整图模糊或降对比**：为了盖水印牺牲整张图，不值。

贴片法的优势正是它**原封不动地搬运了邻居的笔触与纸纹**。

## 复现案例（可直接套用参数）

**模型 hy-image-3.5-edit-wb / provider copilot-image**：几乎每次输出都在**右下角**压同一组标——上行「AI生成」、下行「WORKBUDD…」，半透明白色。960×592 画布下实测位置稳定在 **x ≈ 889–952, y ≈ 549–582**，横跨松林与该处的纸面。

这一带同系列图（水彩村庄）的参数可以直接复用：

```python
X0, Y0       = 875, 534          # 修补块起点，向左上留出羽化余量
XA1, XB0, XB1 = 946, 940, 960    # 块A 到946；块B 从940到画面右边
# 块A：林地+纸面，向左平移 90 取干净同结构像素
# 块B：右侧纸边条，向上平移 46 取干净纸面
# 940–946 重叠带取两块的均值，避免硬边
F = 8                            # 左、上羽化 8px；右、下贴着画面外框不羽化
```

该系列的可复用前提：松林与纸面的交界在 x ≈ 700–940 之间是平的（y ≈ 578–587），所以横向平移取像素不会露缝。**换题材时这一步必须重新量，不要照抄坐标。**

实测本系列 18 张（春/夏/秋 各晴雨昼夜 + 冬 晴/雪/雨 × 昼夜）基线都落在 578–591，波动 ≤ 9px，**同一组参数可直接复用**；只要量出来的基线波动不超过 10px 就能套用。夜间/雨天图的右侧有暗角，贴片后放大 4 倍能看到一小块色调略深的晕染，全图尺寸下不可见，属可接受，不必为此重做。

**又一例：1536×1024 生成后缩到 960×592（2026-10-01 实测，ImageGen 路径）**。同一模型这套水印仍压右下角，
但 1536×1024 的图缩到 960×592 之后，水印整体**更靠下**——只剩一行「AI生成」，且**被画幅底边裁掉一半**（bbox ≈ x 886–958、y 576–592）。
那一带是近乎平坦的米色纸面，**单块横向平移即可，不需要分块**：

```python
X0, Y0, D, F = 874, 566, 100, 8   # 横向左移 100px 取样；左、上各羽化 8px
```

- 水印左边界 ≈ 886，X0=874 留 12px 余量（≥ F=8，够）；水印上边界 ≈ 576，Y0=566 留 10px 余量。
- 取样区 x 774–860 必须干净：逐像素扫一遍确认没有比 x≥886 更靠左的字形残留（用字符图法，见下）。
- 验收：4 张连跑，放大 4 倍看右下角无接缝、无贴片残影。

**换画幅要重新量：1280×720 水彩素材表（2026-09-30 实测）**。同一模型的图标素材表（1280×720）水印仍固定在右下角，实测落在 **x 1176–1272、y 678–718**，且压在**完全平坦的水彩纸面**上——这种情形不需要分块，横向平移一次即可：

```python
X0, Y0, DX, F = 1160, 658, 200, 10   # 取 x-200 处的干净纸面；左、上各羽化 10px
```

- 贴片块起点到水印的左/上余量必须 ≥ 羽化宽度 F（这里 1160→1176 余 16px、658→678 余 20px），余量不够会把水印淡着留下来。
- 取样区（本例 x 960–1080、y ≥ 658）必须先确认是空纸。实测那瓶松露油底边到 y≈655、x≤1133 为止，所以 Y0 取 658 正好避开；**换图时这一句必须重新测**，用「非纸像素的最右列」逐行扫一遍即可。
- **判纸阈值在本例第三次失效**：纸底本身就偏亮（均值 `(244,237,226)`，min 已到 226），照抄 `min>178` 会把整张纸都判成水印、bbox 直接膨胀成整个扫描区。改判**比纸更白**：`min(c)>=238 且 max-min<22` 才命中，bbox 立刻收紧到 1180–1272。
- 验收：残留异常亮点只剩 8 个纸纹噪点；对 228–250 区间做 ×12 对比拉伸后无任何文字残影。

**⚠️ 判纸阈值会随季节失效（2026-09-30 冬天实测）**：`mn>185 且 mx-mn<50` 这套「纸边判据」只对春/夏/秋的米色纸成立。冬天雪景图的纸边偏暖偏暗（实测 `(209,193,172)`，mn 只有 172），阈值一失效，**逐列基线测量会把每列都判成「非纸」而恒返回 H-1**——现象是基线一排全是 591、min==max，看着像「很平」，其实是测量没生效。遇到这种"太平"的结果先怀疑阈值。

改成**色相判据**即可：纸是暖色（r 明显高于 b），雪是冷色（b ≥ r）。

```python
def is_paper(c):
    r, g, b = c
    return (r - b) >= 22 and r > 175 and g > 170   # 暖米色纸；雪地/松林不会命中
```

**顺带一条同源经验**：贴片前务必量一次基线并打印出来，不要因为"同系列前 12 张都用同一组参数"就跳过。冬天的基线恰好也落在 581–591，所以参数确实能复用，但**这个结论只有量过才成立**。

**⚠️ 检测阈值踩坑（2026-09-30 实测）**：自动检测 bbox 时阈值太松（如 `lum>140 且 max-min<38`）会把草地高光、野花等大量正常像素误判成水印，bbox 直接膨胀成整个扫描区（如 840–959 × 500–591），导致贴片块过大、取样区带到长凳/摊位等实体物件，留下明显「复制体残影」。收紧到 **`lum>165 且 max-min<30`** 后 bbox 精确贴合文字（约 892–959 × 558–591）。经验：**贴片块必须只罩住水印文字本身，块一旦大于水印很多，先怀疑阈值而不是加大平移量**；修完必须放大看有没有把邻区实体（长凳、摊位、房子边缘）搬进来。

**⚠️⚠️ 深色背景 + 画面自带白纸边：任何「亮度阈值保护纸边」的写法都会帮倒忙（2026-10-01 夜景实测）**

水彩系列图右下角本来就有一块**白纸边**（本例 x ≥ ~920），水印「AI生成」**左半压在深色草地、右半压在纸边上**
（纸上那半白+白，几乎看不见）。9 张夜景（晴夜/雨夜/雪夜）全部如此。

- **错解一**：`if lum > 232 and sat < 22: continue`（心想"白纸边别涂花"）→ **反而更糟**。
  水印白字本身也亮，被一起**保护**下来；而真纸边均值只有 ~225，没到阈值，反被涂成深色草地 →
  画面变成**黑底白字**，比不修还显眼。**这是本轮踩得最狠的一次。**
- **错解二**：把判据整体调松（`lum>195`）→ 纸边倒是保住了，但水印白字仍然高于它，还是被跳过。
- **正解：不要用亮度去区分纸边，逐行扫它的真实边界。** 从每行最右侧往左扫，
  连续满足「亮 + 低饱和」的起点就是纸边左边界 `edge`；只修补 `[X0, edge)`，`edge` 及其右侧一律不动。

```python
def paper_edge(px, W, y):
    def is_paper(x):
        r, g, b = px[x, y]
        return (r+g+b)/3 > 195 and (max(r,g,b)-min(r,g,b)) < 38
    if not is_paper(W-1): return W      # 该行最右不是纸（夜雨图纸边偏灰时会命中）→ 放弃保护
    x = W-1
    while x-1 >= 0 and is_paper(x-1): x -= 1
    return x

X0, Y0, D, F = 868, 558, 100, 8
for y in range(Y0, H):
    e = paper_edge(px, W, y)
    for x in range(X0, e):              # 只修纸边以左
        ...                             # 取 (x-D, y) 混色，左/上羽化 F
```

实测 9 张的 `edge` 在 **x = 910 ~ 927 之间逐行浮动**，写死任何常数都会出错（写小了留残影、写大了涂掉纸边）。

- **遗留风险**：夜雨图的纸边偏灰，`is_paper(W-1)` 可能为 False → 该行 `edge = W` → 一路修到右边缘。
  本轮 9 张没出事（夜雨图右边缘仍够亮），但**更暗的夜景会中招**。
  上策是**先把纸边裁掉再修**，或给 `edge` 设一个上限（如 `min(edge, 930)`）。
- 验收时**必须放大右下角 4 倍单独看**：这一步的失误只在这种放大下才看得出来，
  缩略图拼版里纸边锯齿会被误读成"好像还有字/好像已经没了"，不可作为判据。
- 别被「黑底白字」误导成"没修干净"就反复重跑：先打印字符图对比**修补前后**同一区域，
  看到的白色块可能只是**取样区搬过来的野花**（本轮就误判过一次，多跑了两个来回）。

**⚠️⚠️⚠️ 上面这条「逐行扫真实边界」本身还有一个致命前提：水印不能碰到纸边（2026-10-01 白天版实测，它当场失效）**

本轮水印「AI生成」横跨 **x ≈ 864–940**，而白纸边从 **x ≈ 923** 开始 —— **水印右半截正好落在纸边上，
白字与白纸"白接白"连成一片**。此时从右往左扫：

```python
while x-1 >= 0 and is_paper(x-1): x -= 1     # 白字也满足 is_paper → 边界一路被推左
```
扫出来的 `edge` **提前了 12 px**（实测 y=583 行扫出 911，真实是 923），于是水印右半截被当成"纸边"保护起来，
**修完还剩半截字**（现象：放大看右下角仍有"生成"二字浮着）。
更隐蔽的是：**这一类残留用字符图也不一定看得出来** —— 纸边和水印都是高亮像素，字符图里全是 `#`，得靠放大图肉眼判。

**正解：拿水印"上方干净的行"来定纸边，取中位数，然后当成常数硬用。**

```python
import statistics
edges = []
for y in range(470, 550):                 # 水印之上的行，逐行扫
    if not is_paper(W-1, y): continue
    x = W-1
    while x-1 >= 0 and is_paper(x-1, y): x -= 1
    edges.append(x)
XE = int(statistics.median(edges))        # 本批实测 923~924，且 min/max 只差 5px
```
（纸边是**竖直**的，上下几十行的边界几乎不变，所以这个常数对水印区同样成立。）
若 `min/max` 相差超过 ~15px 说明纸边是斜的，那就退回"逐行扫 + `min(edge, 上限)`"。

**同时，右半（纸边）那一块必须改用「垂直平移」取源**：

```python
X0, Y0, F = 845, 556, 10                  # 水印左/上各留 10px 余量（≥ F）
XE, D, DV = XE, 100, 40
for y in range(Y0, H):
    for x in range(X0, XE): px[x,y] = mix(px[x,y], sp[x-D, y],  w)   # 左半：草地 → 水平平移
    for x in range(XE,  W): px[x,y] = mix(px[x,y], sp[x, y-DV], w)   # 右半：纸边 → 垂直平移
```
- 纸边是竖直延伸的均匀条带，**向上取源最自然**；若对纸边也用水平平移，会把草地纹理贴上去，
  在纸边位置留下**一条明显的竖向色带**（上方的纸边和这条色带直接断层）。
- 水平平移的块起点 `X0` 要在水印左边界左侧留 ≥ F；本批水印左界 ≈ 864，取 845。
- 羽化 `F=10`；`y < Y0+F` 与 `x` 越过 `XE` 处各羽化一次，右侧贴着画面外框不羽化。

**验收一定要放大看，而且要连着看两次**：第一次改完经常还剩半截（因为边界被污染），
必须以**放大 5 倍的右下角图**为准，字符图、"看起来没了"的缩略图都不能当判据。

**批量处理写成循环，不要一张一个脚本。** 把「量基线 → 贴片 → 存图 → 复制到目标目录 → 出验收放大图」串成一个 for 循环，一次跑完整批；批量时顺便 `print` 每张的基线 min/max，既做记录也做异常预警。

### ⚠️ 雪景图：XE 分区法整体失效，改用「全块向上取样」（2026-10-01 冬天实测）

上面这套「左半水平取样 / 右半垂直取样」的分区，**只在纸边和画面内容亮度差得开时才成立**。
冬天雪景直接把它打穿了：

| | 亮度 | max-min |
|---|---|---|
| 纸边 | 219.7 `(224,220,215)` | 9 |
| **雪地** | **213.3** `(221,212,207)` | 14 |

**雪地只比纸边暗 6，任何"亮度阈值"判据都分不开**。后果是逐行扫描一路穿过雪地，
`median(edges)` 从正常的 921 掉到 **872**（同一批里 min 甚至扫到 432），
于是 `x ∈ [872, 924]` 这十几个像素本该走"向上取样"，却走了"向左取样"——
取到的是画面里的深色地面，直接在水印旁边糊出一块暗斑，**比不修还难看**。

试过三条路，全都失败：

1. 收紧判据（亮度 >212 且 max-min <13）→ 纸边内侧的过渡带被判成"非纸"，XE 反而推到 929，
   前三季回归测试也一起崩（秋天水印分 18.8 → 只有 16.5，等于没修）。
2. 按列投票（每列取 y=40..500 二十几个采样点）→ 阈值一松雪地全过、一紧纸边过渡带全挂，
   没有能同时满足两者的中间值。
3. 换色相判据 → 这回纸边和雪地**都是暖色**（雪地反光带土色，`r-b` 14~31 比纸边的 9 还大），色相反而更分不开。

**正解：放弃分区，整个补丁区统一向上取样。**

```python
X0, Y0, DV, F = 845, 556, 60, 10      # DV 从 40 加到 60，确保取源行 y-60 在水印之上
for y in range(Y0, H):
    for x in range(X0, W):
        w = clamp((x-X0)/F) * clamp((y-Y0)/F)
        px[x,y] = mix(px[x,y], sp[x, y-DV], w)   # 全部垂直取样，不判断纸边
```

代价是右下角画面内容的纹理整体上移 60px（那块是地面，肉眼不可见），
换来的是**四个季节全部一次通过**：实测水印分 `春 15.9→2.4 / 夏 15.8→1.9 / 秋 18.7→2.7 / 冬 10.7→1.2`。
分区法在春/夏/秋能跑，但那只是"恰好没踩到"；既然统一取样对三季同样更好，**直接用统一版，别再分区**。

**配套的验证指标也要换**：`bright()` 那种「数亮度 >165 且低饱和的像素」在冬天完全失效——
纸边本身就是 `(224,220,215)`，会被全部算成残留，冬天实测"残留" 2700+ 其实一个字都没有。
改用**与上方参照行的平均绝对差**：

```python
def wm_score(im, src):        # 补丁区像素 与 (x, y-DV) 的平均绝对差，越小越干净
    tot = n = 0
    for y in range(556, 592):
        for x in range(900, 960):
            for i in range(3): tot += abs(im[x,y][i] - src[x,y-DV][i]); n += 3
    return tot / n            # 实测：修补前 15~19，修补后 1~3
```

判据：`>10` 说明还没修干净，`<5` 是干净的。四个季节目标一致，可直接横向比较。

**上上策：从源头减少一次处理。** 做同系列变体时，参考图优先选**已清理过水印的成品**（本例中即 `<project-root>\game-assets\背景\` 里那几张），而不是最初带水印的生成图/上传图——带水印的参考图有概率让模型把角落字样一起仿出来，等于每张都要清。已清过的成品既干净、又通常已是目标画幅（省掉一次重排），一致性也更好。

## 关键前提

**提示词里写「不要文字、不要水印」是拦不住的**，模型照样在角落压标；「不要规律雨丝」这类否定式描述同样可能被忽略甚至强化。**去水印只能靠出图后处理**——出图流程里默认留出这一步，不要等用户提。

## 环境备忘

- 纯 PIL 就够，不需要 numpy / cv2；区域只有几十乘几十像素时，纯 Python 像素循环完全够快。
- 在 Windows 的 git bash 里跑多行脚本用 `<< 'PY' ... PY` heredoc，不要塞进 `python -c "..."`。
- 这台机器上 bash 的 `rm` 是坏的（exit 127），删临时文件用 Python `os.remove()`。
- 交付前把中间过程产生的放大图/对比图删掉，只留最终成品与原始生成文件。
- **删临时图只删自己刚生成的分析图**（建议统一用 `_` 前缀命名，如 `_corner.png`、`_animals.png`）。**绝不要删带 8 位十六进制前缀的副本文件**（如 `a7d589f8-xxx.png`）——那是画布/文档自动复制的引用文件，删了会让画布缺图。若已误删，可用同名不带前缀的源图复制回去还原（`shutil.copyfile(base, hashed)`）。
