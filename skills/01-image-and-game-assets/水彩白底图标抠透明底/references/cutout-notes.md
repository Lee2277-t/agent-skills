# 水彩白底图标抠透明底（自适应版）

适用：白底水彩图标集 → 透明底整图 + 单图标（96/256）+ 灰底检查。
参考实现：`_work/cut_buttons_v4.py`（改 SRC / NAMES / 网格布局即可复用）。

## 流程（必须按顺序）

0a. **先查 AI 水印**：ImageGen 出图右下角可能有"AI生成"字样 → Read 检查；有则用**背景色**（非纯白！）涂角清除，否则涂白补丁会被色差 flood 当成假内容。
0b. **判断背景类型定阈值策略**：
    - 取四角 40px 中位数得背景色 BC。若 BC 接近纯白（min≥250）→ min 亮度 flood，AI 直出图通常 T=252 直接可用。
    - 若背景偏灰/偏色（BC min<250）→ **min 亮度 flood 必失效**（覆盖率会掉到个位数），改用**色差 flood**：以与 BC 的欧氏距离<TD 为可穿透，TD 从 14 试起；alpha 渐变同样按色差（dist≤10 → 0，dist≥70 → 255，之间线性）。
1. **逐档诊断（不要直接用 252！）**
   - 采样画 min 直方图（`min(R,G,B)` 分桶）。
   - 逐阈值 T ∈ {252,248,244,240,236,232,228} 跑边界 flood，看背景覆盖率。
   - 选"覆盖率≈白纸实际占比且再降 T 覆盖率不再明显增长"的 T（通常 236-244）。
   - 原因：纸纹 min 常落在 240-251，T=252 时 flood 被纸纹挡死（可能只清 3%），整个背景会被当内容保留 → 灰底检查全白框。
2. **flood(T) 清背景** → 内容 = 非 bg 像素。
3. **内容连通域**（4 邻接），按面积过滤碎片（≥400-800px 视图定）。
4. **本体矩形**：在每个内容块内找"深色本体"（min < 200 左右，按图标外框深浅定）最大连通域，其 bbox = 图标本体矩形。适用于带深色外框的图标（装甲板按钮、金属件等）。
5. **框外羽化**：本体矩形外 pad 5% 定取景；取景内、矩形外的像素 alpha 按切比雪夫距离线性衰减（feather ≈ 本体尺寸 3.5%），矩形外远处的白晕/晕染压成透明。
6. **alpha 渐变**：min ≥ 252 → 0；min ≤ 210 → 255；之间线性（浅色水彩边自然半透明）。
7. 导出：透明底整图 + 单图标 96/256（内容占比约 90%，LANCZOS）+ 灰底(150,150,150)检查图。
8. **灰底检查必看**：白框/白噪块 = 背景没抠干净，回到第 1 步降 T；图标边缘生硬 = feather 太小。

def 判定网状块(comps, W, H, MIN_COMP):  # 伪码
    """bbox 占全图 90%+ 但像素密度 < 25% → 背景浅晕网，该档阈值不可用"""
    for c in comps:
        if len(c) < MIN_COMP: continue
        bw, bh = bbox 尺寸(c)
        if bw > 0.9*W and bh > 0.9*H and len(c) < 0.25*W*H: return True
    return False

选档条件（三条同时满足才定档）：
- 覆盖率 ≥ 55%
- 无网状块（浅晕 min 250-251 会连成稀疏全图网，覆盖率达标也会中招）
- 大块数在预期范围内（如图标数 4~8）

## 地块/叠图类素材（俯视 2.5D，叠加到背景上）

**参考实现：`_work/cut_bare.py`（地块状态通用模板）** —— 改 `SRC` / `STATE`(中文状态名) / `OUT_NAME`(单图标前缀) 即可套用到所有地块状态（空地/播种/发芽/生长中/成熟）。已内置：涂水印 → 色差抠图（只留最大块）→ alpha 渐变 → 向内羽化 → 等比居中导出 128/256 → 灰底检查 → 与上一状态并排的背景融合检查。

这类素材（耕地地块、播种/发芽等田块状态）会**直接叠在游戏背景图上**，边缘质量要求比图标高：

- 出图时**用游戏背景或已定稿地块作参考图**（input_fidelity=medium），保证 2.5D 斜 45° 透视与配色一致。
- 抠图后必须做两个检查：灰底检查 + **背景融合检查**（把成品以游戏实际显示尺寸贴到真实背景的田块位置上，放大看边缘）。
- 导出用**等比居中**（`sc=min(S*0.94/cw, S*0.94/ch)`），不要拉伸成正方形，否则透视会变形。

**必踩坑：水彩晕边的米白 halo**。色差法抠图后，土块/地块外围的米白色水彩晕染颜料（与背景色距离 >T1）会被保留为不透明或半透明边缘——灰底上是一圈白晕，叠到深色耕地上就是"贴纸白边"。修复用**向内距离羽化**：

```python
# solid = alpha>=128 的像素；BSS 从所有非 solid 像素做多源 BFS，
# 得到每个 solid 像素到边界的距离 dist_in；然后
alpha *= min(1.0, dist_in / F)   # F≈18（千像素级源图），靠外 F 像素线性淡出
```

- 白晕位于边界附近（dist_in 小）→ 被压到接近 0；土体深色内缘成为新边缘。
- halo 宽或残留斑点多的图可再补一轮 F≈12（等效 ~30px 总羽化）。
- 羽化在**裁剪后的全分辨率透明底**上做，再缩放导出 128/256/512；不要在小图上羽化。
- 注意：含模块级执行代码的处理脚本必须加 `if __name__ == '__main__':` 保护，否则被 import 时会重跑一遍羽化（alpha 二次衰减不可逆）。

**⚠️ 去晕/羽化参数必须按主体密度分档，别一律用激进的：**

| 素材类型 | alpha 渐变 T0/T1 | 羽化 F | 效果 |
|---|---|---|---|
| 密集主体（土丘、叶片、按钮板） | 10 / 70 | 18 | 白晕彻底压掉，边缘干净 |
| 浅色细笔画为主（稻穗、麦穗、纱线、雾气） | 6 / 42 | 6 | 保住水彩密度，不褪色 |

激进参数用在浅色植株上，会把整片浅色洗边压成半透明 → 贴到白/浅色底上**整体褪色、细节丢失**，看起来像"换了一张图"（这类返工过一次：玉米/水稻成熟图）。判断方法：抠好后贴到**白底**上比对——密度高的主体不变色，浅色笔画为主的会明显发白。地块类必做背景融合检查，植株类必做白底对照检查。

## ★★ alpha 判定：必须用「向内距离法」，不能用「色差法」（v2 正确做法）

**这是本项目最核心的坑，务必先读。**

### 色差法为什么是错的

旧做法：`alpha = clip((dist - 10) / 60, 0, 1) * 255`，`dist` = 像素与背景色的欧氏距离。

问题：**水彩主体内部本来就有大片接近白的米色高光**。
实测帆布背包案例：主体 bbox 内 **44.63% 的像素色差 < 14**（纸纹白 + 颜料沉淀的浅色斑）。
按色差判透明 → 这些高光被抠成半透明 → 表面出现**几十个白点**，看起来像材质破损/脏点。

### 正确做法（距离法）

```python
# ① 用 TD=14 从画布四边 flood，只标记「与边缘连通的背景」
bg   = dist < TD
reach = 从四边种子做 BFS，仅在 bg 内扩散
# ② 对 reach 区域做多源 BFS，得到每个像素到背景的向内距离 d_in(px)
d_in = np.full(dist.shape, INF, np.int32)
q = deque(zip(*np.where(reach)))          # 全部背景像素作种子，d_in=0
while q:
    y, x = q.popleft()
    for ny, nx in 四邻:
        if 0<=ny<H and 0<=nx<W and d_in[ny,nx] > d_in[y,x]+1:
            d_in[ny,nx] = d_in[y,x]+1; q.append((ny,nx))
# ③ alpha 只按距离渐变，与「颜色亮暗」完全无关
alpha = np.clip((d_in - 0) / 26.0, 0, 1) * 255
```

效果：主体内部 `d_in` 远大于 26 → 天然全不透明（高光全保住）；只有外缘 26px 做渐变，边缘依旧自然柔和。
副作用：外缘的米白晕会被保留一部分，此时**不要再叠加向内羽化 F**（会二次衰减），把 `F` 设为 0。

参考实现：`_work/cut_single_item.py`（单图标通用）、`_work/cut_rice_tea.py`（多图标整图）。
⚠️ `_work/cut_mature.py`、`cut_bare.py`、`cut_seeded.py` 等旧脚本仍是色差法，用于浅色细笔画主体（稻穗等）时正确，但**用于密集主体（物品、叶片、按钮板）会产生白点**，需要照上述改写。

### 参数

| 主体类型 | TD | 距离渐变 T1 | 向内羽化 F | 效果 |
|---|---|---|---|---|
| 密集主体（物品、叶片、按钮板） | 14 | 26px | 0 | 内部高光全保住，外缘柔 |
| 浅色细笔画（稻穗、麦穗、纱线） | 14 | 6~10px | 6 | 保住水彩密度不褪色 |

### 验"内部无破洞"的正确判据

不要用「中心区 alpha>=250 占比 > 99%」——外缘渐变带会延伸进中心区导致误判。
**对 `alpha <= 10` 的透明区做连通块分析**：若只有 **1 个连通块**（贴着四边的外圈背景），说明内部无破洞。
若出现独立的小透明块，才是内部被误抠了。

## 色差抠图的数值陷阱（两个必踩的坑）

```python
# 坑 1：距离计算必须用 float32
#   np.int16 存 RGB 后 (a - bc)**2 会溢出（255²×3 = 195075 > 32767）→ NaN
#   症状：dist 全 NaN → mask 全 False → 抠不出内容，随后报
#          "only integer scalar arrays can be converted to a scalar index"
a = np.array(im.convert("RGB")).astype(np.float32)
dist = np.sqrt(((a - np.array(bc, np.float32)) ** 2).sum(axis=2))

# 坑 2：PIL 的 putalpha() 不接受二维数组
#   out.putalpha(alpha.astype(np.uint8))  → TypeError
rgba = np.dstack([np.array(im.convert("RGB"), np.uint8), alpha.astype(np.uint8)])
out = Image.fromarray(rgba, "RGBA")
```

### 切分与对齐（★ 动画最容易翻车的地方）

1. 列投影找宽间隙（>图宽 2%）自动切分，`assert 块数 == 预期帧数`。
2. **不要逐帧 `getbbox()` 紧边**。腿脚是细笔画+低对比，`getbbox()` + `alpha>128` 会把底部残留灰影算进内容，各帧脚底 y 极差可达 **191px**，播放时角色疯狂上下抖动。
3. 正确做法：
   ```python
   al    = np.array(co)[:, :, 3]
   strong= al >= 200                                  # 只用「几乎完全不透明」判真主体
   ys    = np.where(strong.any(axis=1))[0]            # 脚底
   bb    = (xs.min(), ys.min(), xs.max()+1, ys.max()+1)
   base  = int(np.median([每帧的 bb[3]]))              # 中位数抵消切分边界误差
   # 统一画布 maxw×maxh，贴入时 y = base - f['bottom']
   ```
4. **渐变带宽度 `T_EDGE` 要按主体最细部位调**。26px 会把腿脚判成半透明（母鸡案例 4 帧全缺脚）；收到 14px 后脚完整保住。细笔画角色（动物腿、枝条、绳索）一律用 10~14px。
5. 验收：脚底 y 极差应 **< 8px**；高度极差应 < 10px。超出说明有残留或吃笔画。
6. 精灵表统一画布 = `maxw * N × maxh`，帧宽必须严格相等（Godot `hframes=N` 按帧宽切）。

### ★★ 多帧动作序列：绝不能写「与参考图几乎相同」

- **踩过的坑（母鸡行走 v1）**：第 2 批提示词写「与参考图 1 的第 N 帧几乎相同的姿势」→ 模型**逐字照抄**，8 帧变成同一动作的细微复制，根本不是动画。
- 前一批的动作描述幅度也要够大：写「位置最高/最低」「上浮 1 像素」这种微差，模型会真的只画 1~2px 差异。
- **正确写法：每帧用「动作名 + 具体腿位」双重描述**
  ```text
  第 1 帧 · 迈步（右腿前伸）：右腿向前大步伸出、爪子张开还未着地，左腿在身后蹬直支撑，身体前倾
  第 2 帧 · 着地（重心下沉）：右腿向前伸直、脚掌平平踩在地面，左腿在身后收起弯起，身体降到最低点
  第 3 帧 · 蹬地过渡：右腿在身后蹬直用力蹬地（脚尖抓地），左腿从身下向前摆出到身体正下方
  第 4 帧 · 左腿前伸：左腿向前大步伸出、爪子张开还未着地，右腿在身后蹬直支撑
  ```
- **必须加对比句**，显式区分易混淆的帧：「第 1 帧和第 4 帧都是一腿前伸一腿后撑，但前伸的是**不同的腿**（帧1 右腿，帧4 左腿），请明确区分。」
- 跨批延续时用「与参考图第 N 帧**左右腿相反**」来表达，不说「相同」。
- **负面词必加**：`四帧姿势相同, 四帧动作重复, 静止站立不迈步, 双脚重叠`。
- **验收判据**：帧高极差大是好事（母鸡 v2 帧高 311~401px），说明腿的伸展范围真的拉开了；若各帧高度几乎一致，多半是动作没做出来。

### 帧数多时（6 帧以上）必须分批出图

- 1536 宽 ÷ 8 帧 = 每帧仅 192px，装不下角色（母鸡实测宽 280~306px）→ 必挤变形。
- **规则：保证每帧宽度 ≥ 角色实际宽度 × 1.2**。1536 图宽下，单帧角色 300px → 最多 4 帧。
- 分批方案：4+4 两批，第 2 批用**第 1 批定稿整图 + 原单帧图作双参考**（`image1`=整图, `image2`=单帧，`input_fidelity=high`），保证跨批连贯。这是本项目验证过的"批次衔接"做法（成熟图标集也是这么做的）。
- 合并时 8 帧必须**整体统一画布**（宽高取全局最大），不能各批各自统一——否则帧宽不等，Godot `hframes=8` 会切错。

### ★ 脚下有淡水面阴影时切不开帧（母鸡下蛋踩坑）

模型常在角色脚下画一圈**淡水面/地面阴影**（色差仅 20~28）。若切分用抠图同款 `TD=18` 判前景，这圈阴影会被当成内容，把相邻两帧之间的空隙**填满**，列投影找不到间隙 → `切出 1 帧（预期 3）`。

```python
# split_n 的切分阈值必须比抠图 TD 更高，只认明显笔触，淡阴影被排除后间隙才显现
def split_n(im, bc, n=3, td_split=30, gap_ratio=0.012):
    cols = (dist >= td_split).any(axis=0)          # 母鸡案例：TD=18 失败，30 成功
    ...                                              # 间隙宽度阈值也可降到图宽 1.2%
```

**规律：切分阈值 > 抠图阈值。** 抠图要「宁可多留渐变带」，切分要「宁可只认实心笔触」。

### ★★ 道具紧贴主体时连通域分不开（鸡蛋紧贴鸡脚）

带道具的帧序列（母鸡下蛋、叼着东西走……），道具常紧贴主体，连通域分析会把两者算成**一个块**，道具丢失。

实测：鸡蛋与鸡脚之间有一段实心连接，`alpha>=200` 下无论 MinFilter 腐蚀到 7 / 11 / 15 / 21 / 31 都断不开——因为连接处本身就有 20px 以上宽。

**正确做法：高阈值 + 中值滤波腐蚀只用于「定位 bbox」，取像素时回到未腐蚀的原 mask**

```python
EGG_TH, EGG_ERODE = 240, 21        # 实测这组合能稳定断开；th=200 全部失败

def find_egg(alpha):
    mimg = Image.fromarray(((alpha >= EGG_TH) * 255).astype(np.uint8))
    er   = np.array(mimg.filter(ImageFilter.MinFilter(EGG_ERODE))) > 127   # 腐蚀后只为定位
    comps = components(er)
    eb = <小的那个块的 bbox>
    # ★ 关键：bbox 定下来后，用【未腐蚀的原 mask】在该范围内取真实像素
    ys, xs = np.where((alpha >= 200)[eb[1]:eb[3], eb[0]:eb[2]])
    crop = co.crop((eb[0]+xs.min()-3, eb[1]+ys.min()-3, ...))
```

- 若腐蚀断了仍连成一团，说明道具与主体**真的实心相连**（模型画死了），此时换个思路：先在**竖直方向**切一刀分离（道具通常在地平线附近、主体在其上方），或直接放弃分离、把道具当整体一起对齐（道具位置在帧间偏移不大时可行）。
- **母鸡 bbox 必须排除道具的横向范围**：`hen_mask[道具行区间:, 道具列区间] = False`。否则道具底边（常略低于脚底）会把基准线拉歪。

### ★★ 跨批出图的地平线不一致，必须按批归一

分两批出图时，模型给每批画的**地平线由它自己决定**，不保证一致。母鸡下蛋实测：第 1 批脚底 y≈820，第 2 批 ≈799，**差 21px**。直接全局取中位数对齐，播放时会在这两批之间整体跳 20px。

```python
med_a = np.median(bots[:PER_BATCH]); med_b = np.median(bots[PER_BATCH:])
for i, m in enumerate(metas):
    m['ref_bottom'] = med_a if i < PER_BATCH else med_b
# 贴入：母鸡底边落在地平线，且把本批内的抖动保留（foot_rel 是帧内真实偏移）
foot_rel = m['bottom'] - m['ref_bottom']
py = round(ground + foot_rel - m['h'])
```

- `foot_rel` 必须**保留**（不能强行全归零），否则批内 1~2px 的地平线抖动也会被拉平，看着假。
- 画布高度要留 **headroom**：`maxh = max(帧高) + 8`。否则 `foot_rel` 为正的帧（站得比基准批高的那些）顶部会被裁掉几像素（实测帧1 `y=-3` 被切头）。
- 道具同样要按 `ground + foot_rel` 落到同一地平线，不能只按道具自身高度贴。

### ★ 道具的横向位置帧间不一致，会跳位

模型每帧独立把角色摆在画面中央，**道具相对角色的偏移每帧都不同**。母鸡下蛋实测蛋心相对鸡身 +152px / +136px，差 16px，播放时蛋会左右跳。

```python
# 取第一个有道具的帧作基准，把所有帧的道具统一到「相对母鸡身体中轴的固定偏移」
ref     = next(m for m in metas if m['egg'])
egg_off = ref['egg']['cx'] - ref['cx']          # 相对偏移，基准帧自己不动
for m in metas:
    if not m['egg']: continue
    ex = round(px + m['w'] / 2.0 + egg_off - m['egg']['w'] / 2.0)
```

### 动作类型决定验收判据（不要用错）

| 动作类型 | 对齐基准 | 验收 |
|---|---|---|
| 只动头（啄食） | 脚底 y | 头高差曲线成弧线；脚底极差 < 8px |
| 全身下沉（下蛋/蹲伏） | 脚底 y + **按批归一地平线** | **帧高极差要大**（下蛋实测 460~732px）；脚底落点全帧一致 |
| 位移（行走） | 脚底 y | 帧高极差大是好事（腿伸展范围） |

**全身下沉动作的帧高极差大才是正确结果**，别误判成"没对齐"。

### ★★★ 翅膀/肢体展开的动作：列投影切不开，必须限制每张图的帧数

**踩过的坑（母鸡振翅跳跃）**：4 帧一次出图后，列投影**整图只有 1 处空白**（另外两处被翅膀完全覆盖），任何算法都切不开。试过的方法全部失败：

| 尝试 | 结果 |
|---|---|
| 提高切分阈值 td 26→70 | 无效（不是淡阴影问题，是真交叠） |
| 间隙宽度阈值 1.2%→0.8% | 无效 |
| 手动指定切点 | 量不准，切出 3 帧 |
| 谷底切点（列前景数最小处） | 切点落在鸡身上，切出半只鸡 |
| 横向等分兜底 | **把鸡翅膀从中间劈开**，最糟 |

**唯一可靠解法：从出图阶段就限制每张图的帧数。**

```text
生成2帧跳跃动作序列图 ...
★ 排版严格要求：画面中只有两只母鸡，左右排列，两只母鸡之间留出很宽的空白间隔，
  母鸡完整可见、互不接触、翅膀和羽毛绝不能交叠重叠。
负面：..., 翅膀交叠, 重叠, 相互接触, 三只鸡, 四只鸡, 三帧, 四帧
```

- 规则：**展开类动作（翅膀张开、跳跃、滑翔）每张图最多 2 帧**；其他动作最多 4 帧。
- 「N 帧/张」的提示词要同时在正面描述和负面词里声明，否则模型会自作主张画更多。
- 分 2+2 两批出，第二批用第一批定稿整图 + 原单帧图双参考。

### ★★ 间隙数 ≠ 帧数时，绝不能等分兜底

自动切分失败后**不要退化成横向等分**——等分线会落在角色身上，把鸡从翅膀中间劈开。正确做法是 `raise` 让流程停下，重新出图限制帧数。

```python
if len(bounds) != n:
    raise RuntimeError('间隙切出 %d 帧（预期 %d）—— 相邻帧横向交叠，'
                       '必须重出图并限制每张帧数，不能等分兜底' % (len(bounds), n))
```

**扫描全图所有空白段**是快速判断「是否真的无间隙」的手段：

```python
runs = []   # 所有 >=5px 的空白段
# 母鸡振翅：整图只有 [(0,36),(356,37),(1502,34)] —— 356 之外全是鸡，证明无法切分
```

### ★★★ 腾空/位移动作的画布几何：不能用「最高帧高 + headroom」

跳跃序列里腾空帧的 `foot_rel` 是**负的**（脚底高于地面线），若写 `canvas_h = maxh + headroom` 而 `headroom = -min(foot_rel - h)`，会算出 800+ px 的荒谬画布。

正确解法：**从约束反推地面线位置**

```python
# py = ground_y + foot_rel - h 必须 >= 0
#   → ground_y >= max(h - foot_rel)
ground_y = int(max(f['h'] - fr for f, fr in zip(frames, foot_rels))) + 2   # +2 抵消 round 误差
canvas_h = ground_y + 6
assert py >= 0   # 贴入时必须断言，否则头冠会被画布顶裁掉（不报错，静默丢失）
```

### ★★★ 跨批坐标：bottom 是批次局部坐标，必须先减本批基准

分批出图时，每批的 `bottom`（bbox 底边）**在各自图内的坐标系**，跨批直接相减毫无意义。实测两批 bottom 相差 800+，算出的偏移全是垃圾。

```python
# 每批各自求中位数作基准
batch_ref = []
k = 0
for bi, (_src, cnt) in enumerate(batches):
    seg = [f['bottom'] for f in frames[k:k+cnt]]
    ref = float(np.median(seg))
    batch_ref.extend([ref] * cnt)     # ★ 逐帧展开，不是每批一项
    k += cnt
assert len(batch_ref) == len(frames)
offs = [f['bottom'] - r for f, r in zip(frames, batch_ref)]
```

**踩过的坑**：`batch_ref` 原本只存「每批一项」（2 项），与 4 帧 `zip` 时被**静默截断成 2 项** → `offs` 少一半 → `np.percentile(offs,75)` 变成假值 → 连锁算出 781px 荒谬 headroom。教训：**凡是要 zip 两个数组，先 assert 长度相等**。

### 地面线取值：按动作类型选

| 动作 | 地面线偏移 | 说明 |
|---|---|---|
| 原地（睡觉/刨地/啄食） | `np.median(offs)` | 保留各批内部抖动，不强行拉平 |
| 腾空（跳跃） | `np.percentile(offs, 75)` | 靠下的帧是着地帧；**不能用 max**（批次间画法差异会造出假的最大值） |

验收：跳跃序列打印 `foot_rels`，**腾空帧应为明显负值**（母鸡振翅 [−1, −94, −99, +3]，腾空帧 2、3）；全部 ≥0 说明腾空感没做出来。
